# 25 · Compatibility and Versions (Which to Download, at a Glance)

中文: `docs/25-兼容与版本.md`

> Intended outcome: after this page you can answer three questions yourself: can my game install it, which zip should I download, and what happens if I install the wrong one.
> Content related to acceptance numbers is in [`docs/wiki/版本与验收.md`](wiki/版本与验收.md); this page only covers "compatibility".

## 1. In One Sentence

The current release is `v4.30.0` (full release · Latest), supporting Minecraft Java Edition 1.21.5 through 26.3, in five packages by version range. The 1.21.6 one has a baseline of `pack_format = 80`; when the version doesn't match, the game flags the pack as "incompatible" (a yellow notice — it can usually still be force-enabled, but this pack hasn't been tested outside its ranges, so don't).


## 2. Version × Variant Matrix

| Variant (zip) | Target MC | `pack_format` | Experimental gameplay needed | Has `features` in `pack.mcmeta` | What happens if you install it into the wrong world |
|---|---|---|---|---|---|
| `doom.nats-v4.30.0-mc1.21.5.zip` (default · 1.21.5) | 1.21.5 | 80 | No | No | Loads normally |
| `doom.nats-v4.30.0-mc1.21.6-1.21.8.zip` (default · 1.21.6 to 1.21.8) | 1.21.6 to 1.21.8 | 80 | No | No | Loads normally |
| `doom.nats-v4.30.0-mc1.21.9-1.21.10.zip` (default · 1.21.9 to 1.21.10) | 1.21.9 to 1.21.10 | 88 | No | No | Loads normally |
| `doom.nats-v4.30.0-mc1.21.11-26.2.zip` (default · 1.21.11 to 26.2) | 1.21.11 to 26.2 | 94 | No | No | Loads normally |
| `doom.nats-v4.30.0-mc26.3.zip` (default · 26.3) | 26.3 | 94 | No | No | Loads normally |
| `doom.nats-v4x-experimental-v4.30.0.zip` (experimental · 1.21.6) | 1.21.6 | 80 | Yes: enable "Minecart Improvements" when creating the world | Yes (`minecraft:minecart_improvements`) | The whole pack is refused (not a warning — a load failure) |

The five range packages plus the experimental variant are all physically separate, independent artifacts; the version-suffix-free `doom.nats-v4.30.0.zip` is the baseline artifact of the 1.21.6 one. The `features` field is pack-wide: the engine either accepts it or rejects it. So "can it be installed" is decided by the variant; "does behavior roll back" is decided by the in-game switches (see [`18-配置手册.md`](18-配置手册.md)).

## 3. Why the Experimental Variant Borrows a "Minecart" Flag

1.21.6 has only three usable experimental flags (all from vanilla's own built-in datapacks): `minecart_improvements` / `redstone_experiments` / `trade_rebalance` — there is no "custom datapack" flag. So it has to borrow a native flag as the engine gate. The reason for choosing "Minecart Improvements": it only changes minecart motion, with the least impact on spawning/combat/trading.

The cost (you must know it): a world that enables this experimental gameplay also gets vanilla's minecart changes (changed minecart motion behavior). If that bothers you, install the default variant.

## 4. Upgrading / Downgrading / Switching Variants

| Scenario | What to do | Watch out for |
|---|---|---|
| Upgrade within a variant (e.g. v4.29 → v4.30.0) | Overwrite the old folder with the new `doom.nats/` → `/reload` | The save and already-spawned mobs are unaffected; rules live in storage and are preserved too |
| Default variant → experimental variant | Delete the old folder, put in the experimental zip's `doom.nats/` → `/reload` | The world must first enable the matching experimental gameplay, otherwise swapping it in fails to load; the safest route is to enable it when creating a new world |
| Experimental variant → default variant | Just swap the folder → `/reload` | Experimental-only content (`near` / `on_spawn` / presets) doesn't take effect; any `doom.nats:exp` storage you wrote stays in the save, harmlessly |
| Full uninstall | Delete `datapacks/doom.nats/` → `/reload` → `/function doom.nats:mode/auto` | This step hands `doMobSpawning` back to vanilla; skip it and spawning stays off |
| Both variants at once | Don't | Only one can be active per namespace; the other's behavior is unpredictable |

## 5. Which Version Is My Game? How Do I Match `pack_format`?

| What you might see | Meaning |
|---|---|
| Singleplayer: the version name under `.minecraft/versions/`; the one selected in the launcher | The MC version you're actually running; it must fall within 1.21.5 to 26.3, and you install the matching package |
| Server: the version the `server.jar` corresponds to (the first line of the startup log states it) | Same as above |
| An "incompatible" prompt in chat when entering the world | Means the `pack_format` in `pack.mcmeta` doesn't match the game |
| The `pack_format` inside `pack.mcmeta` | The declared value per range is in the table in section 2, and they're not all the same. What really decides whether it loads is `min_format` / `max_format`; for the per-version comparison see [the README's version matrix](../README.md#版本对照); the 1.21.6 one and the experimental variant are both 80 |

> Want another MC version? A datapack depends on that version's entity/structure/tag ids and `finalizeSpawn` semantics; it isn't something you can cross versions by changing a number — it needs regeneration + re-acceptance (which requires the author's local development environment, not distributed with this repo).

## 6. Self-Check After Downloading (30 Seconds)

```
1) Is the hash right:   sha256sum -c dist/SHA256SUMS.txt              # the checksum is in dist/SHA256SUMS.txt (two lines)
                        # Windows: Get-Content dist/SHA256SUMS.txt | ForEach-Object { $h,$f = $_ -split '\s+'; "$f => " + $(if ((Get-FileHash "dist/$f" -Algorithm SHA256).Hash.ToLower() -eq $h) {'OK'} else {'MISMATCH'}) }
2) Is the structure right:   after unzipping, the top level should hold exactly one doom.nats/ folder, with pack.mcmeta as its first level
3) Did it install right:   after /reload there's a ready message in chat, and logs/latest.log has no "Failed to load function"
```

All three passing = the download, structure, and loading are fine; if any one fails, file it via the [Issues form](../.github/ISSUE_TEMPLATE/bug_report.yml) (the form will ask you for these three results).
