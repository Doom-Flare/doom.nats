# 13 · v4 User Manual (Natural Spawning Replica)

中文: `docs/13-v4使用手册.md`

> ⚠ **This document is a v4.1 snapshot and has not been updated along the way; for the current state see the [CHANGELOG](../CHANGELOG.md) and [docs/24-玩家能改动的一切.md](24-玩家能改动的一切.md).**
> The `finalizeSpawn` group data row in the "Not implemented" table below was implemented long ago (a group data layer has existed since v4.15, see [docs/19](19-finalizeSpawn与组数据.md)); for the remaining entries, the CHANGELOG is authoritative.

> Aimed at map authors. Default variant = the `doom.nats/` unzipped from `dist/doom.nats-v4.32.0.zip` (generated by this repo's `src/tools/gen_*.mjs`).
> **Always change the generator and re-run it; never hand-edit files inside the pack** (the generators take `--check` to verify drift).

## 1. Prerequisite: Disable Vanilla Natural Spawning

Everything this pack spawns goes through `/summon`, and neither the vanilla cap nor the mobcap applies to `/summon` (the wiki confirms this), so the two don't conflict:

```
/gamerule doMobSpawning false
```

- This stops vanilla natural spawning. This pack's spawning, spawners, and spawn eggs are unaffected.
- ⚠️ Needs real-hardware confirmation: whether passive mobs spawned during chunk generation (`spawnMobsForChunkGeneration`) also fall under this rule; this pack makes no assumption.
- ⚠️ In singleplayer, leaving the pause menu open stops spawning (`tickPaused()`); a dedicated server's `pause-when-empty-seconds` stops ticking after 60 seconds by default.

## 2. Verification (One Command)

```
/reload
/function doom.nats:debug/all
```

It runs five things in order: environment probe → registry listing → dryrun diagnostics → attribution histogram → despawn report.
Then, from outside the pack, run `node doom.nats/tools/collect.mjs`; the report will contain a "spawn-failure attribution histogram" section and an "environment snapshot" section.

### Attribution Code Table (`$chk.reason`)

| Code | Meaning | Common fix |
|---|---|---|
| 0 | Couldn't pick a qualifying chunk (the surrounding 17×17 isn't loaded) | Check `chunks` in `debug/env`; move closer to a loaded area |
| 1 | A player is within the 24-block sphere (vanilla `distSq <= 576`) | Normal behavior; walk further away |
| 2 | Beyond 128 blocks (`despawnDistance²`) | Normal behavior |
| 3 | Light tier insufficient | Adjust `$eff.light` or check the case's `lightRule` |
| 4 | The landing block doesn't allow it | The place most likely to need changes: extend `#doom.nats:standable` / `#doom.nats:spawnable_at` |
| 5 | Global capacity full | Adjust `$eff.max_<category>` or raise the `doom.nats` cadence |
| 6 | Nearby players' local capacity all full | Same as above; or spread the players out |

`dryrun` splits the landing into three scores, `$dr.at` / `$dr.above` / `$dr.below`, pinpointing which one fails.

⚠ In real-hardware runs, `0` (couldn't pick a qualifying chunk) and `8` (couldn't pick a species) increment in strict lockstep (point-for-point equal at 5-second granularity). So the relative sizes of these two numbers can't distinguish the cause, and the histogram can't separate the two categories. `$rej.8` / `$rej.9` only `add`, never `set` ⇒ they never reset to zero (cumulative over the world's lifetime). See [[FAQ]].

## 3. Full Parameter Table (All Scoreboard Fake Players, objective = `doom.nats`)

| Parameter | Default | Meaning |
|---|---|---|
| `$snap_period` | 20 | Snapshot cadence: the interval for environment/case/capacity/biome refresh. ⚠ The acceptance scripts set it to `20000` ("frozen snapshot") to isolate variables; **if the world stays in the frozen state, the symptom is "no spawning at all"** (`$snap.chunks=0` ⇒ `$cap.monster=0` ⇒ every attempt gets `reason=5`), while tick and load logs look completely normal. For troubleshooting see [[FAQ]] |
| `$chunks_mode` | 0 | `spawnableChunkCount` approximation: 0 = scan only the first player (exact in singleplayer / underestimates in multiplayer), 1 = accumulate per player (overestimates in multiplayer) |
| `$eff.period` | 5 | Spawn cadence (`spawn/try` once every N ticks) |
| `$eff.max_monster` / `_creature` / `_ambient` | 70 / 10 / 15 | `maxInstancesPerChunk` per category |
| `$eff.light` | 7 | Light tier upper bound (tiers 0/3/7/11/15) |
| `$despawn_period` | 20 | Despawn check cadence |
| `$despawn_dice` | 40 | Despawn roll denominator (equivalent to vanilla's 1/800 per tick) |
| `$despawn_log` | unset | Set to 1 to print every probabilistic despawn |

## 4. Extension Points

### 1) Register a new environment case

Edit the `CIRC` table in `tools/lib/circ-defs.mjs`, then re-run:

```bash
node tools/gen_pack.mjs && node tools/gen_effects.mjs
node tools/lint_pack.mjs && node tools/install.mjs --variant std
```

Entry structure (`when` and `effects` are both parameters that override vanilla semantics, not extra switches):

```js
{ id: 'snow_night', when: { weather: 1, time: 'night', dim: 0 },
  effects: { period: 4, max_monster: 80, lightRule: 11 }, note: '雪夜' }
```

Available `when` dimensions: `weather`(0 clear/1 rain/2 thunderstorm) · `time`('night') · `dim`(0/1/2) · `players`(≥N) · `phase`(moon phase 0..7).
`effects` can override: `period` · `max_<category>` · `lightRule`. Later registrations take priority (order is priority).

### 2) Extend the landing blocks (most common)

Edit the two block tags (according to your map's actual terrain):

- `data/doom.nats/tags/block/standable.json`: must be standable below (aligns with the "1" test of `on_ground`);
- `data/doom.nats/tags/block/spawnable_at.json`: this spot and the one above it must be a usable free space (aligns with `isValidEmptySpawnBlock`'s "not a full collision box" intent).

Both can nest references to vanilla tags (such as `#minecraft:dirt`), or list block ids directly.

### 3) Change the biome spawn table

The data comes from `_work/generated/biomes.json` (exported from the vanilla jar).
To change weights or add/remove species, edit that file and re-run:

```bash
node tools/export_rosters.mjs && node tools/gen_mobs.mjs
```

> The export preserves the raw weight sum (no normalization), and the interval partition is point-for-point equivalent to vanilla's `WeightedRandom`.

### 4) Make a mob immune to despawning

Give it the `doom.nats.persistent` tag (corresponding to vanilla's `PersistenceRequired`):

```
/tag <entity> add doom.nats.persistent
```

Entities spawned by this pack carry two tags by default: `doom.nats.spawned` and `doom.nats.cat.<category>`.

## 6. Action List for One Complete Real-Hardware Run (v4.1)

The five checks are in "2. Verification". A run that can be used for calibration goes in this order:

```
/reload                              # newly installed packs are rescanned (no need to quit and re-enter the world)
/gamerule doMobSpawning false        # disable vanilla natural spawning; this pack takes over
/time set night                      # daytime surface light is high, monster tiers don't pass
# Stand still for about 2 minutes (don't open the pause menu, don't let the window lose focus — singleplayer pause stops ticks)
/function doom.nats:debug/all
```

The attribution histogram prints values first and then clears them, so each call is one independent measurement window:

```
[nats.reject] rej: 0=<no chunk> 1=<player within 24> 2=<beyond 128> 3=<light tier> 4=<landing block>
                    5=<global capacity> 6=<local capacity> 7=<spawn cost> spawned=<successes>
[nats.light]  tier: 0=? 3=? 7=? 11=? 15=?      ← the tiers hit when light fails
```

Run `node doom.nats/tools/collect.mjs` outside the pack to produce the report. If `_work/watch_collect.mjs` is running in the background,
it will catch the snapshot line itself and run collect, writing the report path into `_work/collect.done`.

## 7. Known Boundaries (Not Pretending to Equal Vanilla)

| Item | Reason | Current state |
|---|---|---|
| Light | The predicate can't read the brightness value, and can't do a "sample and compare" | Approximated with 5 tiers; vanilla passes with probability `uniform(0..7)` |
| Despawn | Can't read `noActionTime` | Can't replicate "start rolling only after 600 ticks spent more than 32 blocks away"; despawns slightly faster. The roll denominator has been scaled by cadence to preserve the per-unit-time expectation |
| Union counting | Euclidean `distance` can't express Chebyshev squares | Two-mode approximation (exact in singleplayer); an exact union needs box tests with absolute coordinates (289 macros/snapshot) |
| `spawn_costs` | Needs a continuous energy field | Not implemented (in vanilla only `warped_forest` and `soul_sand_valley` are non-empty) |
| `finalizeSpawn` group data | Per-mob logic | Not implemented (e.g. chicken jockeys, sheep color inheritance) |
| Collision detection | Entity AABB | Approximated with block tags |
