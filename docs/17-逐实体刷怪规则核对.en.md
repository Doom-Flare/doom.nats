## 2. Cluster: Line-by-Line Source Verification

Source: `net.minecraft.world.level.NaturalSpawner#spawnCategoryForPosition` (local decompiled artifact
`doom.nats/_work/decomp/out/net/minecraft/world/level/NaturalSpawner.java`, lines 139–206).

```java
int spawned = 0;                                   // ① **Total** successes across groups
for (int i = 0; i < 3; i++) {                      // ② At most 3 groups
   int x = pos.getX(); int z = pos.getZ();         // ③ Each group restarts from the origin
   SpawnerData data = null; SpawnGroupData group = null;
   int groupSize = Mth.ceil(random.nextFloat() * 4.0F);   // ④ ceil(rand*4) first
   int spawnedInGroup = 0;                          // ⑤ in-group count (used by isMaxGroupSizeReached)
   for (int j = 0; j < groupSize; j++) {
      x += random.nextInt(6) - random.nextInt(6);   // ⑥ **accumulating** walk within the group (±5 triangular distribution)
      z += random.nextInt(6) - random.nextInt(6);
      ... distance check ...
      if (data == null) {                           // ⑦ the species is picked only once per group
         Optional<SpawnerData> c = getRandomSpawnMobAt(...);
         if (c.isEmpty()) break;                    //    ← cannot draw ⇒ end **this group** (not the whole attempt)
         data = c.get();
         groupSize = data.minCount() + random.nextInt(1 + data.maxCount() - data.minCount());  // ⑧ recompute
      }
      ... validity chain ...
      spawned++; spawnedInGroup++;
      level.addFreshEntityWithPassengers(mob);
      if (spawned >= mob.getMaxSpawnClusterSize()) return;      // ⑨ cluster cap reached ⇒ end the **whole attempt**
      if (mob.isMaxGroupSizeReached(spawnedInGroup)) break;     // ⑩ in-group cap ⇒ end **this group**
   }
}
```

Our implementation compared

| Source point | This pack | Status |
|---|---|---|
| ① Cross-group accumulation | `$att.spawned` (cleared on every try) | ✅ |
| ② 3 groups | `spawn/begin` sets `$grp 3` | ✅ |
| ③ Reset the origin per group | `$wx = $wx0` in `spawn/group` | ✅ (fixed once in v4.10: early versions reset per mob) |
| ④ Group size `ceil(rand*4)` | `random value 1..4` (the 0 case is ignored) | ✅ (negligible difference) |
| ⑤⑥ In-group accumulation | `$wx += $ax` in `spawn/walk` (0..5 minus 0..5) | ✅ |
| ⑦ Cannot draw ⇒ end this group | `$grp.stop 1` + reason=8 | ✅ |
| ⑧ Recompute group size | `spawn/regroup` (with a min==max degeneracy guard) | ✅ |
| ⑨ Cluster cap reached ⇒ end the whole attempt | `$att.stop 1` (`$att.spawned >= $sel.cluster`) | ✅ |
| ⑩ `isMaxGroupSizeReached` | Tropical fish only, see below | ✅ (added in v4.13) |

| Class | Value | Entities covered |
|---|---|---|
| `Mob` (default) | 4 | The vast majority |
| `AbstractFish` | 8 | cod / salmon / pufferfish / tropical_fish (the latter two are covered by closer overrides) |
| `AbstractSchoolingFish` | `getMaxSchoolSize()` | |
| `Salmon` | 5 | salmon |
| `AbstractHorse` | 6 | horse / donkey / mule / skeleton_horse / zombie_horse / camel / llama / trader_llama |
| `Wolf` | 8 | wolf |

> The wiki "Mob spawning" §Pack spawn size statement matches the bytecode exactly: *"8 wolves, cod, and tropical fish; 6 horses and donkeys; 4 for any other mob"*.
> v4.13 correction: ghast/pillager/happy_ghast (=1) and camel/llama/trader_llama (=6) had been missed.

### `isMaxGroupSizeReached`: Not "Group Size" but "Tropical Fish Variant"

Only `TropicalFish` overrides it in the whole codebase:

```java
public boolean isMaxGroupSizeReached(int size) { return !this.isSchool; }
```

That is: for a tropical fish of a non-schooling variant, the group breaks after spawning 1 fish (regardless of `size`).
This pack's `summon` uses the default variant (without `Variant`) ⇒ equivalent to "tropical fish spawn only 1 per group", implemented accordingly (`$sel.grp1`).

## 3. Wiki Worldgen Datapack: What Was Read

Fetch method: minecraft.wiki returns a 403 challenge page (Cloudflare "Please wait") for scripted requests,

### 3.1 Only Three Spawn-Related Fields on the Data Side (1.21.6)

Source: the wiki "Biome definition (Java Edition)", cross-validated against Spyglass's vanilla mcdoc
(`_work/ref/mcdoc/java/data/worldgen/biome.mcdoc`):

```jsonc
{
  "creature_spawn_probability": 0.1,          // affects passive mobs **during chunk generation** only
  "spawners": {                                // weighted table by category
    "monster": [ { "type": "minecraft:zombie", "weight": 100, "minCount": 4, "maxCount": 4 } ]
  },
  "spawn_costs": {                             // non-empty in these two biomes only
    "minecraft:enderman": { "energy_budget": 1.0, "charge": 0.12 }
  }
}
```

Key conclusion (it shapes the whole project): in 1.21.6 the spawn rules (light formula, placement, distance, cluster, cap)
all live in code, and a datapack can only change these three items. I checked the server jar's `data/minecraft/` directory:
there is no registry such as `spawn_condition` (the top level only holds advancement / recipe / loot_table / structure /
worldgen / tags / datapacks / painting_variant / damage_type / banner_pattern / enchantment /
trial_spawner / jukebox_song / trim_* / *_variant / dialogue and so on).
So "reproducing natural spawning with a datapack" requires hand-porting the code rules into the datapack. Section 4 of this document does exactly that.

> Forward look (already recorded by the wiki, unrelated to this project's 1.21.6 target): from 26.3, `spawners` / `spawn_costs` /
> `creature_spawn_probability` are removed from biome and moved to environment attributes.

### 3.2 Biome Tags Can Be Tested Directly

The `biomes` field of `location_check` accepts the `"#ns:tag"` form (source basis: `HolderSetCodec`'s
`registryAwareCodec = Codec.either(TagKey.hashedCodec(...), homogenousListCodec)`). These vanilla
"on/off by biome" rules can be reproduced verbatim:

| vanilla tag | Effect | This pack's predicate |
|---|---|---|
| `#minecraft:allows_surface_slime_spawns` | Surface slimes (swamp / mangrove_swamp) | `spawn/biome_slime` |
| `#minecraft:reduce_water_ambient_spawns` | water_ambient does not spawn 98% of the time in rivers | `spawn/biome_river` |
| `#minecraft:more_frequent_drowned_spawns` | Drowned 1/15 (otherwise 1/40 + deep water) | `spawn/biome_more_drowned` |
| `#minecraft:polar_bears_spawn_on_alternate_blocks` | Polar bears use an alternate "block below" set | `spawn/biome_polar_alt` |

### 3.3 A Map Shipping Its Own Worldgen Datapack ⇒ the Roster Must Be Regenerated From "Effective Data"

If a custom map ships its own worldgen datapack (overriding `worldgen/biome/*.json`, changing `spawners`),
this pack's 65-biome selection table still reads vanilla data. Current approach: `_work/generated/biome-rosters.json`
is exported from the vanilla jar; suggestion (not implemented): add `--worldgen <datapack directory>` to `gen_mobs.mjs`,
merge the map's biome overrides, and only then generate the roster.

## 4. Per-Entity Rules: 44 Predicates Ported Into the Datapack

Source: the static registration block of `SpawnPlacements` (82 entries) + each entity class's `check*SpawnRules`.
Automatic artifact: `doom.nats/_work/ref/spawn-rules-digest.txt` (a source digest of the 44 predicates, available in the same directory as this file).
This pack's rule table: `doom.nats/tools/lib/entity-rules.mjs` → written at generation time to `_work/generated/entity-rules.json`.

### 4.1 Light Requirements Dispatched Per Entity (the Biggest Fix This Round)

| Entity family | Source rule | This pack's light tier |
|---|---|---|
| Most monsters (zombie/skeleton/creeper/spider/enderman/witch/bogged/camel husk…) | `Monster.isDarkEnoughToSpawn`: sky light ≤ `nextInt(32)` ∧ block light ≤ `monster_spawn_block_light_limit` ∧ combined brightness ≤ `uniform(0..7)` | `dark` (tier approximation) |
| Husk / stray | monster rule + `canSeeSky` | `dark` + `can_see_sky` |
| Magma cube / ghast / zombified piglin / piglin / hoglin / ocelot / strider / aquatic family | No light restriction (difficulty/placement only) | `none` |
| Animal family (sheep/cow/pig/chicken/horse/donkey/llama/camel/fox/rabbit/wolf/goat/armadillo/parrot/frog/mooshroom/panda/polar bear/turtle) | `Animal.isBrightEnoughToSpawn`: `getRawBrightness(pos,0) > 8` | `bright` (`combined ≥ 9` or `can see sky`, see 4.3) |
| Bat | `brightness ≤ nextInt(4)` (7 on Halloween) + 50% coin flip | `bat` |
| Slime | biome whitelist ∧ 50<y<70 ∧ 50% ∧ moon phase ∧ `brightness ≤ nextInt(8)` | `slime` |
| Glow squid | `y ≤ seaLevel-33` ∧ `getRawBrightness == 0` ∧ is water | `glow` |
| Patrol (pillager) | `getBrightness(BLOCK) > 8 ⇒ false` | `bl8` (approximated as combined brightness ≤ 8) |

> In the overworld `dimension_type`, `monster_spawn_block_light_limit = 0` (server jar
> `data/minecraft/dimension_type/overworld.json`) ⇒ monsters effectively require block light 0.
> The datapack's `location_check.light` reads combined brightness (with skyDarken subtracted) and cannot isolate block light ⇒ recorded as an approximation.

### 4.2 Placement Is Per-Type

`SpawnPlacementTypes`:

| Type | Test | This pack's place |
|---|---|---|
| `ON_GROUND` | Below `isValidSpawn` (top face complete ∧ own light emission < 14) ∧ both the position and above are `isValidEmptySpawnBlock` | `0` generic land (`#doom.nats:standable` approximation) |
| `IN_WATER` | Position is water ∧ above is not a redstone conductor | `2` in water / `3` water surface window |
| `IN_LAVA` | Position is lava (strider additionally checks "lava above until air") | `5` lava |
| `NO_RESTRICTIONS` | No check (evoker/fox/phantom/shulker/vex/warden/panda…) | `1` no placement restriction |

The five negative conditions of `isValidEmptySpawnBlock` (full collision box / redstone signal source / has a fluid / `#prevent_mob_spawning_inside` /
dangerous to that mob) are approximated with `#doom.nats:spawnable_at` (maintained by the author against the map's block set; the tool `propose_tags.mjs` can check coverage on real terrain).

Per-entity "block below" tags (since v4.13 the vanilla tags are used directly):

`#animals_spawnable_on` (sheep/cow/pig/chicken/horse/donkey/llama/camel), `#foxes_spawnable_on`, `#rabbits_spawnable_on`,
`#wolves_spawnable_on`, `#goats_spawnable_on`, `#camels_spawnable_on`, `#armadillo_spawnable_on`,
`#parrots_spawnable_on`, `#frogs_spawnable_on`, `#mooshrooms_spawnable_on`, `#axolotls_spawnable_on`,
`#bats_spawnable_on` (= `#base_stone_overworld`), `#polar_bears_spawnable_on_alternate`, `minecraft:sand` (turtle).

### 4.3 Two Points That "Can Only Be Approximated" (Stated Plainly, Not Pretended Away)

1. `getRawBrightness(pos, 0) > 8` (the "bright" animals use) does not subtract skyDarken: at night in the open, raw is still 15 ⇒ vanilla can spawn animals at night too.
   Predicates cannot read raw brightness, so this pack approximates it as `combined brightness ≥ 9` or `can_see_sky` (a `minecraft:any_of` composite predicate).
2. "Sampling comparisons" such as `brightness ≤ nextInt(8)` / `≤ nextInt(4)` cannot be done in a datapack ⇒ approximated with fixed tiers
   (the probabilistic effect in which lower brightness passes more often can only be expressed coarsely through tiers).

|---|---|---|

| Ocelot | `nextInt(3) != 0` | `coin_2of3` |
| Drowned | underwater ∧ 1/40 ∧ `y < seaLevel-5`; 1/15 in more-frequent-drowned biomes | `drowned_deep` + biome predicate |
| Guardian | `nextInt(20)==0` or underwater with no view of the sky; requires water | `coin_1of20` + `can_see_sky` |
| Zombified piglin / piglin / hoglin | Block below is not a nether wart block | `if block ~ ~-1 ~ nether_wart_block` |

## 5. The Despawn Layer: Vanilla Already Handles It

Source chain: `ServerLevel.tick` → per-entity `Entity.checkDespawn()` (called explicitly inside `lambda$tick$2`)
→ `Mob.checkDespawn()`:

```java
if (difficulty == PEACEFUL && shouldDespawnInPeaceful()) discard();
else if (!persistenceRequired && !requiresCustomPersistence()) {
   double d2 = nearestPlayer.distanceToSqr(this);
   int dd = category.getDespawnDistance();            // monster 128 / water_ambient 64
   if (d2 > dd*dd && removeWhenFarAway(d2)) discard();                 // ① hard despawn
   int nd = category.getNoDespawnDistance();          // 32 (all categories)
   if (noActionTime > 600 && random.nextInt(800) == 0 && d2 > nd*nd && removeWhenFarAway(d2)) discard();   // ② probabilistic despawn
   else if (d2 < nd*nd) noActionTime = 0;
}
```

Everything this pack summons is an ordinary mob (no `PersistenceRequired`) ⇒ ① and ② are already running.
Adding a dice layer of its own would only make despawning faster than vanilla ⇒ v4.13 disables `$despawn_dice` by default (kept available).
Hard despawn (128 / water_ambient 64) is kept (byte-identical to vanilla, and tunable by map authors).

> Not reproducible: `noActionTime` cannot be read ⇒ even with this layer enabled, the precondition "more than 32 blocks from the player for 600 ticks before dice start rolling" cannot be reproduced.

### 9.6 Pitfalls of the Tests Themselves (Noted So They Are Not Repeated)

| Pitfall | Symptom | Correct approach |
|---|---|---|
| Test rig built at the player's feet | Every attempt gives reason=1 (24-block exclusion zone) | Build the rig > 24 blocks from the player |
| Water pool built outside the window | `place=3` fails, mistaken for a bug | The water surface window is `seaLevel-13..seaLevel` (overworld 50..63); the pool must be built inside it |
| Testing rules without setting `$py` | Every rule depending on `$py` (candidate point y) fails | In manual testing, first run `scoreboard players set $py doom.nats <y>` (the real flow writes it from `pos/pick`) |
| Using `time set night` (13000) as "night" | That is only sunset; `skyDarken` has not reached its value ⇒ the open is still judged "bright" | Use `time set midnight` (18000) |
| Adding only a roof to create "dark" | Sky light leaks in sideways | Build a sealed box (3×3×3 solid → hollow out the center) |
| Resetting only `sel.cat` and reusing storage | Leftover `nbt` contains the `doom.nats.cat.creature` tag ⇒ misread as "creature was drawn" | Clear the whole storage with `data remove storage` |
| Setting `$catid` outside dispatch | The category draw rolls `$catid` internally in dispatch ⇒ setting it does nothing | Verify with distribution statistics (many draws) instead of a single draw |
| Using `node -e "import('./mcauto.mjs')"` to check syntax | The module's top-level code really runs (clears the world and restarts the server) | Use `node --check` |

### 9.7 Two More Items (v4.14b/c)

A. AABB approximation (the last step of vanilla `isValidSpawnPostitionForType`, `level.noCollision(type.getSpawnAABB(x+0.5,y,z+0.5))`)

- `check/block` gained one more condition: wide entities additionally check the four neighbors (foot layer and head layer), extra-wide ones also check ±2, and tall ones check the third block;
- Real-machine evidence (`verify_struct_aabb.mjs`): a spider is rejected when "a neighbor is blocked", an ordinary-sized zombie is unaffected, and an enderman is rejected when the third block is blocked.

B. Nether fortress structure priority (vanilla `NaturalSpawner.mobsAt → isInNetherFortressBounds`)

### 9.8 Two More Places (v4.14d/e)

A. The mobcap counting convention (aligned with `NaturalSpawner.createState` / `SpawnState`)

Vanilla rebuilds SpawnState every tick: it walks all entities in that dimension, counts them per `MobCategory`, and skips
`isPersistenceRequired() || requiresCustomPersistence()`; `canSpawnForCategoryGlobal` then compares that against
`maxInstancesPerChunk × spawnableChunkCount / 289`. This pack's earlier convention deviated in two places:

| Deviation | Consequence | Fix |
|---|---|---|
| Counting only mobs this pack spawned itself (`tag=doom.nats.cat.*`) | Same-category mobs from spawners/structures/commands do not consume quota ⇒ capacity is too loose | Changed to counting by category entity-type tag (`type=#doom.nats:monster` and so on) |
| Counting was done in `core/tick`'s context (world spawn = overworld) | When the player is in the nether, the overworld's mob count throttles the nether's quota | Counting runs under `at @a[gamemode=!spectator,limit=1]` (= the player's dimension) |
| Vanilla-persistent mobs were not skipped | Mobs with `PersistenceRequired` wrongly consume quota | Added `nbt=!{PersistenceRequired:true}` to the selector |

Supporting change: `tags/entity_type/<category>.json` was upgraded from "entities that appear in the roster" to complete vanilla category membership
(`_work/extract_categories.mjs` extracts from the `EntityType` registration block → `_work/generated/entity-categories.json`;
monster 41 entries / creature 32 / misc 70 / water_creature 2 / water_ambient 4 / underground_water_creature 1 / axolotls 1 / ambient 1).
Real-machine assertion: `$cnt.monster` matches "manually counted by category tag" exactly (`verify_rules` item 8).

B. Test hygiene: do not modify shared scoreboards while the pack's own spawn loop is running

This round hit the same class of pitfall three times (assertions failing randomly, then passing on a rerun):

| Symptom | Root cause | Correct approach |
|---|---|---|
| `$sel.light` was overwritten to 3/5, `$py` changed | The pack runs an attempt every `$eff.period` ticks, writing `$py` / `$sel.*` | Freeze before testing: `$snap_period 20000` + `$eff.period 100000` |
| Still overwritten after freezing (`$eff.period=4` in diagnostics) | The freeze was written before `/reload`; reload's `core/setup → circ/snapshot → circ/apply` resets `$eff.period` back to the configured value | The freeze must come after reload and the stabilization wait, and be confirmed in a loop (the tick that changes `$snap_period` may trigger a snapshot) |
| The water surface window failed intermittently | A `$sel.tag=1` left by the previous step was still in effect (requiring `#animals_spawnable_on` below) | Explicitly set all of `$sel.*` before each independent assertion (including `tag/wide/wide2/tall`) |
| The midnight "dark" check failed intermittently | Using a fixed `sleep` to wait for lighting | Changed to polling the predicate until the lighting really arrives (`waitLight`) |

> In one line: a shared scoreboard is a global variable in a concurrent world — tests must either freeze the world or not depend on the previous state.

### 9.9 Two Real-Machine-Class Pitfalls of Multi-Dimension Support (v4.14g/h)

After the fortress and AABB work, I wrote a "nether end-to-end" verification (`_work/verify_nether.mjs`: teleport a real client to a nether fortress,
wait for chunks to load, then accelerate spawning to see whether this pack's mobs really spawn). It reported 0 nether spawns three times in a row, and chasing it down uncovered two real bugs:

Pitfall 1: an `@e` without position/volume constraints selects entities across dimensions (`execute in <dimension>` does not help either)

```mcfunction
# Place a tagged armor stand in the overworld and another in the nether:
execute if entity @e[tag=dtb]                                  # → count: 2 (!!!both are counted)
execute in minecraft:the_end if entity @e[tag=dtb]              # → count: 2 (the end context sees them too)
execute in minecraft:the_nether if entity @e[tag=dtb,x=-30000000,y=-64,z=-30000000,dx=60000000,dy=400,dz=60000000]  # → count: 1 ✅
```

⇒ To restrict by dimension, the selector must carry coordinate/volume constraints (`distance=..N` or an `x/dx/y/dy/z/dz` box).
(Corroborating evidence: an enormous value such as `distance=..50000000` directly reports "An unexpected error occurred"; only the box form is stable.)
Evidence script: `_work/dimtest7.mjs`.

Impact: the mobcap's "per-dimension count" was originally written as `execute in <dim> as @e[type=…]` (unconstrained) ⇒ all three dimensions counted the same global value,
and the overworld's 70 monsters used up the nether's quota too. Fix: add a whole-map box to the counting selector, see `check/caps`.

Pitfall 2: `core/tick`'s execution context is the world spawn (overworld) ⇒ absolute-coordinate positioning lands in the overworld

The spawn chain used to be:

```
core/tick (world spawn / overworld)
  └ spawn/try
      ├ pos/pick        ← internally as @a at @s: computed absolute coordinates in "the player's dimension"
      └ spawn/at        ← after returning to the outer context, positioned <x> <y> <z>: interprets those coordinates as **overworld** again ✗
```

When the player is in the nether, all candidate points land on the same-named coordinates in the overworld ⇒ real-machine symptom: `reason=2` (no player within 128 blocks) explodes,
and the nether never spawns anything. Fix (v4.14h): wrap the whole attempt in the player context:

```mcfunction
# spawn/try
execute as @a[gamemode=!spectator,sort=random,limit=1] at @s run function doom.nats:spawn/try_at
# spawn/try_at (new): pick a point → jump to the pack origin → three group attempts, all inside the player context
```

End-to-end result after the fix (`verify_nether`): a nether peak of 70 of this pack's mobs, `spawned +163`,
`$cnt.monster.nether=68` (close to cap 70), isomorphic to the overworld.

> Both pitfalls belong to the class that "static checks (lint/closure/interpreter) cannot see and only a real machine exposes",
> which is exactly why this project insists that "every conclusion needs real-machine physical evidence".
