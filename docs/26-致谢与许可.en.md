## 2. Third-Party Boundaries (Important)

| Item | Status |
|---|---|
| Minecraft / Mojang assets (textures, models, sounds, code, decompiled output) | Not included; neither this repo nor the zip contains any |
| Third-party appearance / model packs (rigs and the like) | Not distributed with the pack. The custom-appearance bridge is only the `rules/rigs.json` mechanism (source in `src/tools/gen_exp_aj.mjs`, not released with the v4.25/v4.28/v4.30.0 builds): the bridge only demonstrates the mechanism, and the example uses a placeholder id like `your_rig`; the real rig is supplied by you and follows its own license |
| Content generated by this pack | Only the datapack itself (`pack.mcmeta` + the functions, tags, and predicates under `data/`) |
| Versions and compatibility | See [25-Compatibility and Versions](25-兼容与版本.md); the experimental variant borrows one native experimental flag |

> In one sentence: "can I attach an appearance" is the mechanism; "where does the appearance come from" is your business. We do not carry or distribute third-party model/texture packs.

## 3. Credits

### Platforms and References

- Minecraft: Java Edition (Mojang Studios): this pack is an unofficial work, not affiliated with or endorsed by Mojang / Microsoft. What it replicates is the 1.21.6 vanilla behavior itself.
- The vanilla mechanics themselves: per-entity rules, capacity curves, the despawn layer, `finalizeSpawn` group data, and so on all follow the actual 1.21.6 behavior (comparison table in [`17-逐实体刷怪规则核对.md`](17-逐实体刷怪规则核对.md)).

### Tools and Community

| What was used | Purpose |
|---|---|
| [Spyglass](https://github.com/SpyglassMC/Spyglass) (author and community) | The idea behind build-time datapack static checking (optional integration) |
| [misode's datapack generators](https://misode.github.io/) | Reference implementation when generating JSON such as tags/predicates |
| [PackSquash](https://github.com/ComunidadAylas/PackSquash) | Reference tool for compressing/validating the datapack before release |
| The Minecraft datapack community (conventions documented on the wiki and Discord) | Conventions for naming, tags, load order, and so on |
| Every player who helped verify things in a test save | The "reproducible, catchable" bugs in the real-hardware acceptance runs |

### What We Built Ourselves

The generators and the static gate live in this repo under `src/`; the real-hardware test bench and the per-round reports live on the author's machine and are not distributed with this repo; this repo carries only what players need (see "Repository Layout" in the README).
