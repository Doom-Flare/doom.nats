## 一、结论摘要

| # | 发现 | 严重度 | 处置 |
|---|---|---|---|
| 1 | 动物（creature）永远刷不出来：`check/block` 要求「亮 ≥ 9」，而全局 `check/light` 又要求「暗 ≤ 7」 | 🔴 致命 | 光照改为逐实体分派（`$sel.light`），动物走 bright 档 |
| 2 | 水生生物（water_*）永远刷不出来：落位检查无条件要求「下方可站立」，而水生要求「下方是水」 | 🔴 致命 | 落位改为按 `$sel.place` 分派（水中/水面窗口/岩浆/陆生/无限制） |
| 3 | 簇上限表漏了 ghast / pillager / happy_ghast = 1（还有 camel / llama / trader_llama = 6） | 🟠 高 | 规则表按源码补齐 |
| 4 | water_ambient 的距离上限是 64 格（不是 128） | 🟠 中 | 按类别加 `distance=..64` 判定 |
| 5 | 少了一条群系规则：河流群系里 water_ambient 有 98% 概率直接不刷 | 🟠 中 | 新增 `#minecraft:reduce_water_ambient_spawns` 谓词 + 2% 通过掷币 |
| 6 | 史莱姆少了一个 50% 掷币，且缺群系白名单判定 | 🟠 中 | 规则表补齐（`allows_surface_slime_spawns` + 两个掷币） |
| 7 | 消失掷骰层多余：原版 `Mob.checkDespawn()` 本来就对普通生物生效 | 🟡 低 | 默认关闭（`$despawn_dice 0`），保留可开 |
| 8 | 落位用的「下方方块」是自建大标签，而原版是逐实体 vanilla 标签 | 🟡 低 | 改用 `#minecraft:foxes_spawnable_on` 等原标签 |

## 二、簇（cluster）：源码逐行核对

出处：`net.minecraft.world.level.NaturalSpawner#spawnCategoryForPosition`（本地反编译产物
`doom.nats/_work/decomp/out/net/minecraft/world/level/NaturalSpawner.java` 第 139–206 行）。

```java
int spawned = 0;                                   // ① 跨组的**总**成功数
for (int i = 0; i < 3; i++) {                      // ② 最多 3 组
   int x = pos.getX(); int z = pos.getZ();         // ③ 每组从原点重新起算
   SpawnerData data = null; SpawnGroupData group = null;
   int groupSize = Mth.ceil(random.nextFloat() * 4.0F);   // ④ 先 ceil(rand*4)
   int spawnedInGroup = 0;                          // ⑤ 组内计数（isMaxGroupSizeReached 用）
   for (int j = 0; j < groupSize; j++) {
      x += random.nextInt(6) - random.nextInt(6);   // ⑥ 组内**累加**游走（±5 三角分布）
      z += random.nextInt(6) - random.nextInt(6);
      ... 距离检查 ...
      if (data == null) {                           // ⑦ 物种每组只挑一次
         Optional<SpawnerData> c = getRandomSpawnMobAt(...);
         if (c.isEmpty()) break;                    //    ← 抽不到 ⇒ 结束**本组**（不是整次尝试）
         data = c.get();
         groupSize = data.minCount() + random.nextInt(1 + data.maxCount() - data.minCount());  // ⑧ 重算
      }
      ... 合法性链 ...
      spawned++; spawnedInGroup++;
      level.addFreshEntityWithPassengers(mob);
      if (spawned >= mob.getMaxSpawnClusterSize()) return;      // ⑨ 达簇上限 ⇒ 结束**整次尝试**
      if (mob.isMaxGroupSizeReached(spawnedInGroup)) break;     // ⑩ 组内上限 ⇒ 结束**本组**
   }
}
```

我们的实现对照

| 源码点 | 本包 | 状态 |
|---|---|---|
| ① 跨组累计 | `$att.spawned`（每次 try 清零） | ✅ |
| ② 3 组 | `spawn/begin` 设 `$grp 3` | ✅ |
| ③ 每组重置原点 | `spawn/group` 里 `$wx = $wx0` | ✅（v4.10 修过一次：早期是每只重置） |
| ④ 组大小 `ceil(rand*4)` | `random value 1..4`（0 的情况忽略） | ✅（可忽略差异） |
| ⑤⑥ 组内累加 | `spawn/walk` 里 `$wx += $ax`（0..5 减 0..5） | ✅ |
| ⑦ 抽不到 ⇒ 结束本组 | `$grp.stop 1` + reason=8 | ✅ |
| ⑧ 重算组大小 | `spawn/regroup`（含 min==max 退化保护） | ✅ |
| ⑨ 达簇上限 ⇒ 结束整次尝试 | `$att.stop 1`（`$att.spawned >= $sel.cluster`） | ✅ |
| ⑩ `isMaxGroupSizeReached` | 热带鱼专用，见下 | ✅（v4.13 补） |

### 簇上限表（扫描 1038 个实体类，只有 8 个覆写）

| 类 | 值 | 覆盖到的实体 |
|---|---|---|
| `Mob`（默认） | 4 | 绝大多数 |
| `AbstractFish` | 8 | cod / salmon / pufferfish / tropical_fish（后两者被更近的覆写覆盖） |
| `AbstractSchoolingFish` | `getMaxSchoolSize()` | |
| `Salmon` | 5 | salmon |
| `AbstractHorse` | 6 | horse / donkey / mule / skeleton_horse / zombie_horse / camel / llama / trader_llama |
| `Wolf` | 8 | wolf |
| `Ghast` | 1 | ghast |
| `Pillager` | 1 | pillager |
| `HappyGhast` | 1 | happy_ghast |

> wiki《Mob spawning》§Pack spawn size 的说法与字节码完全一致：*"8 wolves, cod, and tropical fish；6 horses and donkeys；4 for any other mob"*。
> v4.13 修正：原来漏了 ghast/pillager/happy_ghast（=1）与 camel/llama/trader_llama（=6）。

### `isMaxGroupSizeReached`：不是“组大小”，而是“热带鱼变体”

全库只有 `TropicalFish` 覆写：

```java
public boolean isMaxGroupSizeReached(int size) { return !this.isSchool; }
```

即：非群游变体的热带鱼，组内生成 1 只后就 break（与 `size` 无关）。
本包 `summon` 的是默认变体（不带 `Variant`）⇒ 等价于“热带鱼每组只生 1 只”，已按此实现（`$sel.grp1`）。

## 三、wiki worldgen 数据包：读了什么

抓取方式：minecraft.wiki 对脚本请求返回 403 挑战页（Cloudflare "Please wait"），
本轮改用无头 Chrome `--dump-dom` 抓 `?action=raw`（脚本 `_work/wiki.mjs`），
原文存 `doom.nats/_work/research/_raw/wiki_*.wiki`（Mob_spawning 75KB/1577 行、Biome definition、Data pack 等）。

### 3.1 数据侧只有三个与刷怪有关的字段（1.21.6）

出处：wiki《Biome definition (Java Edition)》，并用 Spyglass 的 vanilla mcdoc 交叉验证
（`_work/ref/mcdoc/java/data/worldgen/biome.mcdoc`）：

```jsonc
{
  "creature_spawn_probability": 0.1,          // 仅影响**区块生成期**的被动生物
  "spawners": {                                // 按类别的加权表
    "monster": [ { "type": "minecraft:zombie", "weight": 100, "minCount": 4, "maxCount": 4 } ]
  },
  "spawn_costs": {                             // 只有这两个群系非空
    "minecraft:enderman": { "energy_budget": 1.0, "charge": 0.12 }
  }
}
```

关键结论（决定整个项目形态）：1.21.6 的刷怪规则（光照公式、落位、距离、簇、cap）
全在代码里，数据包只能改这三项。我核对了服务端 jar 的 `data/minecraft/` 目录：
没有 `spawn_condition` 之类的注册表（顶层只有 advancement / recipe / loot_table / structure /
worldgen / tags / datapacks / painting_variant / damage_type / banner_pattern / enchantment /
trial_spawner / jukebox_song / trim_* / *_variant / dialogue 等）。
所以“用数据包复刻自然刷怪”必须把代码规则手工搬进数据包。本文第四节做的就是这件事。

> 前瞻（wiki 已记录，与本项目 1.21.6 目标无关）：26.3 起 `spawners` / `spawn_costs` /
> `creature_spawn_probability` 从 biome 移除，搬到 environment attributes。

### 3.2 群系标签可以直接判定

`location_check` 的 `biomes` 字段接受 `"#ns:tag"` 形式（源码依据：`HolderSetCodec` 的
`registryAwareCodec = Codec.either(TagKey.hashedCodec(...), homogenousListCodec)`）。原版这几条
“按群系开/关”的规则可以逐字复刻：

| vanilla 标签 | 作用 | 本包谓词 |
|---|---|---|
| `#minecraft:allows_surface_slime_spawns` | 地表史莱姆（swamp / mangrove_swamp） | `spawn/biome_slime` |
| `#minecraft:reduce_water_ambient_spawns` | 河流里 water_ambient 98% 不刷 | `spawn/biome_river` |
| `#minecraft:more_frequent_drowned_spawns` | 溺尸 1/15（否则 1/40 + 深水） | `spawn/biome_more_drowned` |
| `#minecraft:polar_bears_spawn_on_alternate_blocks` | 北极熊换用另一套“下方方块” | `spawn/biome_polar_alt` |

### 3.3 地图自带 worldgen 数据包 ⇒ roster 需要按“有效数据”重生成

若自定义地图自己带了 worldgen 数据包（覆盖 `worldgen/biome/*.json`，改 `spawners`），
本包的 65 群系选择表读的还是原版数据。目前的做法：`_work/generated/biome-rosters.json`
由原版 jar 导出；建议（未实现）：`gen_mobs.mjs` 加 `--worldgen <datapack 目录>`，
把地图的 biome 覆盖合并后再生成 roster。

## 四、逐实体规则：44 条谓词搬进数据包

出处：`SpawnPlacements` 的静态注册块（82 条）+ 各实体类的 `check*SpawnRules`。
自动产物：`doom.nats/_work/ref/spawn-rules-digest.txt`（44 条谓词的源码速览，本文件同目录可查）。
本包的规则表：`doom.nats/tools/lib/entity-rules.mjs` → 生成期落盘 `_work/generated/entity-rules.json`。

### 4.1 光照要求按实体分派（本轮最大修正）

| 实体族 | 源码规则 | 本包 light 档 |
|---|---|---|
| 大多数怪物（僵尸/骷髅/苦力怕/蜘蛛/末影人/女巫/沼骸/骆驼尸壳…） | `Monster.isDarkEnoughToSpawn`：天空光 ≤ `nextInt(32)` ∧ 方块光 ≤ `monster_spawn_block_light_limit` ∧ 综合亮度 ≤ `uniform(0..7)` | `dark`（档位近似） |
| 尸壳 / 流浪者 | 怪物规则 + `canSeeSky` | `dark` + `can_see_sky` |
| 岩浆怪 / 恶魂 / 僵尸猪灵 / 猪灵 / 疣猪兽 / 豹猫 / 炽足兽 / 水生族 | 不限光（只查难度/落位） | `none` |
| 动物族（羊/牛/猪/鸡/马/驴/羊驼/骆驼/狐狸/兔子/狼/山羊/犰狳/鹦鹉/蛙/蘑菇牛/熊猫/北极熊/海龟） | `Animal.isBrightEnoughToSpawn`：`getRawBrightness(pos,0) > 8` | `bright`（`综合 ≥ 9` 或 `能看到天空`，见 4.3） |
| 蝙蝠 | `亮度 ≤ nextInt(4)`（万圣节 7）+ 50% 掷币 | `bat` |
| 史莱姆 | 群系白名单 ∧ 50<y<70 ∧ 50% ∧ 月相 ∧ `亮度 ≤ nextInt(8)` | `slime` |
| 发光鱿鱼 | `y ≤ seaLevel-33` ∧ `getRawBrightness == 0` ∧ 是水 | `glow` |
| 巡逻队（掠夺者） | `getBrightness(BLOCK) > 8 ⇒ false` | `bl8`（综合亮度 ≤ 8 近似） |

> 主世界 `dimension_type` 里 `monster_spawn_block_light_limit = 0`（服务端 jar
> `data/minecraft/dimension_type/overworld.json`）⇒ 怪物实际要求方块光为 0。
> 数据包的 `location_check.light` 读的是综合亮度（扣过 skyDarken），无法拆出方块光 ⇒ 记为近似。

### 4.2 落位（placement）是逐类型的

`SpawnPlacementTypes`：

| 类型 | 判定 | 本包 place |
|---|---|---|
| `ON_GROUND` | 下方 `isValidSpawn`（上表面完整 ∧ 自身发光 < 14）∧ 位置与上方都是 `isValidEmptySpawnBlock` | `0` 通用陆生（`#doom.nats:standable` 近似） |
| `IN_WATER` | 位置是水 ∧ 上方不是红石导体 | `2` 水中 / `3` 水面窗口 |
| `IN_LAVA` | 位置是岩浆（炽足兽另查“上方岩浆直到空气”） | `5` 岩浆 |
| `NO_RESTRICTIONS` | 不检查（evoker/fox/phantom/shulker/vex/warden/panda…） | `1` 无落位限制 |

`isValidEmptySpawnBlock` 的五个否定条件（完整碰撞盒 / 红石信号源 / 有流体 / `#prevent_mob_spawning_inside` /
对该生物危险）用 `#doom.nats:spawnable_at` 近似（作者按地图方块集维护，工具 `propose_tags.mjs` 可在真实地形上核覆盖面）。

逐实体“下方方块”标签（v4.13 起直接用 vanilla 原标签）：

`#animals_spawnable_on`（牛羊猪鸡马驴羊驼骆驼）、`#foxes_spawnable_on`、`#rabbits_spawnable_on`、
`#wolves_spawnable_on`、`#goats_spawnable_on`、`#camels_spawnable_on`、`#armadillo_spawnable_on`、
`#parrots_spawnable_on`、`#frogs_spawnable_on`、`#mooshrooms_spawnable_on`、`#axolotls_spawnable_on`、
`#bats_spawnable_on`（= `#base_stone_overworld`）、`#polar_bears_spawnable_on_alternate`、`minecraft:sand`（海龟）。

### 4.3 两个“只能近似”的点（写清楚，不假装）

1. `getRawBrightness(pos, 0) > 8`（动物用的“亮”）不扣 skyDarken：夜里露天 raw 仍是 15 ⇒ 原版夜里也能刷动物。
   谓词读不到 raw 亮度，本包近似为 `综合亮度 ≥ 9` 或 `can_see_sky`（`minecraft:any_of` 复合谓词）。
2. `亮度 ≤ nextInt(8)` / `≤ nextInt(4)` 这类“采样比较”无法在数据包里做 ⇒ 用固定档位近似
   （亮度越低越容易通过的概率效果只能靠档位粗粒度表达）。

|---|---|---|
| 恶魂 | `nextInt(20) == 0` | `coin_1of20` |
| 豹猫 | `nextInt(3) != 0` | `coin_2of3` |
| 溺尸 | 水下 ∧ 1/40 ∧ `y < seaLevel-5`；高溺尸群系 1/15 | `drowned_deep` + 群系谓词 |
| 守卫者 | `nextInt(20)==0` 或水下看不到天；要求水 | `coin_1of20` + `can_see_sky` |
| 僵尸猪灵 / 猪灵 / 疣猪兽 | 下方不是下界疣块 | `if block ~ ~-1 ~ nether_wart_block` |
| 蠹虫 / 末影螨 | 不限光 ∧ 5 格内无玩家 | `noPlayer5`（本包 roster 里暂无这两种） |

## 五、消失层：原版已经在管了

源码链：`ServerLevel.tick` → 每个实体 `Entity.checkDespawn()`（`lambda$tick$2` 里显式调用）
→ `Mob.checkDespawn()`：

```java
if (difficulty == PEACEFUL && shouldDespawnInPeaceful()) discard();
else if (!persistenceRequired && !requiresCustomPersistence()) {
   double d2 = nearestPlayer.distanceToSqr(this);
   int dd = category.getDespawnDistance();            // monster 128 / water_ambient 64
   if (d2 > dd*dd && removeWhenFarAway(d2)) discard();                 // ① 硬消失
   int nd = category.getNoDespawnDistance();          // 32（所有类别）
   if (noActionTime > 600 && random.nextInt(800) == 0 && d2 > nd*nd && removeWhenFarAway(d2)) discard();   // ② 概率消失
   else if (d2 < nd*nd) noActionTime = 0;
}
```

本包召出的都是普通生物（没有 `PersistenceRequired`）⇒ ①②本来就在跑。
再加一层自己的掷骰只会让消失比原版更快 ⇒ v4.13 默认关闭 `$despawn_dice`（保留可开）。
硬消失（128 / water_ambient 64）保留（与原版逐字相同，且可被地图作者调）。

> 不可复刻项：`noActionTime` 读不到 ⇒ 即使打开本层，也无法复刻“距玩家 32 格外满 600 tick 才开始掷骰”的前置条件。

### 9.9 多维度支持的两个真机级坑（v4.14g/h）

做完要塞与 AABB 之后，我写了一个“下界端到端”验证（`_work/verify_nether.mjs`：把真客户端传到下界要塞，
等区块加载，然后加速刷怪观察是否真的生成本包生物）。它连续三次都报下界 0 生成，追下去挖出两个真 bug：

坑 1：不带位置/体积约束的 `@e` 会跨维度选实体（`execute in <维度>` 也不管用）

```mcfunction
# 主世界放一个带标签的盔甲架、下界再放一个：
execute if entity @e[tag=dtb]                                  # → count: 2（！！！两个都算）
execute in minecraft:the_end if entity @e[tag=dtb]              # → count: 2（末地上下文也能看到）
execute in minecraft:the_nether if entity @e[tag=dtb,x=-30000000,y=-64,z=-30000000,dx=60000000,dy=400,dz=60000000]  # → count: 1 ✅
```

⇒ 要按维度限定，选择器必须带坐标/体积约束（`distance=..N` 或 `x/dx/y/dy/z/dz` 盒子）。
（旁证：`distance=..50000000` 这种超大值会直接报 "An unexpected error occurred"，盒子形式才稳。）
证据脚本：`_work/dimtest7.mjs`。

影响：mobcap 的“每维度计数”最初写成 `execute in <dim> as @e[type=…]`（无约束）⇒ 三个维度数出来是同一个全局值，
主世界的 70 只怪物把下界的额度也占光了。修法：计数选择器加全图盒子，见 `check/caps`。

坑 2：`core/tick` 的执行上下文在世界出生点（主世界）⇒ 绝对坐标定位会落到主世界

刷怪链原来是：

```
core/tick（世界出生点 / 主世界）
  └ spawn/try
      ├ pos/pick        ← 内部 as @a at @s：算出了"玩家所在维度"的绝对坐标
      └ spawn/at        ← 返回外层上下文后 positioned <x> <y> <z>：又按**主世界**解释这些坐标 ✗
```

玩家在下界时，候选点全部落到主世界的同名坐标上 ⇒ 真机现象：`reason=2`（128 格内没有玩家）暴涨、
下界永远 0 生成。修法（v4.14h）：把整次尝试包进玩家上下文：

```mcfunction
# spawn/try
execute as @a[gamemode=!spectator,sort=random,limit=1] at @s run function doom.nats:spawn/try_at
# spawn/try_at（新）：取点 → 跳到 pack 原点 → 三组尝试，全在玩家上下文里
```

修完的端到端结果（`verify_nether`）：下界峰值 70 只本包生物、`spawned +163`，
`$cnt.monster.nether=68`（接近 cap 70），与主世界同构。

> 这两个坑都属于“静态检查（lint/闭包/解释器）看不见、只有真机才暴露”的那一类，
> 也正是这个项目坚持“每条结论都要真机物证”的原因。
