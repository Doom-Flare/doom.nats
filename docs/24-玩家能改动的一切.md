# 24 · 玩家能改动的一切（全清单）
English: `docs/24-玩家能改动的一切.en.md`


> 面向玩家/整合包作者：这张表把"你能动什么"一次说全。
> 三条口径先说清：① 默认什么都不改 = 原版（`rules/` 空 + storage 空时行为与原版一致，每次提交自动验）；
> ② 能改的是判定与数量，不是客户端资源与实体 AI；③ 标 🧪 的属于非原版能力，只在实验性变体 `v4x` 里，且世界要开对应实验性玩法。
>
> 分层：A 运行时刻（游戏里改，下一拍生效）· B 构建期（改文件后重新生成，可分享）· C 运行时旋钮（`$cfg.*`/`$eff.*`，见 `docs/18`）· D 标签与开关（方块/实体标签、模式命令）。

---

## A. 运行时刻：storage `doom.nats:author`（在游戏里改，立即生效）

管理命令：

```
/function doom.nats:author/show        打印当前所有覆盖（含"实验性：开/关"）
/function doom.nats:author/reset       全部回到原版
/function doom.nats:author/help        命令一览
/function doom.nats:author/add_entry   从你手上的生物采样一条（含 NBT）🧪
/function doom.nats:author/export      把当前覆盖导出成可复制的一行命令（分享给别人）
/data merge storage doom.nats:exp_in {name:"blood_moon"}   套用预设 🧪 第一步：设预设名（可用 blood_moon / storm_season / deep_dark）
/function doom.nats:exp/preset         套用预设 🧪 第二步：派发上面那个名（实测入口；无参宏，doom.nats:author/preset 在成品里不存在）
```

### A1 逐实体规则 `entityRules."<实体 id>"`

| 键 | 取值 | 作用 | 例子 |
|---|---|---|---|
| `belowAny` | 方块标签数组 | 额外算"能站的地方" | `["#minecraft:leaves"]` ⇒ 僵尸能刷在树叶上（方块标签别漏 `#`；`minecraft:leaves` 是标签名不是方块 id） |
| `place` | `ground` / `any` / `water` / `water_surface` / `below_tag` / `lava` | 落位类型（要不要地面、要不要在水里） | 发光鱿鱼改 `ground` ⇒ 上陆地 |
| `light` | `none` / `dark` / `bright` / `bat` / `slime` / `glow` / `bl8` | 光照档 | `dark` 就只在暗处刷 |
| `lightMax` / `lightMin` | 0–15 | 比档位更细的亮度上下限 | `lightMax:7` 只在天黑后刷 |
| `yMin` / `yMax` | 整数（闭区间） | 只在某个高度刷 | `yMin:-64,yMax:0` ⇒ 只在地下 |
| `biomeIn` / `biomeNot` | 群系 id 数组或 `["#标签"]` | 只在/不在这些群系 | `["#minecraft:is_deep_ocean"]` |
| `weather` | `thunder` / `rain` / `clear` | 只在某种天气 | `thunder` ⇒ 雷暴限定 |
| `persist` | `true` | 生成即永不消失 | 做"地标怪" |

> 只能构建期改的键（写进 storage 不会生效）：`tag`（`below_tag` 用哪个方块标签）· `cluster`（一次最多几只）· `coins`（掷币/月相）· `sky` `deep` `river98` `d64` `noPlayer5` `ySea` `yTurtle` `lavaToAir` `noSky` `belowSurface` `notWart` `moreDrowned` 等源码级开关。改 `rules/entity-rules.json` 后重新生成（玩法 B）。
> 注意 `ySea` 这类"规则级"开关运行时刻去不掉：发光鱿鱼的深度门（y ≤ 海平面-33）在 `check/entity` 里按规则号判，改 `place` 不会绕过它。

### A2 追加条目 `entries[]`（一条 = "什么条件下多刷什么"）

| 字段 | 说明 |
|---|---|
| `id` `mob` `category` | 名字 / 实体 / 类别（`monster` `creature` `ambient` `water_creature` `water_ambient` `underground_water_creature` `axolotls`） |
| `biome` | 群系 id 或 `#标签`（单数；要多个群系就加多条。例："末地外岛" = `end_highlands`/`end_midlands`/`end_barrens`/`small_end_islands` 共 4 条，中央岛是另一个群系 `the_end`） |
| `weight` | 命中率 ≈ `weight / 1000000`（不是"同池按比例"）：要生效就填 10 万级，`40` 这种小数字等于不刷；默认 `1`。多条同时存在时看总和：Σweight ≤ `1000000`，否则靠后的条目永不命中（各条按声明顺序依次吃 `0..999999` 的区间 ⇒ 例：4 条各 `900000` 只有第 1 条活着，应改成 4 条各 `200000`）。构建期 `rules/entries.json` 同口径。见 [[规则字段参考]] 的 ⚠ `weight` 的真实口径 |
| `min` / `max` | 一次生几只（组大小；上限还受原版"簇上限"约束，多数生物 ≤ 4） |
| `nbt` | 自定义 NBT（装备、名字、属性、药水效果、乘客…1.21.5+ 是 `equipment:{}`） |
| `when` | `thundering` `raining` `yMin` `yMax` `lightMax` `lightMin`（全部 AND） |

> 构建期条目（玩法 B）还多这些写法：`biomes`（多群系数组）· `group:[最少,最多]` · 条目级 `place`/`light`/`tag`/`cluster` 覆盖 · `groupByY`。运行时刻那套读的是 `biome` / `min` / `max`，两条别混。

### A3 数量曲线 `counts`

| 键 | 作用 |
|---|---|
| `groupByY."<实体>"` | `[{yMin?,yMax?,min,max}]`：一次生几只按高度分段 |
| `capByY."<类别>"` | `[{yMin?,yMax?,max,localMax}]`：这类生物的总容量/每玩家容量按高度分段 |

硬上限（超出不生效）：条目 8 条 · Y 段 8 段 · 落位面标签 8 个 · 群系列表各 4 条。

### A4 改不到的部分（运行时刻做不到）

源码级开关（`coins`/`cluster`/`deep`/`sky`/`ySea` 等决定函数体形状的字段）、给"该群系原本没有该类别的"加怪（要改世界生成）、条目不走组数据（`SpawnGroupData`，要完整组语义用构建期）。

另有两条最容易踩空的边界（真机实测）：

- 不能按结构限刷。"只在末地城 / 要塞 / 神殿里刷"这类写法没有对应字段：author 层没有 structure 键，成品里也没有 `in_end_city` 谓词；构建期硬编码的结构只有要塞 / 前哨站 / 沼泽小屋 / 海底神殿 / 远古城市 / 试炼密室 ⇒ 只能改用群系表达（例：末地外岛 = 4 个群系，见上表）。
- 条目路径不装载被选物种的原版 `place`/`light`/`rule`/`tall`。这几个 `$sel.*` 会沿用"上一次香草抽取"留下的残留值 ⇒ 读 `$sel.rule` / `$sel.tall` 可能不是你以为的物种。`entityRules` 只能钉 `place`/`light` 两项，`rule`/`tall` 没有对应字段；换群系/换维度后残留可能从"惰性"变成"否决"（`reason=9`，表现成"怪被无声拒掉"）。排查见 [[FAQ]]。

## B. 构建期：`doom.nats/rules/`（改文件 + 重新生成，可分享给别人）

| 文件 | 内容 | 与 A 的关系 |
|---|---|---|
| `rules/entity-rules.json` | A1 的全部字段（含运行时刻做不到的 `coins`/`cluster`/`deep`…） | A 的子集 + 源码级开关 |
| `rules/entries.json` | A2 的全部字段（条目走完整组数据） | A 的加强版 |
| `rules/counts.json` | A3 的全部字段 | 同 A |
| `rules/rigs.json` 🧪 | 自定义外观：`carrier`（内核生物）/ `carrier_nbt` / `rig`（骨架召唤函数）/ `on_spawn` / `cat` / `count_with_carrier` | 只在实验性变体，且未随 v4.25/v4.28/v4.29/v4.30.0 成品发布（`src/rules/rigs.json` 是 `{}` ⇒ 生成器不产文件；需自备非空配置 + `DOOM_EXP=1` 重跑 `gen_exp_aj`） |
| `rules/presets/*.json` 🧪 | 预设包（一键切换的世界观） | 实验性 |

生成与安装（以下命令需要本机开发环境，不随本仓库分发；只想要数据包的话，直接解压 `dist/` 的 zip 即可）：

```bash
cd doom.nats
for g in gen_pack gen_pos gen_check gen_mobs gen_spawn gen_despawn gen_effects gen_debug gen_group gen_author; do node tools/$g.mjs; done
node tools/check_static.mjs                  # 必须 0 error（默认变体 0 error / 2 warning）
node tools/install.mjs --variant std          # 或 --experimental 装实验性变体
```

## C. 运行时旋钮 `$cfg.*` / `$eff.*`（键清单与取值范围见 `docs/18-配置手册.md`）

| 组 | 能调什么 |
|---|---|
| 容量 | 每个类别的每玩家上限与全局容量基数（`max_monster` / `max_creature` / `max_ambient` / `max_water_*` / `max_axolotls` …） |
| 光照 | 怪物"够暗"的档位（`light` 0–15 的分档） |
| 节拍 | 刷怪尝试周期 `period`、批处理量 `batch`、快照周期（调快=更密，调慢=更省） |
| 世界 | 海平面、下界/末地的光照档、出生点 24 格排除、世界边界（reason=11）、取点回退与地板高度 |
| 玩法 | `peaceful`（和平难度）、`difficulty`、`special`（特殊生物比例）、`persist`（全部生成物持久化） |
| 模式 | `mode/survival`（关原版生成、本包接管）/ `mode/manual` / `mode/auto` / `mode/off`（交还原版） |

## D. 标签与对象（作者/整合包最常用的"接口"）

| 东西 | 作用 |
|---|---|
| `#doom.nats:standable` / `#doom.nats:full_collision` | "什么算能站的地面"（`belowAny` 之外的全局白名单） |
| `#doom.nats:spawnable_at` / `#doom.nats:narrow_partial` | "什么算空位/窄条可穿过"（AABB 近似） |
| `#doom.nats:water_fluid` | 什么算"水"（含水草/海带/气泡柱） |
| `doom.nats.persistent` 实体标签 | 免疫本包清理层（原版消失逻辑仍适用） |
| `PersistenceRequired:1b` | 原版语义：永不消失 |
| `#doom.nats:monster` 等类别标签 | 按类别筛选/统计（`@e[type=#doom.nats:monster]`） |
| 结构覆盖 / 群系名单 | 走世界生成覆盖（`tools/apply_worldgen.mjs`），可整类删掉或改写某群系的刷怪表 |

## E. 实验性专属 🧪（`v4x` 变体，世界需开对应实验性玩法才能加载）

| 能力 | 怎么写 |
|---|---|
| `near`：附近有什么才刷（"狼群附近出羊"） | 条目/规则里加邻近实体条件（半径 + 数量范围） |
| `on_spawn`：出生演出（粒子/音效/播报/额外 NBT） | 条目里写 `on_spawn:1b`（钩子开关），再在数据包里建函数 `doom.nats:exp/on_spawn/<条目 id>`（`@s` = 新实体）；或预设里配置 |
| 预设包 | `data merge storage doom.nats:exp_in {name:"blood_moon"}` → `function doom.nats:exp/preset`（实测入口；`author/preset` 在成品里不存在） |
| 自定义外观（rig 桥接） | `rules/rigs.json`：真实体当内核 + 骨架当外观（`ride` 挂载）。源码在 `src/tools/gen_exp_aj.mjs`，未随 v4.25/v4.28/v4.29/v4.30.0 成品发布：需自备非空 `rules/rigs.json`（样例 `src/rules/examples/aj/rigs.json`）并 `DOOM_EXP=1` 重跑生成器；本仓 `rules/rigs.json` 就是 `{}`，成品 zip 里 `exp/aj` 条目为 0 |
| `author/export` 分享 | 把当前覆盖打成一行可复制命令 |

引擎门：实验性变体在 `pack.mcmeta` 里声明所需旗标；世界没开就拒绝加载（不是警告）。1.21.6 可借用的原生旗标只有 `minecart_improvements` / `redstone_experiments` / `trade_rebalance`，开它的世界会同时拿到对应的原版改动。

## F. 一句话总结

位置（落位面/方块标签/Y）· 状态（光照/天气/时间/月相）· 空间（群系白黑名单；结构只有构建期硬编码的 6 种，运行时刻表达不了）· 数量（权重/组大小/容量随高度）· 外观与演出（NBT/出生特效/自定义骨架 🧪）。
这五组互相正交，可以叠加组合。"雷暴的深海、悬在海面、骑着鸡、戴着发光头盔、一次两只"这种效果，就是在这张表里各挑一项拼出来的。
