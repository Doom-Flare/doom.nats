# 21 · What Players/Map Authors Can Change (and How)

中文: `docs/21-玩家可改清单.md`

> "Player" in this pack = an author using this pack to make a custom map. Every item below comes with the concrete way to change it; after changing anything, uniformly run `/function doom.nats:cfg/apply` (or, after switching dimensions, `/function doom.nats:cfg/apply_here`).
> Type declarations are in `doom.nats/mcdoc/doom.nats/config.mcdoc` inside the unzipped pack (for editor hints).

## A. Configuration (Single Entry Point: `doom.nats:config` → `cfg/apply` → `$cfg.*`)

```mcfunction
# Write only the keys you're changing; the rest take defaults (cfg/setup rewrites defaults on every load)
data merge storage doom.nats:config {difficulty:3, special:100, batch:60, band:{mode:3,yMin:40,yMax:120}}
function doom.nats:cfg/apply
```

| Key | Default | What changing it does |
| --- | --- | --- |
| `seaLevel.{overworld,the_nether,the_end}` | 63 / 32 / 0 | Water-surface window, glow squid `y≤sea-33`, turtle `y<sea+4` |
| `light.{...}` | 7 | The monster "dark" tier upper bound (an approximation of `uniform(0..light)` tiers) |
| `cap.{monster,creature,ambient,water_creature,water_ambient,underground_water_creature,axolotls}` | 70/10/15/5/20/5/5 | That category's mobcap (`maxInstancesPerChunk`) |
| `distance.{...}` | 128 (`water_ambient` 64) | That category's despawn distance |
| `noDespawnDistance` | 32 | Within this distance, `noActionTime` is zeroed |
| `playerExclusion` | 24 | No spawning within 24 blocks of a player (vanilla `isRightDistanceToPlayerAndSpawnPoint`) |
| `spawn24` + `spawnX` `spawnY` `spawnZ` | 0 (off) + 0/0/0 | No spawning within 24 blocks of the world spawn (v4.17). Off by default: a datapack can't read `getSharedSpawnPos()`, so the author must declare the coordinates; `spawn24:1` takes effect only when all three axes are given, and missing any one axis reverts to off. Failure attribution `reason=10` (details in docs/18 §2.2b) |
| `period` / `batch` / `maxBatch` / `density` | 5 / 6 / 40 / 0 | Spawn cadence and throughput; when `density>0`, AIMD auto-adjusts `batch` |
| `dice` | 0 | >0 turns on this pack's probabilistic despawn layer (an optional extra beyond vanilla `checkDespawn`) |
| `creatureGate` | 400 | The cadence at which passive mobs become candidates (vanilla `gameTime % 400`) |
| `persist` | 0 | 1 ⇒ spawned mobs all carry `PersistenceRequired:1b` (never despawn) |
| `peaceful` | 0 | 1 ⇒ the whole monster category stops spawning (a datapack can't read difficulty, so the author must declare it) |
| `difficulty` | 2 | 0..3; only affects the "spiders share effects on hard difficulty" group data |
| `special` | -1 | Regional difficulty percent; -1 = derive from `difficulty` (normal 75 / hard 100) |
| `band.mode` | 0 | 0 find the ground automatically / 1 fixed band / 2 follow the player ± jitter / 3 uniform random band (closest to vanilla) |
| `band.yMin` `band.yMax` `band.jitter` | 60 / 70 / 3 | Parameters of the modes above (`min==max` has a degeneracy guard) |

## B. Block Tags (Decide "What Counts as Standable / a Usable Free Space")

| File | Semantics | How to change |
| --- | --- | --- |
| `data/doom.nats/tags/block/standable.json` | Approximates `ON_GROUND`'s `isValidSpawn` (full top face ∧ own light emission <14) | A map pack overrides the same-named tag; or run `node src/tools/propose_tags.mjs` for a suggested set |
| `data/doom.nats/tags/block/spawnable_at.json` | Approximates `isValidEmptySpawnBlock` (not full collision / not a redstone source / not a fluid / not a dangerous block) | Same as above |
| `data/doom.nats/tags/entity_type/<category>.json` | Category → entities (used by cap counting and `@e[type=#…]`) | Add them when you add custom mobs |

## C. Functions You Can Call Directly (The Switches in the Author's Hands)

| Function | Purpose |
| --- | --- |
| `doom.nats:cfg/setup` | Rewrite the defaults (runs automatically once on load) |
| `doom.nats:cfg/apply` / `cfg/apply_here` | Fold storage into `$cfg.*`; the latter probes the current dimension first |
| `doom.nats:mode/auto` / `mode/off` / `mode/manual` | enable/disable/manual takeover (auto sets `gamerule doMobSpawning false`) |
| `doom.nats:spawn/try` | Manually run one complete attempt (3 groups, one species draw per group) |
| `doom.nats:debug/env` / `debug/all` / `debug/clear` | Environment snapshot / full diagnostics / clear the field (skips persistent and riding mobs) |
| `doom.nats:grp/init` + `grp/mem/<slug>` | The group data layer (internal use; callable directly for testing and debugging, needs `with storage doom.nats:sel` / `doom.nats:grp`) |

## D. Save/World Side

| Item | How to change |
| --- | --- |
| Vanilla spawning | `mode/auto` sets `gamerule doMobSpawning false` (this pack takes over); for coexistence use `mode/manual` |
| Game difficulty | Only settable by the map/server; this pack declares it with `difficulty` (it can't read the real difficulty) |
| World spawn 24-block exclusion | Implemented (v4.17, off by default): a datapack can't read `getSharedSpawnPos()`; the way to change it is writing `{spawn24:1, spawnX:…, spawnY:…, spawnZ:…}` into `doom.nats:config` and then `cfg/apply` (see docs/18 §2.2b) |
| Map's own worldgen (overriding biome `spawners`) | Implemented (v4.18/Q7): `node tools/apply_worldgen.mjs --worldgen <map dir containing data/>` → `export_rosters` → 9 generators; `--reset` reverts, `--status` shows the current state. For full regression verification use `node tools/regress.mjs --worldgen <dir>` (it reverts automatically afterwards and reads back to verify). Real-hardware four-phase numbers in `reports/验证-世界生成覆盖-20260928.md` (not in this repo) |

## E. Not Changeable (Changing These Means Touching the Generators/Code)

| Item | Why |
| --- | --- |
| Biome → species table (roster) | Generated from `_work/generated/biome-rosters.json`; the way to change it is to modify the extractor/generator and regenerate |
| Per-entity rules (placement/light/coin flip/cluster cap) | `tools/lib/entity-rules.mjs` is the single source of truth; hand-editing artifacts is forbidden |
| Structure `spawn_overrides` | Currently only nether fortresses; for other structures see docs/19 Q2 (not implemented) |
| Brain memory / school-of-fish leader / fox target list | Memory entries can be written with NBT ( `dig_cooldown` was verified on real hardware), but sensor memory is recomputed every tick, and object references and the Goal list are not data |
| Halloween pumpkins | Reads the system calendar; a datapack has no interface |

## F. Pack Body and Test Infrastructure

| Item | Notes |
| --- | --- |
| Install | Unzip `dist/doom.nats-v4.31.0.zip` and put `doom.nats/` into `<save>/datapacks/` (script `src/tools/install.mjs`) |
| Production maps | Don't include `zz-test-fixtures` or `doom.log` (that's test infrastructure; install pulls it in too, so just delete it for release) |
| Verification | `node src/tools/check_static.mjs` (generator drift/lint/closure); on real hardware `regress.mjs --reuse` |
