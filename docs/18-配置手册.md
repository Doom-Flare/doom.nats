# 18 · 配置手册（「所有的刷新都可以被定义」，v4.14）
English: `docs/18-配置手册.en.md`


> 目标：把此前散落在生成器里的数值全部收进可被地图/数据包覆盖的配置层；
> 每一格刷怪行为（取点高度、类别容量、距离、节拍、光照档、海平面、持久化、方块标签、逐实体规则）
> 都能由作者声明或改写。本文是全部旋钮的清单与出处。

---

## 一、三层配置模型

| 层 | 位置 | 谁写 | 说明 |
|---|---|---|---|
| 默认层 | `storage doom.nats:cfg_defaults` | 本包（每次装载重写） | 值 = 原版语义（出处见下表），别手改 |
| 覆盖层 | `storage doom.nats:config` | 地图/作者（只写想改的键） | 不需要写全；没有的键取默认 |
| 折算层 | `$cfg.*` 计分板 | `cfg/apply` | 其余各层只读 `$cfg.*`（每拍随维度刷新） |

写入方式：

```mcfunction
# 只覆盖你想改的键（其余的照旧）
data merge storage doom.nats:config {seaLevel:{overworld:64}, cap:{monster:120}, band:{mode:1, yMin:70, yMax:90}}
function doom.nats:cfg/apply          # 在主世界/当前玩家维度生效
function doom.nats:cfg/apply_here     # 先探测执行位置所在维度，再折算（作者复核用）
```

- `cfg/apply` 读取由 `circ/snapshot` 每拍写入的 `$snap.dim`（在首个非旁观玩家位置探测）；
- `cfg/apply_here` 是在当前执行位置探测维度（`execute in minecraft:the_nether run function doom.nats:cfg/apply_here`）；
- 两种方式都会把默认层与覆盖层合并，覆盖层优先。

> ⚠ `data merge` 是浅合并：`{cap:{monster:120}}` 只改 `cap.monster`，其他 `cap.*` 保持默认。

### 2.2 类别容量与距离

| 键 | 默认 | 原版出处 |
|---|---|---|
| `cap.monster` | `70` | `MobCategory.MONSTER(70, …)` |
| `cap.creature` | `10` | `MobCategory.CREATURE(10, …)` |
| `cap.ambient` | `15` | `MobCategory.AMBIENT(15, …)` |
| `cap.water_creature` | `5` | `MobCategory.WATER_CREATURE(5, …)` |
| `cap.water_ambient` | `20` | `MobCategory.WATER_AMBIENT(20, …)` |
| `cap.underground_water_creature` | `5` | `MobCategory.UNDERGROUND_WATER_CREATURE(5, …)` |
| `cap.axolotls` | `5` | `MobCategory.AXOLOTLS(5, …)` |
| `distance.monster` … `distance.axolotls` | `128`（`water_ambient` 为 64） | 第 5 个构造参数 = `despawnDistance` |
| `noDespawnDistance` | `32` | `MobCategory.noDespawnDistance`（近于此距离会清零 `noActionTime`） |
| `playerExclusion` | `24` | `NaturalSpawner.isRightDistanceToPlayerAndSpawnPoint`：`distSq ≤ 24²` 拒 |
| `spawn24` | `0`（关闭） | 同一条判定的第二分支：`getSharedSpawnPos().closerToCenterThan(pos, 24)` 拒。数据包读不到出生点 ⇒ 需作者声明（见 2.2b） |
| `spawnX` / `spawnY` / `spawnZ` | `0` | 世界出生点的方块坐标（整数）。与 `spawn24:1` 同时给出才生效 |

全局容量算法（逐字复刻，不可配）：`cap = cap.<类别> × spawnableChunkCount / 289`（整数除法、严格小于）；
`spawnableChunkCount` 由 `circ/snapshot` 用 `execute if loaded` 实测 17×17 并集。

统计口径（v4.14d 对齐原版 `SpawnState.createState`）：计数在玩家所在维度里做，按
`type=#doom.nats:<类别>`（完整 vanilla 类别成员）统计，并跳过 `nbt={PersistenceRequired:true}` 的生物。
⇒ 刷怪笼 / 结构 / 指令 / 其它数据包生成的同类生物都会占用额度（与原版一致）。
类别标签可用 `node _work/extract_categories.mjs` 重新生成（来源 = `EntityType` 注册块）。

维度作用域的真机经验（v4.14g/h）：
① 不带坐标/体积约束的 `@e` 会跨维度选实体（`execute in <维度>` 不管用）。要限定必须加
   `distance=..N` 或 `x/dx/y/dy/z/dz` 盒子，本包的每维度计数就是这么做的。
② 刷怪尝试必须在玩家上下文里跑（`core/tick` 的上下文在世界出生点）。否则绝对坐标定位会落到主世界，
   玩家在下界/末地时永远刷不出怪。实现见 `spawn/try → spawn/try_at`。

### 2.2b 世界出生点 24 格排除（v4.17 · P1-5）

原版 `isRightDistanceToPlayerAndSpawnPoint` 一次判两条（1.21.6 named 208 行）：

```java
if (distSq <= 576.0) return false;                                        // ① 玩家 24 格 ⇒ 本包的 reason=1
else if (level.getSharedSpawnPos()                                     // ② 世界出生点 24 格
             .closerToCenterThan(new Vec3(pos.getX()+0.5, pos.getY(), pos.getZ()+0.5), 24.0)) return false;
```

②这条数据包读不到：`level.dat` 的 `spawn` 字段没有谓词/命令可查，玩家 NBT 里的 `SpawnX/Y/Z` 是床/重生锚
（睡过觉就与世界出生点分叉）。所以只能由作者声明，默认关闭：

```mcfunction
# 例：世界出生点在 (-128, 64, 320)
data merge storage doom.nats:config {spawn24:1, spawnX:-128, spawnY:64, spawnZ:320}
function doom.nats:cfg/apply
```

- 启用门槛：`spawn24=1` 且三轴坐标都声明过。缺任一轴 ⇒ `cfg/apply` 把 `$cfg.spawn24` 压回 `0`
  （否则默认 `0,0,0` 会被当作出生点，把世界原点周围 24 格整片禁掉）；
- 判定等价于原版浮点式（含 `BlockPos` 中心的 `+0.5` 半格偏移）：整数式 `4d² = 4dx² + (2dy+1)² + 4dz² < 2304`，
  正好 24 格不算拒（与源码的 `<` 一致）；
- 失败归因：`reason=10`（直方图 `[nats.reject] rej: … 10=<n>`；原 0–9 编码见 `spawn/emit` → `debug/reject`）；
- 候选点坐标取 `$wx / $py / $wz`（`spawn/walk` 维护的当前游走点），不是群系快照点；
- 读不到出生点的旧行为（= 这条判定完全不生效）仍是一份可选的“已知偏差”，见 docs/19 Q1。

红→绿记录（两个真机级坑，都是这条判定自己踩出来的）：

1. 门槛不能写 `execute unless data …`。离线解释器（`tools/lib/interp.mjs` 的 `evalCondition`）没有 `data` 分支，
   `unless data storage …` 会被判成“取反后为真”，后面的 `storage` 就被当成子命令 ⇒ `sim_v4` 的 `no-error`
   从 27 PASS/0 FAIL 变成 24/3（`execute subcommand storage` ×3，经 cfg/apply 每次调用放大）。改成
   `set 0 → execute if data storage … run set 1 → 三轴相乘` 后恢复 27/0（且真机语义完全相同）。
2. 测试必须先对齐“执行维度”。`@a[distance=…]` 是按执行维度选人的：机器人在下界时，在主世界
   `execute positioned … run function check/distance` 会因“本维度没有玩家”退化成 `reason=2`，8 条断言全红。
   `_work/verify_spawn24.mjs` 每次都先读玩家 `Dimension`，再 `execute in <维度> positioned …`。

### 2.3 节拍与密度

| 键 | 默认 | 原版出处 | 说明 |
|---|---|---|---|
| `period` | `5` | —（数据包特有） | 每 `period` tick 发起一批刷怪尝试；原版是“每合格区块每 tick” |
| `batch` | `6` | — | 每批多少个原点（吞吐旋钮） |
| `maxBatch` | `40` | — | 密度控制（AIMD）能加到的上限；与 `gamerule maxCommandChainLength` 挂钩 |
| `density` | `0` | — | 目标生成数/分钟（0 = 关闭自动调节，用 `batch` 手工值） |
| `dice` | `0` | — | 本包自带的“概率消失”层；0 = 关闭（交给原版 `Mob.checkDespawn`，见 §5） |
| `creatureGate` | `400` | `ServerChunkCache.tickChunks`：`gameTime % 400 == 0` | 被动生物（creature）只在节拍命中的那一拍进候选类别（`MobCategory.isPersistent` 语义） |
| `persist` | `0` | — | 1 ⇒ 本包生成的所有生物带 `PersistenceRequired:1b`（永不消失） |
| `peaceful` | `0` | `MinecraftServer.isSpawningMonsters()`：`difficulty != PEACEFUL` | 1 ⇒ monster 类别整类不进候选（数据包读不到难度，需地图/作者声明；和平难度下原版自己也会让怪物消失） |
| `difficulty` | `2` | — | 0 和平 / 1 简单 / 2 普通 / 3 困难。数据包读不到游戏难度，组数据层里“蜘蛛在困难难度共享效果”这一条靠它声明 |
| `special` | `-1` | — | 区域难度系数 percent（`DifficultyInstance.getSpecialMultiplier()` 的 0..1 × 100）。`-1` = 自动：按 `difficulty` 取成熟世界近似（普通 75、困难 100；简单/和平 0）。原版按世界时间/月相/区块驻留时间逐区块计算，数据包不可观测 |

### 2.4 取点（高度带）

| 键 | 默认 | 说明 |
|---|---|---|
| `band.mode` | `0` | `0` 自动找地面 · `1` 固定带随机 · `2` 跟随玩家 ± jitter · `3` 均匀随机带（最接近原版 `uniform(minY, 地表+1)`） |

### 2.55 结构刷怪优先（下界要塞）

`spawn/pick_one` 命中“下界 ∧ 下方是 `minecraft:nether_bricks` ∧ 位于 `minecraft:fortress` 结构内”这一组合时，
用固定表 `mob/fortress`（= 原版 `NetherFortressStructure.FORTRESS_ENEMIES`，权重和 28）替代群系表。
要塞路径把 `$cost.threshold` 置 0（不做 spawn cost）。要换成别的结构/名单，改 `gen_mobs.mjs` 里
`FORTRESS` 数组与 `predicate/spawn/in_fortress.json` 的 `structures` 列表即可。

### 2.6 逐实体规则（规则的“可定义”）

规则的数据源是一张表：`src/tools/lib/entity-rules.mjs`（47 个实体 → 27 条规则签名），
生成期落盘 `doom.nats/_work/generated/entity-rules.json`（含每条规则的语义字段），
再由 `gen_mobs.mjs`（写 roster 的 `$sel.*`）与 `gen_check.mjs`（生成 `check/block` / `check/entity`）共用。

要改某个实体的规则，有两种做法：

1. 改表重建（推荐）：编辑 `lib/entity-rules.mjs`，然后
   `node src/tools/gen_mobs.mjs && node src/tools/gen_check.mjs`（或整包 `--check` 回归）。
2. 运行期改写 roster：`data merge storage doom.nats:sel {…}` 只能改“这一次尝试”；
   要持久地改某个群系/类别的物种表，改写对应 `<群系>/<类别>` 函数（它会连带写 `$sel.rule` 等字段）。

规则字段（一条规则 = 一个签名）：

| 字段 | 取值 | 语义 |
|---|---|---|
| `place` | `ground` / `any` / `water` / `water_surface` / `below_tag` / `lava` | 对应 `SpawnPlacementTypes` 的 ON_GROUND / NO_RESTRICTIONS / IN_WATER / IN_WATER+水面窗口 / ON_GROUND+专属标签 / IN_LAVA |
| `light` | `none` / `dark` / `bright` / `bat` / `slime` / `glow` / `bl8` | 逐实体光照要求（§4） |
| `tag` | vanilla 方块标签 | 下方方块（动物族） |
| `coins` | `half` / `moon` / `2of3` / `1of15` / `1of20` / `1of40` | 原版谓词里的随机否决 |
| `sky` / `noSky` | bool | 尸壳/流浪者要 `can_see_sky`；守卫者 `1/20` 或水下看不到天 |
| `notWart` | bool | 下方不是下界疣块（僵尸猪灵/猪灵/疣猪兽） |
| `deep` | bool | 溺尸 `y < seaLevel-5`（`#more_frequent_drowned_spawns` 群系改 1/15） |
| `river98` | bool | 河流群系 water_ambient 98% 不刷 |
| `d64` | bool | water_ambient 必须距玩家 ≤ 64 |
| `ySea` / `yTurtle` | bool | 发光鱿鱼 `≤ seaLevel-33` / 海龟 `< seaLevel+4` |
| `lavaToAir` | bool | 炽足兽：上方岩浆到空气 |
| `grp1` | bool | 热带鱼非群游变体 ⇒ 组内只生 1 只 |
| `cluster` | int | `getMaxSpawnClusterSize`（默认 4） |
| 尺寸（自动） | width/height | 从 `EntityType.Builder.sized(w,h)` 抽（`_work/generated/hitboxes.json`）：width>1 ⇒ 查四邻、width>2 ⇒ 查 ±2、height>2 ⇒ 查第三格（对应原版 `noCollision(getSpawnAABB)`） |
| `persist` | bool | 该物种带 `PersistenceRequired:1b` |

## 三、维度差异（本包已按维度折算）

| 维度 | 海平面 | 怪物光照档 | 天空光 | `can_see_sky` | 备注 |
|---|---|---|---|---|---|
| 主世界 | 63 | ≤ 7（采样 0..7） | 有 | 露天 true | 动物“亮” = 综合 ≥ 9 或能看到天空 |
| 下界 | 32 | ≤ 7（常量） | 无 | false | 动物“亮”退化为“方块光 ≥ 9”（与原版 `getRawBrightness(pos,0) > 8` 逐字一致） |
| 末地 | 0 | ≤ 7 | 无 | false | 同上 |

维度判定在首个非旁观玩家的位置做（`circ/detect_dim`）。
`core/tick` 由 tick 标签调用，执行上下文在世界出生点，早先直接判定会永远得到“主世界”（v4.14 修）。

## 四、光照（逐实体，v4.13 修）

| 档 | 判据 | 对应原版 |
|---|---|---|
| `none` | 不判 | 岩浆怪/恶魂/猪灵族/豹猫/炽足兽/水生族/发光鱿鱼（各有自己的规则） |
| `dark` | 综合亮度 ≤ `light.<维度>` 档 | `Monster.isDarkEnoughToSpawn` |
| `bright` | 综合亮度 ≥ 9 或能看到天空 | `Animal.isBrightEnoughToSpawn`（raw 亮度 > 8 的近似） |
| `bat` | ≤ 3（万圣节 7）+ 50% | `Bat.checkBatSpawnRules` |
| `slime` | ≤ 7 + 50% + 月相 | `Slime.checkSlimeSpawnRules` |
| `glow` | == 0 | `GlowSquid.checkGlowSquidSpawnRules` |
| `bl8` | ≤ 8 | `PatrollingMonster.checkPatrollingMonsterSpawnRules` |

已知近似：原版是“亮度 ≤ `random.nextInt(N)`”的采样比较（越低越容易过），数据包的谓词只能按档位判定。

## 五、持久化（`PersistenceRequired`）三态

| 状态 | 谁设置 | 原版行为 | 本包清理/消失层 |
|---|---|---|---|
| 默认（本包生成物） | 无 | `Mob.checkDespawn` 正常管：128 格硬消失 + `noActionTime>600` 后每 tick 1/800 掷骰 | `debug/clear` / 自带消失层都会处理 |
| 带 `doom.nats.persistent` 标签 | 作者/地图（`tag @e add …`） | 不认（这就是本包自己的标签，生物仍是普通生物 ⇒ 照样消失） | 清理与消失层跳过它 |
| 带 `PersistenceRequired:1b` | 逐规则 `persist: true`，或全局 `$cfg.persist=1` | `checkDespawn` 直接返回 ⇒ 永不消失 | 清理与消失层跳过它 |

```mcfunction
# 例：让某只生物永远留下（原版语义）
data merge entity @e[type=zombie,limit=1] {PersistenceRequired:1b}
# 例：只让本包的清理/消失层放过它（原版仍会让它消失）
tag @e[type=zombie,limit=1] add doom.nats.persistent
```

> 参考：原版里会让生物“自然持久”的路径有：命名牌（`NameTagItem`）、结构生成（海底废墟/沼泽小屋/林地府邸）、
> 骑乘（`requiresCustomPersistence = isPassenger()`）、`setItemSlotAndDropWhenKilled`（带装备必掉落的怪）等。
> 本包不主动添加这些（保持“普通生物”语义）。

## 六、配方（常见场景）

```mcfunction
# ① 自定义地图：固定高度带 + 高密度 + 怪物不消失
data merge storage doom.nats:config {band:{mode:1,yMin:70,yMax:96}, batch:120, maxBatch:200, persist:1}
function doom.nats:cfg/apply

# ② 生存直用（已默认）：关原版自然生成 + 原版语义参数
function doom.nats:mode/survival

# ③ 性能保守（mspt 敏感：把 batch 压回个位数、节拍放慢）
data merge storage doom.nats:config {batch:4, period:10, maxBatch:20, density:0}
function doom.nats:cfg/apply

# ④ 只在下界提高怪物上限（维度键写进覆盖层后，切维度时自动生效）
```

## v4.19 新增：取点回退（深水 / 浮空时按原版整列均匀取 y）

| 键 | 默认 | 说明 |
|---|---|---|
| `band.fallback` | `1` | 模式 0「自动扫地面」扫不到地面时，是否回退成原版式整列均匀取点。`0` = 旧行为（贴玩家层） |
| `floorY.overworld` / `.the_nether` / `.the_end` | `-64` / `0` / `0` | 回退区间下界（= 原版 `Level.getMinY`）。回退区间 = `[floorY, 玩家层+2]` |

背景：原版 `NaturalSpawner.getRandomPosWithin` 的 y 在 `[minY, 地表高度+1]` 整列均匀随机。
玩家浮在深海上方时，水下十几格照样是候选点。本包模式 0 只在「玩家层 +2 .. -16」扫地面；深水上方这段窗口里
没有任何可站立层 ⇒ 候选点被钉在玩家那一层 ⇒ 溺尸的 `isDeepEnoughToSpawn`（`y < seaLevel-5`）永远不过，
水面窗口（place 3）又要求上方也是水 ⇒ 深水零生成（溺尸、鱼、鱿鱼都没有）。
回退只在「模式 0 ∧ 扫不到 ∧ `fallback=1`」时触发；陆地上扫得到地面 ⇒ 行为完全不变。
回退点有一部分会落在石头里被 `check/block` 拒掉，与原版“抽了才知道”同构。

```mcfunction
# 关掉回退（恢复旧行为）
data merge storage doom.nats:config {band:{fallback:0}}
function doom.nats:cfg/apply
# 改下界（例如地图把主世界底部设得更低）
data merge storage doom.nats:config {floorY:{overworld:-128}}
function doom.nats:cfg/apply
```

## 附：运行时刻改（v4.24）：「不等重生成，改 storage 即刻生效」

本章前面几节都是构建期/装载期旋钮（`$cfg.*` 由 `cfg/apply` 折算，装载时生效）。
v4.24 把「可自定义」又往前推了一层：运行时刻改 storage，判定当场读，不用重新生成包、不用重装、不用重启。

### 一、两条通路，互不冲突

| | 构建期（v4.23） | 运行时刻（v4.24） |
|---|---|---|
| 入口 | `rules/entity-rules.json` · `entries.json` · `counts.json` | `storage doom.nats:author`（形状与三个 JSON 同构） |
| 生效方式 | 改文件 → 跑生成器 → 重装/`/reload` | 改 storage，下一条判定就是新值（不必 `/reload`；`function doom.nats:author/load` 只是刷新摘要缓存） |
| 上限 | 无（生成期展开） | 条目 ≤8 · Y 段 ≤8 · 落位面标签 ≤8 · 群系名单各 ≤4（运行期槽位是固定的） |
| 命令面 | 无（改文件） | `author/{help,show,load,reset,export,demo,add_entry,add_below_tag,set_group_by_y,set_cap_y}` |

> 三层身份：① 原版复刻（默认，`rules/` 空 + storage 空 ⇒ 逐条与原版一致）
> ② 本包扩展（稳定）：上面这张表的全部能力
> ③ 实验性（非原版）：`near` 关系条件 / `on_spawn` 演出钩子 / `preset` 预设，只在实验性变体 `v4x` 里，
> 产物落在 `doom.nats:exp/*`（函数）、`doom.nats.exp.*`（实体标签）、`doom.nats:exp`（storage）。

### 二、逐字段清单

与 `rules/README.md` §7 同一张表（那里是主手册）：

- `entityRules.<实体 id>`：`belowAny`(≤8) `yMin` `yMax` `lightMin` `lightMax` `weather` `biomeIn`(≤4) `biomeNot`(≤4) `place` `light` `persist`
- `entries[]`（≤8）：`id` `mob` `biome` `category` `weight` `min` `max` `nbt` `when{thundering,raining,yMin,yMax,lightMin,lightMax}`
  ⚠ `weight` 的命中率 ≈ `weight / 1000000`，不是“与香草同池按比例”。要生效就填 10 万级，`40` 这种数字等于不刷。
  多条同时存在时看总和：Σweight 建议 ≤ `1000000`，否则靠后的条目永不命中（各条按声明顺序依次吃 `0..999999` 的区间；
  例：4 条各 `900000` 只有第 1 条活着，应改成各 `200000`）。对照表见 [`wiki/规则字段参考.md`](wiki/规则字段参考.md)
- `counts.groupByY.<实体 id>[]`（≤8 段）：`{yMin?,yMax?,min,max}`（后面的段覆盖前面的段）
- `counts.capByY.<类别>[]`（≤8 段）：`{yMin?,yMax?,max?,localMax?}`

否决时的 reason 码与构建期/原版一致：落位面 ⇒ `3`（光照）/`4`（方块），其余规则 ⇒ `9`，容量 ⇒ `5`。

### 三、实验性变体与两道开关

1. 引擎门（整包级）：实验性变体 `dist/doom.nats-v4x-experimental-v4.30.0.zip`（解压出的 `doom.nats/`）的 `pack.mcmeta` 声明
   `"features": {"enabled": ["minecraft:minecart_improvements"]}`（1.21.6 没有“自定义数据包”旗标，
   只能借一个原生实验性旗标；代价是开它的世界同时拿到 vanilla 的矿车改动）。
   世界没开该实验性玩法时：客户端的包列表里它是不兼容/不可选的，服务端 `/datapack enable` 会明确拒绝：
   `Pack 'file/doom.nats' cannot be enabled, since required flags are not enabled in this world: minecraft:minecart_improvements!`
   （真机日志；注意 `/reload` 会绕过这道门，正式发货请以“世界装载态”为准。）
