# 16 · 生存直用手册（v4.12）
English: `docs/16-生存直用手册.en.md`


> ⚠ 本文是 v4.12 快照，未随线更新；现状见 [CHANGELOG](../CHANGELOG.md) 与 [docs/24-玩家能改动的一切.md](24-玩家能改动的一切.md)。
> 下文「没做（缺口）」表里的「结构刷怪优先」与「`finalizeSpawn` 族群数据」两条早已实现（结构的 `spawn_overrides`、组数据层，见 [docs/19](19-finalizeSpawn与组数据.md)）；其余「与原版的差距」条目以 CHANGELOG 为准。

> 回答用户的问题：「其实我觉得可以是直接当做生存数据包那种使用了？你觉得呢？」
> 结论：可以，而且已经做到「装上就接管」。唯一必须自动做掉的事（关原版自然生成）已内置；
> 想自己管就一句话退场。下面是装配步骤、开关清单、实测数字，以及与原版到底还差什么。

---

## 一、三步装上

| 步 | 动作 | 说明 |
|---|---|---|
| ① | 把 `dist/doom.nats-v4.32.0.zip` 解压出的 `doom.nats/` 放进 `<存档>/datapacks/`（服务器放 `world/datapacks/`） | 自动化装包的 `src/tools/install.mjs`（要本机存档 / 服务器） |
| ② | 进世界后 `/reload` | 新放进世界目录的包不必退出重进（源码依据：`ReloadCommand.discoverNewPacks` → `PackRepository.reload()`） |
| ③ | 看聊天栏 / 服务器日志出现 `[nats] mode/survival —— 已接管自然生成（doMobSpawning=false）` | 出现即就位；没出现看 `logs/latest.log` 的加载报错 |

为什么第①步里「关原版」不用你操心：本包用 `summon` 造生物，`doMobSpawning` 管不到它。
原版自然生成若还开着，等于刷两份，分布、容量、性能都会失控。
所以 `core/setup`（装载 tag）会直接执行 `mode/survival`，把 `doMobSpawning` 关掉。
只关「自然生成」，刷怪笼 / 结构生成 / 繁殖 / 指令召唤 / 刷怪蛋都不受影响。

## 二、开关与命令（全部可写在聊天栏，也可由命令方块/地图调用）

| 命令 | 作用 |
|---|---|
| `function doom.nats:mode/survival` | 生存直用：`gamerule doMobSpawning false` + 立刻出一份环境快照（装载时默认执行） |
| `function doom.nats:mode/manual` | 以后装载不再自动改 gamerule（交给你/地图自己管；开关状态存在计分板，`/reload` 与重进世界都保留） |
| `function doom.nats:mode/auto` | 恢复默认（装载时自动接管） |
| `function doom.nats:mode/off` | 退场：静默清掉本包生物 + `gamerule doMobSpawning true` |
| `function doom.nats:debug/clear` | 只清场（静默移除，走 `util/void_kill`，没有掉落也不给经验） |
| `function doom.nats:debug/density` | 看密度控制现状：目标/分钟、上一分钟实际、`$eff.batch`、情形节拍、当前 cap |
| `function doom.nats:debug/env` | 环境快照：人数 / 已加载区块 / 天气 / 阶段 / 维度 |
| `function doom.nats:debug/reject_report` | 归因直方图（reason 0..9）+ 光照失败档位，打印后清零 |
| `function doom.nats:debug/mobs` | 生物注册表与簇上限一览 |
| `tag @e[type=zombie,limit=1] add doom.nats.persistent` | 把某只生物标记为「持久」⇒ `debug/clear` 不会清它 |

调密度：默认 `$eff.batch = 6`（每拍原点数），情形引擎按雨/雷暴/夜/维度/人数/月相自动改节拍与上限。
要闭环控制就设目标：

```
scoreboard players set $density doom.nats 200     # 目标 200 只/分钟，0 = 关（默认）
scoreboard players set $ctrl.maxBatch doom.nats 200
```

低于目标就加批、超出 25% 就按比例收缩（AIMD），测量源是 `$spawned.total`，累积值，永不被清零。

## 三、真机验证（2026-09-28，常驻测试服 + RCON）

脚本 `_work/verify_mode.mjs`（已并入一键回归 `regress.mjs --reuse` 的一步），9 PASS / 0 FAIL：

| 断言 | 结果 |
|---|---|
| 基线：手动 `gamerule doMobSpawning true` | ✅ true |
| `/reload` 无加载报错 | ✅ 未见 `Failed to load` |
| `reload` 后自动接管 | ✅ `doMobSpawning=false`，日志有 `mode/survival` |
| `mode/off` 后把自然生成还给原版 | ✅ `true` |
| `mode/off` 顺带静默清场 | ✅ 清理 95 只，掉落物 0 |
| `mode/manual` 后再 `/reload` | ✅ 保持 true（自动接管真的被挡住） |
| `mode/auto` 恢复 | ✅ `false` |

「清理无掉落」这条是有物证的：此前用 `kill @e[tag=doom.nats.spawned]` 清场，地上留下了 476 个掉落物；
改用 `util/void_kill`（`tp @s ~ ~-500 ~`，与原作 `recovered/doom.nats` 一致）后，清场新增掉落物 0。

## 四、性能与容量（本机实测）

| 指标 | 实测 |
|---|---|
| 稳态怪物数 | 71.7（cap 70，峰值 77），容量链真的在管 |
| mspt | 均值 5.29 / 峰值 5.70（预算 50） |
| 全清后回满 | 2 秒内 70 → 26，约 6 秒回到 70 |
| 吞吐上限来源 | 不是性能，是原版 `maxCommandChainLength`（默认 65536 ≈ 10 次尝试/tick） |
| 抬到 1,000,000 后 | batch 40 → 9.7 ms；160 → 24.1 ms；400 → 50.9 ms（超预算） |

建议：mspt 想守在 30 ms 以内 ⇒ 本机 `$eff.batch` 不超过 200。
自定义地图要更高密度，优先抬 `maxCommandChainLength` 再抬 batch，别把帧预算吃光。

## 五、与原版的差距（诚实清单，别当成「完全一致」）

来自 `docs/14` 的机制覆盖表，按生存实际影响重排：

### 已经做到源码级一板一眼的

| 环节 | 说明 |
|---|---|
| 全局 mobcap | `maxInstancesPerChunk × spawnableChunkCount / 289`，整数除法、严格小于（`spawnableChunkCount` 是实测的 17×17 已加载并集，不是估算） |
| 每玩家 cap | 用 `maxInstancesPerChunk` 本身，OR 语义 |
| 簇（cluster）模型 | 每次尝试最多 3 组；组起点每组重置、组内走位 `nextInt(6)-nextInt(6)` 累加；物种每组只挑一次；`groupSize = minCount + rand(1+max-min)`；`spawned ≥ getMaxSpawnClusterSize()` ⇒ 结束整次尝试（默认 4，只有 8 个实体类覆写） |
| 消失 | 硬消失 128 格（水生 64）+ 概率消失（分母放大到 1/40 / 20 tick，等价原版 1/800 每 tick）；走 `void_kill` 的 discard 语义 |
| 群系刷怪表 | 65 群系 769 行，与 vanilla `WeightedRandom` 逐点等价 |
| 逐实体落位 | 规则 0..4：通用 / 水面水生 / 深水 / 蝙蝠（低于地表 + 亮度 + 50%） / 史莱姆（50<y<70 + 月相 + 亮度） |
| 情形引擎 | 雨 / 雷暴 / 夜晚 / 维度 / 人数 / 月相 → 节拍与上限 |

### 近似（能用，但别拿它跟原版逐格对）

| 环节 | 差距 |
|---|---|
| 光照 | 只能 5 档区间近似（谓词读不到亮度数值），原版是 `uniform(0..7)` 采样比较 |
| 玩家禁区 | 原版 24 格，本包 27 格下限近似 |
| 多玩家区块并集 | 单人精确；多人用两种方形近似（欧氏距离表达式在数据包里写不出来） |
| 碰撞盒 | 用方块标签近似，不是真 AABB |
| `spawn cost` | 化简为 `Σ(1/r) ≤ budget/q²`，4 桶近似；只对 `warped_forest` / `soul_sand_valley` 适用（原版也只有这两处非空） |
| 取点 y | 读不到 heightmap ⇒ 跟随玩家 ± jitter 或地图声明的固定带 |

### 没做（缺口，写在这里而不是假装等同）

| 环节 | 影响 |
|---|---|
| 结构刷怪优先 | 下界要塞等固定表不生效 |
| `finalizeSpawn` 族群数据 | 僵尸骑鸡、羊的颜色随群系等不生效 |
| 史莱姆区块（y<40 那条规则） | 只在 50<y<70 按原版规则刷；40 以下不刷（数据包算不出区块级 RNG，除非地图作者预先声明） |
| 区域高度带 | `pos/band` 仍是占位实现（`storage doom.nats:bands` 尚未接线），自定义地图作者需先声明 |

> 一句话：当生存玩没问题；要「逐格等同原版」需要 mod 层接管 `NaturalSpawner`，数据包到不了。

## 六、卸载 / 回滚

```
function doom.nats:mode/off      # 清场 + 把自然生成还给原版
```
然后删掉 `datapacks/doom.nats`，`/reload`。
注意：已经生成的生物不会因为你删包而消失（它们就是普通生物），需要的话先 `debug/clear`；
`doom.nats:mode/off` 已经把这一步做掉了。

---

## 七、自定义地图作者还要做的两件事

1. 声明高度带：设 `$band.mode = 1`，并把 `$band.yMin / $band.yMax`（同时写 `storage doom.nats:band`）改成地图的实际生成带。
2. 校准方块标签：`node src/tools/propose_tags.mjs` 直接读地图的 Anvil 区域文件，产出 `#doom.nats:standable` / `#spawnable_at` 的覆盖提案。
   参考：测试地形（积雪）地表 40% 是冰族方块，补进标签后覆盖率 3.7% → 43.9%，`spawnable_at` 100%，可采纳建议清零。

## 八、v4.14 变化（生存相关的三处）

| 变化 | 说明 | 对生存的影响 |
|---|---|---|
| 动物终于会刷了 | 之前所有物种共用"暗 ≤ 7"的光照档，而动物又要求"亮 ≥ 9" ⇒ 互相矛盾、永不刷出 | 白天（或夜里露天）能看到羊/牛/猪/鸡等；`snowy_beach` 这类没有 creature 列表的群系仍然不刷（与原版一致） |
| 维度参数按维度取 | 海平面 63/32/0、光照档按维度；维度在首个玩家位置探测 | 进下界/末地后刷怪参数自动跟随（之前会一直用主世界参数） |
| 一切都是可配置的 | `storage doom.nats:config` 覆盖海平面/光照/容量/距离/节拍/密度/消失/持久化/高度带 | 想改强度、想让怪留着、想固定高度带，都不必改包：`data merge storage …` + `function doom.nats:cfg/apply`（见 `docs/18-配置手册.md`） |

还有两条与生存直接相关：

- 消失：本包生成的是普通生物，原版自己的消失逻辑（128 格 / 1 分钟后 1/800）本来就在管；
  我们自带的掷骰层默认关闭（`dice:0`），不再让消失比原版更快。
- 持久化：`tag @e add doom.nats.persistent` 只影响本包的清理与消失层（让怪活下来）；
  要让原版也不消失，得用 `PersistenceRequired:1b`（或把 `persist` 配成 1）。
