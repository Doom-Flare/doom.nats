# 已知限制
English: `docs/wiki/已知限制.en.md`

先说三件明确做不到的事，免得你白试：

| 想做 | 为什么做不到 |
|---|---|
| 全新的模型 / 贴图 / AI / 寻路 | 数据包管不了客户端资源，也管不了实体的行为逻辑。想加自定义生物外观，只能用“真实体当内核 + 骨架当外观”的桥接（实验性变体）；AI 与寻路改不了。 |
| 给“原本没有这一类别的群系”加怪 | 群系 → 物种表是世界生成层的数据，要改世界生成（`worldgen` 覆盖），不是运行时刻规则能办的。 |
| 让生物之间产生因果关系（例如“蜘蛛吃虫”） | 那是实体行为层（Goal / Brain）的事，数据包没有这个接口。 |

> 一句话：本包能改的只有判定与数量（在哪刷、什么时候刷、刷多少、长什么样）。客户端资源、实体行为、世界生成结构，都改不了。

## 一、近似（能用，但别拿它跟原版逐格对）

| 环节 | 差距 |
|---|---|
| 光照 | 谓词读不到亮度数值，只能按 5 档区间近似；原版是 `uniform(0..7)` 采样比较 |
| 玩家禁区 | 原版 24 格，本包用 27 格下限近似 |
| 多玩家区块并集 | 单人精确；多人用两种方形近似（欧氏距离表达式写不出来） |
| 碰撞盒 | 用方块标签近似，不是真 AABB |
| `spawn cost` | 化简为 `Σ(1/r) ≤ budget/q²`，4 桶近似 |
| 取点高度 | 读不到 heightmap ⇒ 跟随玩家 ± jitter，或按地图声明的固定带 |
| 消失 | 读不到 `noActionTime`，没法完全复刻“离开 32 格满 600 tick 才开始掷骰”，消失略快（掷骰分母已按节拍放大，以保持单位时间期望） |

## 二、没做 / 缺口

| 环节 | 影响 |
|---|---|
| 史莱姆区块（y < 40 那条规则） | 只在 50 < y < 70 按原版规则刷；40 以下不刷。数据包算不出区块级 RNG，除非地图作者预先声明 |
| 万圣节南瓜 | 读系统日历，数据包没有接口 |
| 区域难度 / 真实难度 | 数据包读不到，只能用配置声明（`difficulty` / `special`），会与真实难度不同步 |
| 世界出生点 24 格 | 读不到 `getSharedSpawnPos()`，默认关闭，需要作者声明坐标 |
| Brain 记忆 / 学校鱼 leader / 狐狸目标列表 | 记忆项可用 NBT 写，但传感器记忆每 tick 重算，对象引用与 Goal 列表不是数据 |
| 区块生成期被动生物是否被 `doMobSpawning` 管到 | 没做假设，也没验证 |
| 按结构限刷（“只在末地城 / 要塞里刷”） | author 层没有 structure 字段；成品里也没有 `in_end_city` 谓词（构建期硬编码的结构只有要塞 / 前哨站 / 沼泽小屋 / 海底神殿 / 远古城市 / 试炼密室）⇒ 只能改用群系表达（例：末地外岛 = `end_highlands`/`end_midlands`/`end_barrens`/`small_end_islands` 共 4 条） |
| 条目路径的物种原版规则 | 运行时刻的条目不装载被选物种的 `place`/`light`/`rule`/`tall`，会沿用上一次香草抽取的残留值 ⇒ `$sel.rule` / `$sel.tall` 可能不是你写的数。`entityRules` 只能钉 `place`/`light`，`rule`/`tall` 没有对应字段、运行时刻改不了。残留多数时候惰性无害（实测幽灵窗口无 override 时是 `rule=12` / `tall=1`，即末影人残值，而 `rule 12` 在 `check/entity` 全 38 行里无任何匹配）；但 `$sel.rule` 若被落点香草表留成 `11`（溺尸，要求脚下是水）或 `28`（史莱姆），会无声拒掉你的目标怪，归因里只看到 `reason=9`。换群系 / 换维度后最容易撞上 ⇒ 排查见 [[FAQ]] |
| `weight` 的“同池竞争” | 不成立：实测命中率 ≈ `weight / 1000000`（源码注释写的“与香草同池按比例”与实际不符）⇒ 要生效就填 10 万级。机制见 [[规则字段参考]] |
| `weight` 的总和天花板 | 各条按声明顺序依次吃 `0..999999` 的区间 ⇒ Σweight 建议 ≤ `1000000`；超了靠后的条目永不命中（源码级论证；`4 × 200000` 有实测旁证）。例：4 条各 `900000`（Σ3,600,000）实际只有第 1 条活着。见 [[规则字段参考]] |

## 三、能力边界（写在明面上）

当生存数据包玩没问题；要“逐格等同原版”，需要 mod 层接管 `NaturalSpawner`。数据包到不了那个精度。

同理，运行时刻能改的规则有硬上限（条目 8 条 / Y 段 8 段 / 落位面标签 8 个 / 群系列表各 4 条），也改不了决定函数体形状的源码级开关（`coins` / `cluster` / `deep` / `sky` 等），那些要动构建期规则层。

## 四、遇到偏差怎么办

1. 先跑 `/function doom.nats:debug/reject_report` 看归因（见 [[FAQ]]）
2. 对照本页确认是不是“已知近似”
3. 是 bug 就带上完整上下文（版本号 / 维度 / 归因直方图 / `debug/env` 输出）反馈到 [Issues](https://github.com/DoomDecapitator/doom.nats/issues)
