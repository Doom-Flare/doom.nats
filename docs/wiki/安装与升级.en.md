# Installation and Upgrade

中文: `docs/wiki/安装与升级.md`

Unzip, put `doom.nats/` into the save's `datapacks/`, run `/reload`. Upgrading means replacing that folder and running `/reload` again. The save and the mobs already spawned are unaffected.

## Installation

1. Unzip `dist/doom.nats-v4.30.0.zip` to get a `doom.nats/` folder
2. Put the whole folder into `<save>/datapacks/`. On a server put it in `world/datapacks/`
3. Go into the world and run `/reload`

A pack you just placed into the world directory does not require quitting and re-entering.

The final structure looks like this:

```
saves/<save>/datapacks/
└── doom.nats/            ← pack.mcmeta is at this level
    ├── pack.mcmeta
    ├── data/
    └── ...
```

Once installed, chat and the server log will print one line:

```
[nats] mode/survival —— 已接管自然生成（doMobSpawning=false）
```

If you do not see it, look in `logs/latest.log` for load errors.

## Why It Automatically Turns Off Vanilla Spawning

This pack creates mobs with `/summon`, and vanilla's spawning rules do not cover `/summon`. If vanilla natural spawning stayed on, that would be spawning twice over, and the distribution, caps, and performance would all run away. So on load it automatically runs `mode/survival` once, setting `gamerule doMobSpawning` to `false`.

Only natural spawning is turned off. Spawners, structure generation, breeding, command summoning, and spawn eggs are all unaffected.

To manage it yourself, run these:

```
/function doom.nats:mode/manual     # from now on loading no longer changes the gamerule automatically (the state lives on a scoreboard, survives reload/re-entry)
/function doom.nats:mode/auto       # back to the default: take over automatically on load
/function doom.nats:mode/off        # exit: silently clears this pack's mobs + gives natural spawning back to vanilla
```

## Verifying It Is Installed

```
/reload
/function doom.nats:debug/env       # environment snapshot: player count / loaded chunks / weather / phase / dimension
/function doom.nats:debug/all       # full diagnostics: environment → registries → trial run → rejection histogram → despawn report
```

Stand still at night and wait two minutes, then run `debug/reject_report` again; you will see the distribution of rejection reasons (`reason=0..11`) and the success count:

```
[nats.reject] rej: 0=<no valid chunk drawn> 1=<player within 24> 2=<beyond 128> 3=<light tier> 4=<landing block> 5=<global capacity> 6=<local capacity> 7=<spawn cost> spawned=<successes>
```

## Upgrading

1. Delete the old `datapacks/doom.nats/`
2. Put the `doom.nats/` unzipped from the new zip in. Do not stack two versions together
3. `/reload`

> Mobs that have already spawned will not vanish or change shape because you swapped the pack; they are just ordinary mobs.
> Custom rules are written in the `doom.nats:author` storage (see [[快速上手-在游戏里改规则]]), and swapping the pack keeps them with the save. But if a new version changed field semantics, double-check against [[规则字段参考]].

## Uninstalling and Rolling Back

```
/function doom.nats:mode/off     # clear the field + give natural spawning back to vanilla
```

Then delete `datapacks/doom.nats` and run `/reload` again.

> To make the pack's mobs disappear as well, you must run `mode/off` first. It has a built-in silent cleanup, with no drops and no experience. If you just delete the folder, they will stay in the world as ordinary mobs.

## Caveats

- In singleplayer, do not open the pause menu and do not let the window lose focus. Pausing in singleplayer stops the tick, and spawning stops with it.
- A dedicated server's `pause-when-empty-seconds` defaults to stopping the tick after 60 seconds, and with nobody there it likewise does not spawn.
- Supports Minecraft 1.21.5 to 26.3, split into five builds by version range: use `-mc1.21.5` for 1.21.5, `-mc1.21.6-1.21.8` for 1.21.6–1.21.8,
  `-mc1.21.9-1.21.10` for 1.21.9–1.21.10, `-mc1.21.11-26.2` for 1.21.11–26.2, and `-mc26.3` for 26.3.
  The baseline pack (1.21.6) is `pack_format` 80. Installing the wrong version fails to load.
- Only one variant per save. Do not install the default variant and the experimental variant at the same time.

To check download integrity, `dist/SHA256SUMS.txt` holds the sha256 of all current release artifacts, each line formatted as `<sha256>` followed by two spaces and the file name. Run this from the repository root:

```
sha256sum -c dist/SHA256SUMS.txt
```

Windows PowerShell:

```powershell
Get-Content dist/SHA256SUMS.txt | ForEach-Object {
  $h, $f = $_ -split '\s+'
  "$f => " + $(if ((Get-FileHash "dist/$f" -Algorithm SHA256).Hash.ToLower() -eq $h) {'OK'} else {'MISMATCH'})
}
```

For finer configuration (sea level, caps, cadence, height band, spawn-point 24-block exclusion) see [docs/18-配置手册.md](https://github.com/DoomDecapitator/doom.nats/blob/main/docs/18-配置手册.md).
