# 快速上手 · 在游戏里改规则
English: `docs/wiki/快速上手-在游戏里改规则.en.md`

把你的规则写进存储 `doom.nats:author`，下一拍就按新规则判定，不用重装包、不用重启、不用重新生成世界。

## 一、先记住三条管理命令

```
/function doom.nats:author/show     看现在改了什么（含实验性开关状态）
/function doom.nats:author/help     命令一览
/function doom.nats:author/reset    一键回到原版（清空全部覆盖）
```

## 二、复制就能用的三条起手式

1) 让僵尸也能刷在树叶上（原版树叶不算“能站的地方”）

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".belowAny set value ["#minecraft:leaves"]
```

2) 雷暴时，深海多刷一种僵尸（权重 10 万 ⇒ 约 10% 的尝试会选到它）

```
/data modify storage doom.nats:author entries append value {id:"storm",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:zombie",weight:100000,when:{thundering:true}}
```

> ⚠ `weight` 的真实口径是命中率 ≈ `weight / 1000000`：写 `40` 等于不刷，要明显生效请填 10 万级（`100000`≈10% · `900000`≈90%）。完整对照表见 [[规则字段参考]]。

3) 越深越挤：僵尸一组 4~6 只，地表只出 1 只

```
/data modify storage doom.nats:author counts.groupByY."minecraft:zombie" set value [{yMax:0,min:4,max:6},{yMin:1,min:1,max:1}]
```

改完跑一次 `/function doom.nats:author/show` 确认写进去了，然后站着等几十秒。

## 三、它是怎么生效的（理解这一点，你就不会写错）

- 判定是每次刷怪尝试当场读的。你写的是“什么时候允许它出现”，不是“把它调快”。
- `weight` 是“条件成立才进候选”：雷暴没开，这条根本不在候选表里，等于原版。条件成立之后，它每次被选中的概率 ≈ `weight / 1000000`（不是“和原有物种同池按比例分”）。所以要填 10 万级，写 `40` 等于不刷。详见 [[规则字段参考]]。
- 默认什么都不改时，行为与原版一致，所以任何时刻 `author/reset` 都能干净回到原版。

## 四、六个可改的维度

| 维度 | 改它用 |
|---|---|
| 落位面 | `entityRules."<实体>".belowAny`（额外算能站的方块）、`place`（地面/水里/水面/岩浆…） |
| 光照 | `light`（档位：`none`/`dark`/`bright`/`bat`/`slime`/`glow`/`bl8`）、更细的 `lightMax` / `lightMin`（0–15） |
| 高度 | `yMin` / `yMax`（闭区间）、数量曲线的 `groupByY` / `capByY` |
| 群系 | `biomeIn` / `biomeNot`（可用群系标签，如 `#minecraft:is_nether`） |
| 天气 / 时间 | `weather`（`thunder`/`rain`/`clear`）、条目里的 `when:{thundering:true,raining:true}` |
| 数量 | 条目的 `weight` / `min` / `max`，以及 `counts.groupByY`（一次几只）、`counts.capByY`（这一类总容量） |

字段取值、能填什么、硬上限，全部在 [[规则字段参考]]。

## 五、看 / 撤销 / 分享

```
/function doom.nats:author/show      当前所有覆盖
/function doom.nats:author/export    打成一行命令，能发给别人
/function doom.nats:author/reset     全部回到原版
```

## 六、注意

- 字段名分两层：条目里群系是 `biome`（单数）、组大小是 `min` / `max`；`biomes` / `group` / `cluster` / `ySea` 是构建期 `rules/*.json` 的写法，写进 storage **不报错也不生效**。
- 运行时刻做不到的：决定函数体形状的源码级开关（`coins` / `cluster` / `deep` / `sky` / `ySea` 等）、给“该群系原本没有该类别的”加怪、以及让条目走完整组数据语义。这些要么用构建期规则层，要么根本做不到（见 [[已知限制]]）。
- 按结构限刷做不到：“只在末地城 / 要塞里刷”没有对应字段（author 层没有 structure 键，成品里也没有 `in_end_city` 谓词），改用群系表达（末地外岛的 4 个群系见 [[示例库]]）。
- 条目里的 `$sel.rule` / `$sel.tall` 可能不是你写的值：条目路径不装载被选物种的原版 `place`/`light`/`rule`/`tall`，会沿用上一次香草抽取的残留值（`entityRules` 只能钉 `place`/`light`）。换群系后残留可能把怪无声拒掉（`reason=9`）。
- 硬上限（超出直接不生效）：条目 8 条 · Y 段 8 段 · 落位面标签 8 个 · 群系列表各 4 条。
- 写在 `author` 存储里的规则是跟着存档的；换包不丢，但字段语义变了要复核。
- 只想换个“手感强度”（节拍、容量、海平面、持久化）而不是改规则时，用配置层 `doom.nats:config` + `/function doom.nats:cfg/apply`，见仓库的 [docs/18-配置手册.md](https://github.com/Doom-Flare/doom.nats/blob/main/docs/18-配置手册.md)。
