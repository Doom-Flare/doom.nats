# 示例库
English: `docs/wiki/示例库.en.md`

用法：挑一条，把命令整行贴进聊天栏（需要管理员权限），再 `/function doom.nats:author/show` 确认。全部立即生效，改坏了 `/function doom.nats:author/reset` 一键还原。

> 每条都按「效果 → 命令 → 注意」写。命令一律是 `data modify storage doom.nats:author ...`。

> ⚠ `weight` 先记住一句：真实口径是命中率 ≈ `weight / 1000000`（不是“和原有物种同池按比例分”）。
> 本页示例一律按 10 万级写（≈10% 的尝试会选到它）；写 `40` 这种小数字等于不刷。
> 常用档：`10000`≈1%（稀有）· `100000`≈10%（常见）· `250000`≈25% · `500000`≈50% · `900000`≈90%（几乎独占，仅单条时可用）。
> 🔴 多条同时存在时要看总和：`weight` 是“骰值窗口长度”，不是百分比。各条按声明顺序依次吃 `0..999999` 的区间，所以 **Σweight 建议 ≤ `1000000`**，超了靠后的条目永不命中。
> 完整对照表与机制见 [[规则字段参考]] 的「⚠ `weight` 的真实口径」。

## 一、按维度刷（主世界 / 下界 / 末地）

效果：僵尸只在下界的群系里刷

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".biomeIn set value ["#minecraft:is_nether"]
```

注意：`["#minecraft:is_nether"]` 是群系标签，不用把几十个群系列出来。反过来用 `biomeNot` 排除。

效果：末地中央岛额外加一种“末影巡逻兵”（带紫色名字；要刷在外岛看下一节）

```
/data modify storage doom.nats:author entries append value {id:"end_patrol",biome:"minecraft:the_end",category:"monster",mob:"minecraft:enderman",weight:100000,min:2,max:4,nbt:"{CustomName:'{...}'}"}
```

注意：`nbt` 里放的是 JSON 字符串，引号要转义。本页末的“带 NBT 的特产”有更简单抄的写法。
注意：`minecraft:the_end` 是中央岛的群系，不是外岛。末地内岛与外岛是不同的群系，外岛要写 4 条（见下一节）。

效果：发光鱿鱼不再刷在主世界（下界 / 末地照旧）

```
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".biomeNot set value ["#minecraft:is_overworld"]
```

## 二、末地：只在外岛刷（4 个群系 · 中央岛 0）

先记一件事：末地内岛（中央岛）与外岛是不同群系。中央岛是 `minecraft:the_end`，外岛是这 4 个：

| 外岛群系 | id |
|---|---|
| 高地 | `minecraft:end_highlands` |
| 中部 | `minecraft:end_midlands` |
| 荒原 | `minecraft:end_barrens` |
| 小岛 | `minecraft:small_end_islands` |

一条 entry 只能写一个群系，所以要“任意外岛”就得写 4 条（4 条并集 = 外岛 100% 覆盖，中央岛 0）。
`#minecraft:has_structure/end_city` 不是“全部外岛”（实测只覆盖 `end_highlands` / `end_midlands`，不含 `end_barrens` / `small_end_islands`），别拿它当外岛标签。
`#minecraft:is_end` 是“整个末地”（含中央岛）。
结构条件（“只在末地城结构内”）做不到：author 层没有 structure 字段，成品里也没有 `in_end_city` 谓词。

效果：末地外岛刷烈焰人（中央岛不刷）

```
/data modify storage doom.nats:author entries set value [{"id":"blaze_highlands","mob":"minecraft:blaze","biome":"minecraft:end_highlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_midlands","mob":"minecraft:blaze","biome":"minecraft:end_midlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_barrens","mob":"minecraft:blaze","biome":"minecraft:end_barrens","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_small","mob":"minecraft:blaze","biome":"minecraft:small_end_islands","category":"monster","weight":200000,"min":1,"max":1}]
```

为什么这 4 条各写 `200000`，而不是各写 `900000`？因为区间是按声明顺序依次切的，而且看的是总和。
4 条各写 `900000`：Σweight = 3,600,000。第 1 条窗口 ≈ `[10, 900010)` 正常，第 2/3/4 条的窗口起点已经 ≥ 900010 > 999999，永远不可能命中（源码级论证；`4 × 200000` 有实测旁证，见下）。
换成 `4 × 200000`：Σweight = 800,000 ≤ 1,000,000，4 条都活着，每条在自己那个群系里 ≈20% 命中。
不是“越大越好”。这 4 条其实不会互相抢，一个候选点只会属于这 4 个群系里的 1 个。它们各自的 `weight` 只跟自己比，但总和受 `1000000` 的天花板约束。

注意：真正“互相抢”的是条件同时成立的条目。它们按声明顺序依次吃区间，靠前的先吃掉自己那一段，靠后的只剩剩下的。Σweight 一旦超过 `1000000`，靠后的直接永不命中。

### 最小可复现：从零到“看到烈焰人”

```
# ① 找一块真的外岛地面（外岛稀疏，别硬 tp —— 脚下可能是虚空，会掉下去）
/execute in minecraft:the_end run locate structure minecraft:end_city
#   回执示例：The nearest minecraft:end_city is at [-1216, ~, -256]
/execute in minecraft:the_end run forceload add -1216 -256 -1152 -192
/execute in minecraft:the_end run tp @s -1216.5 63 -255.5
/execute in minecraft:the_end run execute at @s if block ~ ~-1 ~ minecraft:end_stone   # 必须 Test passed
/function doom.nats:debug/env                                  # 期望 players≥1 chunks=289 dim=2

# ② 写上面那份 4 条 entry（各 200000 ⇒ Σweight 800000，4 条都活着）
/data modify storage doom.nats:author entries set value [{"id":"blaze_highlands","mob":"minecraft:blaze","biome":"minecraft:end_highlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_midlands","mob":"minecraft:blaze","biome":"minecraft:end_midlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_barrens","mob":"minecraft:blaze","biome":"minecraft:end_barrens","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_small","mob":"minecraft:blaze","biome":"minecraft:small_end_islands","category":"monster","weight":200000,"min":1,"max":1}]
/function doom.nats:author/show                                # 期望 entries=4

# ③ 等 2–3 分钟再数
/execute in minecraft:the_end if entity @e[type=minecraft:blaze]
```

注意：真人玩家先 `/gamemode spectator`。非旁观玩家会抢“锚点玩家”（`pos/pick` 用 `@a[gamemode=!spectator]`），把一半尝试分到主世界去。
实测参考（v4.28 真机）：单条 `weight=900000` ⇒ 180 秒内 `$spawned` +99，场上烈焰人 0 → 32；同一套规则下 `weight=90` 是 90 秒 0 只。（`900000` 只在单条时安全；多条必须看 Σweight ≤ `1000000`。）

四格矩阵实测（v4.28 系装机副本 · 真机计数，8/8 符合期望）。这是“群系门真的在起作用”的证据，不是概率抖动：

| 配方 | 中央岛 `the_end`（峰值 / 终值） | 外岛 4 群系（峰值 / 终值） | `$rej.9` Δ |
|---|---|---|---|
| `blaze @ the_end` ×1，w=`900000` | 51 / 28 ✅ | 0 / 0 | 0 |
| `blaze @` 外岛 ×4，各 w=`200000` | 0 / 0 | 22 / 22 ✅ | 0 |
| `zombie @ the_end` ×1，w=`900000` | 56 / 56 ✅ | 0 / 0 | 0 |
| `zombie @` 外岛 ×4，各 w=`200000` | 0 / 0 | 22 / 22 ✅ | 0 |

- 只换位置、不换规则：中央岛规则拿到外岛 ⇒ 0；外岛规则拿到中央岛 ⇒ 0（反向格全 0）。
- 两怪（`blaze` / `zombie`）零 override 就能刷，不需要额外用 `entityRules` 去钉 `place` / `light`。
- 8 个窗口的 `$rej.9`（物种否决策）恒 0，所以没有“刷得出来、却被规则无声拒掉”的暗亏。
- 同时段末地怪物总数（含原版末影人）一直有 70~103，说明末地本身在正常刷怪。目标怪为 0 是群系门造成的，不是容量或节拍。

## 三、落位面（原版根本站不住的地方）

效果：僵尸刷在树叶上（树冠层生态）

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".belowAny set value ["#minecraft:leaves"]
```

效果：极地：浮冰 / 蓝冰上也刷北极熊

```
/data modify storage doom.nats:author entityRules."minecraft:polar_bear".belowAny set value ["minecraft:blue_ice","minecraft:packed_ice"]
```

效果：下界：岩浆块与黑曜石上也刷僵尸猪灵

```
/data modify storage doom.nats:author entityRules."minecraft:zombified_piglin".belowAny set value ["minecraft:magma_block","minecraft:obsidian"]
```

效果：发光鱿鱼上陆地（“修 bug”就是这么修的）

```
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".place set value "ground"
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".light set value "dark"
```

注意：一条命令只改一个键。`belowAny` 是追加“能站的地方”，不是替换原版能站的所有方块。`belowAny` 里写的是方块标签（`#minecraft:leaves`）或具体方块 id（`minecraft:oak_leaves`）；`minecraft:leaves` 是标签名、不是方块 id，漏了 `#` 这条就不生效。
注意：发光鱿鱼还差一道深度门（原版 y ≤ 海平面-33，规则级开关），运行时刻去不掉。上面两条能让它落位/光照变陆生，但要真在陆地上刷出来，得构建期改 `rules/`（`"ySea": null`）。

## 四、光照（地下专属 / 白天限定）

效果：流浪者（stray）只刷在亮度 ≤ 3 的地方，地下洞窟专属

```
/data modify storage doom.nats:author entityRules."minecraft:stray".lightMax set value 3
```

效果：羊只刷在亮度 ≥ 9 的地方，白天草原动物

```
/data modify storage doom.nats:author entityRules."minecraft:sheep".lightMin set value 9
```

注意：光照是近似的（游戏里只有 5 档区间能判），别拿它跟原版逐格对。连续数值做不到（见 [[已知限制]]）。

## 五、高度

效果：山羊只刷在 Y 120 以上（高原 / 山地专用）

```
/data modify storage doom.nats:author entityRules."minecraft:goat".yMin set value 120
```

效果：蠹虫只刷在 Y 10 以下（深洞专属）

```
/data modify storage doom.nats:author entityRules."minecraft:silverfish".yMax set value 10
```

注意：`yMin` / `yMax` 是闭区间，可以只写一个。

## 六、天气 / 情形

效果：雷暴 + 深海 + 海面以下，才刷带三叉戟的溺尸

```
/data modify storage doom.nats:author entries append value {id:"storm_drowned",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:drowned",weight:100000,when:{thundering:true,yMax:40},nbt:"{equipment:{mainhand:{id:\"minecraft:trident\",count:1}}}"}
```

注意：这条示例带装备 NBT。1.21.5+ 装备字段已改名（`HandItems` → `equipment`），**旧写法会被静默丢弃**（不报错，但实体上什么都没有）。完整说明与可直接抄的示例见本页第八节。

效果：下雨才出现的史莱姆（沼泽）

```
/data modify storage doom.nats:author entries append value {id:"rain_slime",biome:"#minecraft:is_swamp",category:"monster",mob:"minecraft:slime",weight:100000,when:{raining:true}}
```

注意：`when` 里的多个条件是 AND。条件不成立时，这条根本不进候选池，所以它不会挤掉原版物种。条件成立后，每次被选中的概率 ≈ `weight / 1000000`（见本页开头）。

## 七、数量与规模

效果：越深越挤：僵尸一组 4~6 只，地表只出 1 只

```
/data modify storage doom.nats:author counts.groupByY."minecraft:zombie" set value [{yMax:0,min:4,max:6},{yMin:1,min:1,max:1}]
```

效果：地下的怪物总容量翻倍（全局 200 / 每人 140），地表维持原样

```
/data modify storage doom.nats:author counts.capByY.monster set value [{yMax:0,max:200,localMax:140},{yMin:1,max:70,localMax:70}]
```

效果：一次多出几只（“蝗灾”感）：蜘蛛一次 4 只
（运行时刻改不了“簇上限”：原版多数生物 = 4；`cluster` 是构建期字段，见 [[规则字段参考]]）

```
/data modify storage doom.nats:author counts.groupByY."minecraft:spider" set value [{min:4,max:4}]
```

注意：Y 段最多 8 段。容量是上限，实际到不到得了还看区块数与玩家数。

## 八、带 NBT 的“特产”（装备 / 名字 / 药水 / 乘客）

效果：同一个僵尸，两种地域变体（沙漠穿皮革头、雪原照旧）

```
/data modify storage doom.nats:author entries append value {id:"desert_zombie",biome:"minecraft:desert",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{equipment:{head:{id:\"minecraft:leather_helmet\",count:1}}}"}
```

效果：骑着鸡、静音、无重力（“漂着的鸡骑士”，只在雷暴的森林）

```
/data modify storage doom.nats:author entries append value {id:"ghost_rider",biome:"#minecraft:is_forest",category:"monster",mob:"minecraft:zombie",weight:50000,when:{thundering:true},nbt:"{Silent:1b,NoGravity:1b,Passengers:[{id:\"minecraft:chicken\"}]}"}
```

效果：出生就带永久速度效果

```
/data modify storage doom.nats:author entries append value {id:"swift_zombie",biome:"minecraft:plains",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{active_effects:[{id:\"minecraft:speed\",amplifier:1b,duration:-1,show_particles:1b}]}"}
```

效果：下界刷合金僵尸：全套合金，死了还不掉装备

```
/data modify storage doom.nats:author entries append value {id:"nether_royal_zombie",biome:"#minecraft:is_nether",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{equipment:{mainhand:{id:\"minecraft:netherite_sword\",count:1},head:{id:\"minecraft:netherite_helmet\",count:1},chest:{id:\"minecraft:netherite_chestplate\",count:1},legs:{id:\"minecraft:netherite_leggings\",count:1},feet:{id:\"minecraft:netherite_boots\",count:1}},drop_chances:{mainhand:0.0f,head:0.0f,chest:0.0f,legs:0.0f,feet:0.0f}}"}
```

注意：装备 NBT 的三个坑（1.21.5+ 起）

1. 旧字段已被移除：`HandItems` / `ArmorItems` / `HandDropChances` / `ArmorDropChances` 在 1.21.5+ 不再存在，现在写 `equipment:{…}`（装备）和 `drop_chances:{…}`（装备掉落率）。
   🔴 旧写法**不报错**：命令照样回 `Modified entity data`，实体上却什么都没有（静默失效，真机实测）。
2. `drop_chances` 是实体级的：它和 `equipment` 平级，都是实体 NBT 的顶层键。塞进 `equipment` 里面同样被静默丢弃。
   槽位名两边一致：`mainhand` `offhand` `head` `chest` `legs` `feet`（马 / 狼的护甲是 `body`）。掉率写 `0.0f` = 必不掉。
3. `nbt` 的值是 SNBT 字符串，不是裸复合：整行命令里内层引号必须写成 `\"`（漏了整条命令直接废）。物品栈的新写法是 `{id:"minecraft:…",count:1}`，旧的 `Count:1b` 已改成小写 `count`；`Health:40f` 这类 CamelCase 字段没变，不用动。

> 实测回执：上面那条合金僵尸落地后，实体上是 `equipment = {mainhand:{count:1,id:"minecraft:netherite_sword"}, head:{…netherite_helmet}, chest:{…netherite_chestplate}, legs:{…netherite_leggings}, feet:{…netherite_boots}}`，一次测试里 22 只僵尸全部带上了全套合金。
> 字段总表见 [[规则字段参考]]；构建期 `rules/entries.json` 的同类坑见 `src/rules/README.md` §7.5 坑 5。

## 九、看 / 撤销 / 分享

```
/function doom.nats:author/show      当前所有覆盖
```

## 十、实验性专属（世界需开启对应实验性玩法）

效果：附近有狼才刷羊（“狼群附近”的生态感）

```
/data modify storage doom.nats:author entries append value {id:"wolf_sheep",biome:"#minecraft:is_forest",category:"creature",mob:"minecraft:sheep",weight:100000,when:{near:{type:"minecraft:wolf",radius:24,min:1}}}
```

效果：生成时放一段演出：粒子 + 雷声 + 播报

```
/data modify storage doom.nats:author entries append value {id:"thunder_king",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:zombie",weight:50000,when:{thundering:true},on_spawn:1b}
```

注意：这两条只在实验性变体 `doom.nats-v4x-experimental-v4.31.0.zip` 里，而且世界必须在创建时开启对应实验性玩法。见 [[实验性变体-v4x]]。
注意：`on_spawn` 不是内联命令串。写 `on_spawn:1b` 只是打开钩子，演出命令要另建函数文件 `data/doom.nats/function/exp/on_spawn/<条目 id>.mcfunction`（`@s` = 刚生成的实体）。

> 更多例子（四个完整用例）见仓库的 [docs/24-玩家能改动的一切.md](https://github.com/Doom-Flare/doom.nats/blob/main/docs/24-玩家能改动的一切.md)。
