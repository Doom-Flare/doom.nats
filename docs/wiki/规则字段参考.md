# 规则字段参考
English: `docs/wiki/规则字段参考.en.md`


能改的东西分三大块：逐实体规则（某个生物怎么刷）、追加条目（什么条件下多刷什么）、数量曲线（一次几只 / 这一类能有多少）。下面按“落位面 / 光照 / 高度 / 群系 / 天气 / 数量”六个维度列全。

> **字段表以本仓库的 `src/rules/README.md` 为准**（[查看](https://github.com/Doom-Flare/doom.nats/blob/main/src/rules/README.md)）；本页是玩家速查版，若两者不一致，以那一份为准。
> 改法就是往存储 `doom.nats:author` 里写（见 [[快速上手-在游戏里改规则]]），改完下一拍生效。

## 一、逐实体规则 `entityRules."<实体 id>"`

| 键 | 取值 | 作用 | 例子 |
|---|---|---|---|
| `belowAny` | 方块标签数组 | 额外算“能站的地方” | `["#minecraft:leaves"]` ⇒ 僵尸能刷在树叶上（方块标签别漏 `#`） |
| `place` | `ground` / `any` / `water` / `water_surface` / `below_tag` / `lava` | 落位类型（要不要地面、要不要在水里） | 发光鱿鱼改 `ground` ⇒ 上陆地 |
| `light` | `none` / `dark` / `bright` / `bat` / `slime` / `glow` / `bl8` | 光照档 | `dark` ⇒ 只在暗处刷 |
| `lightMax` / `lightMin` | 0–15 | 比档位更细的亮度上下限 | `lightMax:7` ⇒ 只在天黑后刷 |
| `yMin` / `yMax` | 整数（闭区间） | 只在某个高度刷 | `yMin:-64,yMax:0` ⇒ 只在地下 |
| `biomeIn` / `biomeNot` | 群系 id 数组，或 `["#标签"]` | 只在 / 不在这些群系 | `["#minecraft:is_deep_ocean"]` |
| `weather` | `thunder` / `rain` / `clear` | 只在某种天气 | `thunder` ⇒ 雷暴限定 |
| `persist` | `true` | 生成即永不消失（做“地标怪”） | — |

> 只能构建期改的键（写进 storage 不会生效）：`tag`（`below_tag` 用哪个标签）· `cluster` · `coins` · `sky` `deep` `river98` `d64` `noPlayer5` `ySea` `yTurtle` `lavaToAir` `noSky` `belowSurface` `notWart` `moreDrowned`。其中 `tag` 与 `belowSurface` 有一个运行时刻的例外：把 `place` 设成 `"any"`（值 1）时这两道门会一并放行 —— v4.32 起生效，用来做“空中生成”。
> 它们是源码级/规则级开关。比如发光鱿鱼的深度门（y ≤ 海平面-33）按规则号判，运行时刻改 `place` 绕不过去（那条走 `ySea`，不认 `place`）。要动它们，得在构建期改 `rules/` 后重新生成。

## 二、追加条目 `entries[]`（一条 = “什么条件下多刷什么”）

| 字段 | 说明 |
|---|---|
| `id` / `mob` / `category` | 名字 / 实体 id / 类别（`monster` `creature` `ambient` `water_creature` `water_ambient` `underground_water_creature` `axolotls`） |
| `biome` | 群系 id 或 `#标签`（单数；要多个群系就加多条） |
| `weight` | 命中率 ≈ `weight / 1000000`（不是“同池按比例”）。要明显生效请填 10 万级；写 `40` 等于不刷。默认 `1`。多条同时存在时看总和：**Σweight ≤ `1000000`**。详见下面 ⚠ `weight` 的真实口径 |
| `min` / `max` | 一次生几只（还受原版“簇上限”约束，多数生物 ≤ 4） |
| `nbt` | 自定义 NBT：装备、名字、属性、药水效果、乘客……（1.21.5+ 装备写成 `equipment:{}`） |
| `when` | `thundering` `raining` `yMin` `yMax` `lightMax` `lightMin`（多个条件全部 AND） |

> 构建期条目（`rules/entries.json`）另有 `biomes`（多群系数组）/ `group:[最少,最多]` / 条目级 `place`·`light`·`tag`·`cluster` 覆盖 / `groupByY`。那是另一套写法，写进 storage 不生效。

### ⚠ `weight` 的真实口径（v4.28 真机实测）

一句话：条件成立时，每次尝试被选中的概率 ≈ `weight / 1000000`。要它真的刷出来，就填 10 万级。

| 你填的 `weight` | 每次尝试的命中率 | 实际观感（真机） |
|---|---|---|
| `40` | 0.004% | 等于不刷：要 2.5 万次尝试才轮到一次 |
| `90` | 0.009% | 同上：实测 90 秒 0 只 |
| `10000` | 1% | 稀有，但看得见 |
| `100000` | 10% | 常见 |
| `250000` | 25% | 很常见 |
| `500000` | 50% | 与原有物种平分秋色 |
| `900000` | ≈90% | 几乎独占。实测 180 秒烈焰人 22 → 32 只（仅单条时可用；多条见下面 Σweight） |

- 为什么不是“同池竞争”：命中窗口 `#off..#hi` 是按“香草权重和 + weight”这种小数量级算出来的（各群系/类别从个位数到 600 上下不等），但拿去比较的 `$rng` 是还没取模的 `random value 0..999999`。取模 `$rng %= #wsum` 发生在这次比较之后，所以只有 0..999999 里那一段长度 = `weight` 的骰值能命中。
- 🔴 多条同时存在时看的是总和：`#off` 从“香草权重和”（约 10）起算，各条按声明顺序依次吃区间。所以 **Σweight 建议 ≤ `1000000`**，否则靠后的条目窗口起点会超过 `999999`，永不命中（源码级论证；`4 × 200000` 有实测旁证）。
- 所以旧文档与源码注释里那句“与香草条目同池按比例竞争”与实测不符（属已知偏差。包自带的固定 `$rng` 探针正好只踩在两种口径重合的那一段上，验不到命中率）。按上面这张表填即可。
- 默认值是 `1`，条目不写 `weight` ≈ 百万分之一，基本不会出现。
- 多条条目条件同时成立时，按声明顺序依次吃区间：第一条先吃掉自己那一段，靠后的只剩剩下的。一旦 Σweight > `1000000`，靠后条目的窗口起点就超过 `999999`，永远不可能命中。想让几条都有戏，就按群系/条件把它们分开，并把 Σweight 压在 `1000000` 以内（例如 4 条各 `200000`）。
- 构建期条目（`rules/entries.json`）走的是同一条命中链，口径一样。

## 三、数量曲线 `counts`

| 键 | 作用 |
|---|---|
| `groupByY."<实体>"` | `[{yMin?,yMax?,min,max}]`：一次生几只，按高度分段 |
| `capByY."<类别>"` | `[{yMin?,yMax?,max,localMax}]`：这类生物的总容量 / 每玩家容量，按高度分段 |

## 四、硬上限（超出不生效）

条目 8 条 · Y 段 8 段 · 落位面标签 8 个 · 群系列表各 4 条。

## 五、六个维度的速查

| 维度 | 用哪些键 |
|---|---|
| 落位面 | `belowAny` · `place` · `tag`（+ 全局方块标签见下） |
| 光照 | `light`（档） · `lightMax` / `lightMin`（细） |
| 高度 | `yMin` / `yMax` · `counts.groupByY` · `counts.capByY` |
| 群系 | `biomeIn` / `biomeNot` |
| 天气 / 时间 | `weather` · `when.thundering` / `when.raining` |
| 数量 | `weight` · `group` · `counts.*` |

## 六、标签接口（作者 / 整合包最常用）

| 东西 | 作用 |
|---|---|
| `#doom.nats:standable` / `#doom.nats:full_collision` | “什么算能站的地面” |
| `#doom.nats:spawnable_at` / `#doom.nats:narrow_partial` | “什么算空位 / 窄条可通过” |
| `#doom.nats:water_fluid` | 什么算“水”（含水草 / 海带 / 气泡柱） |
| `doom.nats.persistent` 实体标签 | 免疫本包的清理与消失层（原版消失逻辑仍适用） |
| `PersistenceRequired:1b` | 原版语义：永不消失 |
| `#doom.nats:monster` 等类别标签 | 按类别筛选 / 统计，如 `@e[type=#doom.nats:monster]` |

## 七、运行时旋钮（不是规则，是“强度”）

海平面、每类容量、消失距离、刷怪节拍、批处理量、出生点 24 格排除、持久化、和平难度开关……这些走配置层：

```
data merge storage doom.nats:config {cap:{monster:70}, persist:0, border:{centerX:0,centerZ:0,size:0}}
function doom.nats:cfg/apply
```

完整键清单与取值范围见仓库的 [docs/18-配置手册.md](https://github.com/Doom-Flare/doom.nats/blob/main/docs/18-配置手册.md)。
