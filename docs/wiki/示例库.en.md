# Example Library

中文: `docs/wiki/示例库.md`

How to use it: pick one, paste the whole command line into chat (requires operator permission), then confirm with `/function doom.nats:author/show`. All of them take effect immediately; if you break something, `/function doom.nats:author/reset` restores it in one click.

> Each one is written as "effect → command → caveats". The commands are all `data modify storage doom.nats:author ...`.

> ⚠ Remember one thing about `weight` first: the real measure is a hit rate ≈ `weight / 1000000` (not "shared proportionally in the same pool as the existing species").
> Every example on this page is written at hundred-thousand scale (≈10% of attempts pick it); writing a small number like `40` equals not spawning.
> Common tiers: `10000`≈1% (rare) · `100000`≈10% (common) · `250000`≈25% · `500000`≈50% · `900000`≈90% (almost exclusive, usable only as a single entry).
> 🔴 When several are present at once, the total matters: `weight` is a "dice-window length", not a percentage. Each entry eats its interval across `0..999999` in declaration order, so **Σweight is recommended ≤ `1000000`**; above that the later entries never hit.
> For the full comparison table and the mechanism see the "⚠ `weight`'s real measure" section of [[规则字段参考]].

## 1. Spawning by Dimension (Overworld / Nether / End)

Effect: zombies spawn only in the Nether's biomes

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".biomeIn set value ["#minecraft:is_nether"]
```

Note: `["#minecraft:is_nether"]` is a biome tag, so you do not need to list dozens of biomes. Use `biomeNot` in reverse to exclude.

Effect: the End's central island gets one extra "enderman patrol" (with a purple name; to spawn them on the outer islands see the next section)

```
/data modify storage doom.nats:author entries append value {id:"end_patrol",biome:"minecraft:the_end",category:"monster",mob:"minecraft:enderman",weight:100000,min:2,max:4,nbt:"{CustomName:'{...}'}"}
```

Note: what goes inside `nbt` is a JSON string, and the quotes must be escaped. The "specialties with NBT" at the end of this page has an easier spelling to copy.
Note: `minecraft:the_end` is the central island's biome, not the outer islands'. The End's inner and outer islands are different biomes, and the outer islands require 4 entries (see the next section).

Effect: the glow squid no longer spawns in the Overworld (the Nether / End are unchanged)

```
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".biomeNot set value ["#minecraft:is_overworld"]
```

## 2. The End: Spawn Only on the Outer Islands (4 biomes · 0 on the central island)

First remember one thing: the End's inner island (central island) and outer islands are different biomes. The central island is `minecraft:the_end`, and the outer islands are these 4:

| Outer-island biome | id |
|---|---|
| Highlands | `minecraft:end_highlands` |
| Midlands | `minecraft:end_midlands` |
| Barrens | `minecraft:end_barrens` |
| Small islands | `minecraft:small_end_islands` |

One entry can only name one biome, so "any outer island" requires 4 entries (the union of all 4 = 100% coverage of the outer islands, 0 on the central island).
`#minecraft:has_structure/end_city` is not "all outer islands" (measured: it covers only `end_highlands` / `end_midlands`, not `end_barrens` / `small_end_islands`), so do not use it as an outer-island tag.
`#minecraft:is_end` is "the entire End" (central island included).
Structure conditions ("only inside an end city structure") cannot be done: the author layer has no structure field, and the release has no `in_end_city` predicate either.

Effect: the End's outer islands spawn blazes (the central island does not)

```
/data modify storage doom.nats:author entries set value [{"id":"blaze_highlands","mob":"minecraft:blaze","biome":"minecraft:end_highlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_midlands","mob":"minecraft:blaze","biome":"minecraft:end_midlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_barrens","mob":"minecraft:blaze","biome":"minecraft:end_barrens","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_small","mob":"minecraft:blaze","biome":"minecraft:small_end_islands","category":"monster","weight":200000,"min":1,"max":1}]
```

Why do these 4 entries each write `200000`, instead of `900000` each? Because the intervals are cut in declaration order, and it is the total that matters.
4 entries at `900000` each: Σweight = 3,600,000. Entry 1's window ≈ `[10, 900010)` is fine, and entries 2/3/4 have window starts already ≥ 900010 > 999999, so they can never hit (a source-level argument; `4 × 200000` has measured corroboration, see below).
Switching to `4 × 200000`: Σweight = 800,000 ≤ 1,000,000, all 4 are alive, and each hits ≈20% within its own biome.
It is not "the bigger the better". These 4 do not actually compete with each other, since a candidate point can only belong to 1 of these 4 biomes. Each one's `weight` is only compared with itself, but the total is constrained by the `1000000` ceiling.

Note: what really "competes with each other" are entries whose conditions hold at the same time. They eat the interval in declaration order; the earlier ones eat their own segment first, and the later ones only have what is left. Once Σweight exceeds `1000000`, the later ones simply never hit.

### Minimal Reproduction: From Zero to "Seeing a Blaze"

```
# ① find a piece of actual outer-island ground (the outer islands are sparse, do not just tp — the ground underfoot may be void and you will fall)
/execute in minecraft:the_end run locate structure minecraft:end_city
#   example reply: The nearest minecraft:end_city is at [-1216, ~, -256]
/execute in minecraft:the_end run forceload add -1216 -256 -1152 -192
/execute in minecraft:the_end run tp @s -1216.5 63 -255.5
/execute in minecraft:the_end run execute at @s if block ~ ~-1 ~ minecraft:end_stone   # must be Test passed
/function doom.nats:debug/env                                  # expected players≥1 chunks=289 dim=2

# ② write the 4 entries above (200000 each ⇒ Σweight 800000, all 4 alive)
/data modify storage doom.nats:author entries set value [{"id":"blaze_highlands","mob":"minecraft:blaze","biome":"minecraft:end_highlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_midlands","mob":"minecraft:blaze","biome":"minecraft:end_midlands","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_barrens","mob":"minecraft:blaze","biome":"minecraft:end_barrens","category":"monster","weight":200000,"min":1,"max":1},{"id":"blaze_small","mob":"minecraft:blaze","biome":"minecraft:small_end_islands","category":"monster","weight":200000,"min":1,"max":1}]
/function doom.nats:author/show                                # expected entries=4

# ③ wait 2–3 minutes and count
/execute in minecraft:the_end if entity @e[type=minecraft:blaze]
```

Note: a real player should first `/gamemode spectator`. A non-spectator player competes for the "anchor player" slot (`pos/pick` uses `@a[gamemode=!spectator]`), splitting half the attempts off to the Overworld.
Measured reference (v4.28 real hardware): a single entry at `weight=900000` ⇒ `$spawned` +99 within 180 seconds, blazes on the field 0 → 32; under the same rules `weight=90` is 0 in 90 seconds. (`900000` is safe only as a single entry; for several you must watch Σweight ≤ `1000000`.)

Measured four-cell matrix (v4.28-series installed copy · real-hardware counts, 8/8 as expected). This is evidence that "the biome gate really is working", not probability jitter:

| Recipe | Central island `the_end` (peak / final) | Outer islands, 4 biomes (peak / final) | `$rej.9` Δ |
|---|---|---|---|
| `blaze @ the_end` ×1, w=`900000` | 51 / 28 ✅ | 0 / 0 | 0 |
| `blaze @` outer islands ×4, w=`200000` each | 0 / 0 | 22 / 22 ✅ | 0 |
| `zombie @ the_end` ×1, w=`900000` | 56 / 56 ✅ | 0 / 0 | 0 |
| `zombie @` outer islands ×4, w=`200000` each | 0 / 0 | 22 / 22 ✅ | 0 |

- Change only the location, not the rules: the central-island rule applied to the outer islands ⇒ 0; the outer-island rule applied to the central island ⇒ 0 (the reverse cells are all 0).
- Both mobs (`blaze` / `zombie`) spawn with zero override, and there is no need to pin `place` / `light` with `entityRules` on top.
- `$rej.9` (species rejection) across all 8 windows is constantly 0, so there is no hidden loss of "it could spawn, but was silently rejected by the rules".
- At the same time the End's total mob count (including vanilla endermen) stayed at 70~103, showing the End itself is spawning normally. The target mob being 0 is caused by the biome gate, not by caps or cadence.

## 3. Landing Face (Places Vanilla Simply Cannot Stand On)

Effect: zombies spawn on leaves (canopy-layer ecology)

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".belowAny set value ["#minecraft:leaves"]
```

Effect: polar regions: polar bears also spawn on floating ice / blue ice

```
/data modify storage doom.nats:author entityRules."minecraft:polar_bear".belowAny set value ["minecraft:blue_ice","minecraft:packed_ice"]
```

Effect: the Nether: zombified piglins also spawn on magma blocks and obsidian

```
/data modify storage doom.nats:author entityRules."minecraft:zombified_piglin".belowAny set value ["minecraft:magma_block","minecraft:obsidian"]
```

Effect: the glow squid goes on land (this is how that "bug fix" was done)

```
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".place set value "ground"
/data modify storage doom.nats:author entityRules."minecraft:glow_squid".light set value "dark"
```

Note: one command changes only one key. `belowAny` appends "places you can stand", it does not replace all the blocks vanilla can stand on. What goes inside `belowAny` is a block tag (`#minecraft:leaves`) or a concrete block id (`minecraft:oak_leaves`); `minecraft:leaves` is a tag name, not a block id, and dropping the `#` means this one does not take effect.
Note: the glow squid still has one depth gate left (vanilla's y ≤ sea level-33, a rule-level switch) that cannot be removed at runtime. The two commands above can make its landing/light terrestrial, but to really make it spawn on land you must change `rules/` at build time (`"ySea": null`).

## 4. Light (Underground Only / Daytime Only)

Effect: strays spawn only where brightness ≤ 3, underground caves only

```
/data modify storage doom.nats:author entityRules."minecraft:stray".lightMax set value 3
```

Effect: sheep spawn only where brightness ≥ 9, daytime plains animals

```
/data modify storage doom.nats:author entityRules."minecraft:sheep".lightMin set value 9
```

Note: light is approximate (the game can only judge 5 tier intervals), so do not compare it against vanilla block by block. Continuous values cannot be done (see [[已知限制]]).

## 5. Height

Effect: goats spawn only above Y 120 (plateau / mountain only)

```
/data modify storage doom.nats:author entityRules."minecraft:goat".yMin set value 120
```

Effect: silverfish spawn only below Y 10 (deep caves only)

```
/data modify storage doom.nats:author entityRules."minecraft:silverfish".yMax set value 10
```

Note: `yMin` / `yMax` are a closed interval, and you can write only one of them.

## 6. Weather / Situation

Effect: only in a thunderstorm + deep ocean + below the surface does a drowned with a trident spawn

```
/data modify storage doom.nats:author entries append value {id:"storm_drowned",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:drowned",weight:100000,when:{thundering:true,yMax:40},nbt:"{equipment:{mainhand:{id:\"minecraft:trident\",count:1}}}"}
```

Note: this example carries equipment NBT. For 1.21.5+ the equipment field was renamed (`HandItems` → `equipment`), and **the old spelling is silently discarded** (no error, but there is nothing on the entity). For the full explanation and a copyable example see section 8 of this page.

Effect: slimes that appear only when it is raining (swamp)

```
/data modify storage doom.nats:author entries append value {id:"rain_slime",biome:"#minecraft:is_swamp",category:"monster",mob:"minecraft:slime",weight:100000,when:{raining:true}}
```

Note: multiple conditions in `when` are ANDed. When the condition does not hold, this entry is not in the candidate pool at all, so it will not crowd out the vanilla species. Once the condition holds, the chance of being picked each time ≈ `weight / 1000000` (see the top of this page).

## 7. Counts and Scale

Effect: the deeper, the more crowded: zombies come in groups of 4~6, but only 1 spawns at the surface

```
/data modify storage doom.nats:author counts.groupByY."minecraft:zombie" set value [{yMax:0,min:4,max:6},{yMin:1,min:1,max:1}]
```

Effect: the underground monster cap doubles (global 200 / per-player 140), the surface stays as it is

```
/data modify storage doom.nats:author counts.capByY.monster set value [{yMax:0,max:200,localMax:140},{yMin:1,max:70,localMax:70}]
```

Effect: several more at a time (a "locust plague" feel): spiders 4 at a time
("Cluster cap" cannot be changed at runtime: vanilla has 4 for most mobs; `cluster` is a build-time field, see [[规则字段参考]])

```
/data modify storage doom.nats:author counts.groupByY."minecraft:spider" set value [{min:4,max:4}]
```

Note: at most 8 Y segments. Caps are upper limits, and whether they are actually reached still depends on the chunk count and the player count.

## 8. "Specialties" with NBT (Equipment / Names / Potions / Passengers)

Effect: the same zombie, two regional variants (desert wears a leather cap, snowy plains stays as it is)

```
/data modify storage doom.nats:author entries append value {id:"desert_zombie",biome:"minecraft:desert",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{equipment:{head:{id:\"minecraft:leather_helmet\",count:1}}}"}
```

Effect: riding a chicken, silent, no gravity (a "floating chicken jockey", in a thunderstorm forest only)

```
/data modify storage doom.nats:author entries append value {id:"ghost_rider",biome:"#minecraft:is_forest",category:"monster",mob:"minecraft:zombie",weight:50000,when:{thundering:true},nbt:"{Silent:1b,NoGravity:1b,Passengers:[{id:\"minecraft:chicken\"}]}"}
```

Effect: spawns already carrying a permanent speed effect

```
/data modify storage doom.nats:author entries append value {id:"swift_zombie",biome:"minecraft:plains",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{active_effects:[{id:\"minecraft:speed\",amplifier:1b,duration:-1,show_particles:1b}]}"}
```

Effect: the Nether spawns a netherite zombie: full netherite, and it does not even drop its equipment when it dies

```
/data modify storage doom.nats:author entries append value {id:"nether_royal_zombie",biome:"#minecraft:is_nether",category:"monster",mob:"minecraft:zombie",weight:100000,nbt:"{equipment:{mainhand:{id:\"minecraft:netherite_sword\",count:1},head:{id:\"minecraft:netherite_helmet\",count:1},chest:{id:\"minecraft:netherite_chestplate\",count:1},legs:{id:\"minecraft:netherite_leggings\",count:1},feet:{id:\"minecraft:netherite_boots\",count:1}},drop_chances:{mainhand:0.0f,head:0.0f,chest:0.0f,legs:0.0f,feet:0.0f}}"}
```

Note: three traps of equipment NBT (as of 1.21.5+)

1. The old fields have been removed: `HandItems` / `ArmorItems` / `HandDropChances` / `ArmorDropChances` no longer exist in 1.21.5+, and you now write `equipment:{…}` (equipment) and `drop_chances:{…}` (equipment drop rates).
   🔴 The old spelling **does not error**: the command still replies `Modified entity data`, yet there is nothing on the entity (a silent no-op, measured on real hardware).
2. `drop_chances` is entity-level: it is a peer of `equipment`, both being top-level keys of the entity NBT. Putting it inside `equipment` is likewise silently discarded.
   The slot names are the same on both sides: `mainhand` `offhand` `head` `chest` `legs` `feet` (a horse's / wolf's armor is `body`). Writing the drop rate as `0.0f` = it never drops.
3. `nbt`'s value is an SNBT string, not a bare compound: inside the whole command line, the inner quotes must be written as `\"` (drop one and the whole command is dead). The new spelling for an item stack is `{id:"minecraft:…",count:1}`; the old `Count:1b` has become the lowercase `count`; CamelCase fields like `Health:40f` are unchanged and need no edit.

> Measured receipt: after the netherite zombie above lands, the entity carries `equipment = {mainhand:{count:1,id:"minecraft:netherite_sword"}, head:{…netherite_helmet}, chest:{…netherite_chestplate}, legs:{…netherite_leggings}, feet:{…netherite_boots}}`, and in one test all 22 zombies had the full netherite set.
> For the full field table see [[规则字段参考]]; for the same kind of trap in the build-time `rules/entries.json` see `src/rules/README.md` §7.5 trap 5.

## 9. View / Undo / Share

```
/function doom.nats:author/show      All current overrides
/function doom.nats:author/export    Pack into one line, shareable with others
/function doom.nats:author/reset     Everything back to vanilla
```

## 10. Experimental Only (the world must have the matching experimental gameplay enabled)

Effect: sheep spawn only when a wolf is nearby (the ecology feel of "near a wolf pack")

```
/data modify storage doom.nats:author entries append value {id:"wolf_sheep",biome:"#minecraft:is_forest",category:"creature",mob:"minecraft:sheep",weight:100000,when:{near:{type:"minecraft:wolf",radius:24,min:1}}}
```

Effect: play a show on spawn: particles + thunder + announcement

```
/data modify storage doom.nats:author entries append value {id:"thunder_king",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:zombie",weight:50000,when:{thundering:true},on_spawn:1b}
```

Note: these two are only in the experimental variant `doom.nats-v4x-experimental-v4.30.1.zip`, and the world must have the matching experimental gameplay enabled at creation time. See [[实验性变体-v4x]].
Note: `on_spawn` is not an inline command string. Writing `on_spawn:1b` only opens the hook; the show commands must be put in a separate function file `data/doom.nats/function/exp/on_spawn/<entry id>.mcfunction` (`@s` = the entity that was just spawned).
