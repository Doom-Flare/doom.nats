# Quick Start · Changing Rules in Game

中文: `docs/wiki/快速上手-在游戏里改规则.md`

Write your rules into the `doom.nats:author` storage, and the next tick judges by the new rules — no reinstalling the pack, no restarting, no regenerating the world.

## 1. First, Remember Three Management Commands

```
/function doom.nats:author/show     See what has been changed right now (including the experimental switch state)
/function doom.nats:author/help     Command overview
/function doom.nats:author/reset    One command back to vanilla (clears all overrides)
```

## 2. Three Openers You Can Copy and Use

1) Let zombies also spawn on leaves (vanilla does not count leaves as "somewhere you can stand")

```
/data modify storage doom.nats:author entityRules."minecraft:zombie".belowAny set value ["#minecraft:leaves"]
```

2) During a thunderstorm, the deep ocean spawns one more kind of zombie (weight 100,000 ⇒ about 10% of attempts pick it)

```
/data modify storage doom.nats:author entries append value {id:"storm",biome:"#minecraft:is_deep_ocean",category:"monster",mob:"minecraft:zombie",weight:100000,when:{thundering:true}}
```

> ⚠ `weight`'s real measure is a hit rate ≈ `weight / 1000000`: writing `40` equals not spawning; for a clear effect fill in hundred-thousand-scale values (`100000`≈10% · `900000`≈90%). For the full comparison table see [[规则字段参考]].

3) The deeper, the more crowded: zombies come in groups of 4~6, but only 1 spawns at the surface

```
/data modify storage doom.nats:author counts.groupByY."minecraft:zombie" set value [{yMax:0,min:4,max:6},{yMin:1,min:1,max:1}]
```

After changing something, run `/function doom.nats:author/show` once to confirm it was written, then stand there and wait a few dozen seconds.

## 3. How It Takes Effect (Understand This and You Will Not Get It Wrong)

- The judgement is read on the spot on every spawning attempt. What you write is "when it is allowed to appear", not "make it faster".
- `weight` means "it only enters the candidate table once the condition holds": with no thunderstorm, this entry is not in the candidate table at all, equal to vanilla. Once the condition holds, the chance it is picked on each attempt ≈ `weight / 1000000` (not "sharing a pool proportionally with the existing species"). So fill in hundred-thousand-scale values; writing `40` equals not spawning. See [[规则字段参考]] for details.
- By default, with nothing changed, the behavior matches vanilla, so `author/reset` can cleanly return to vanilla at any moment.

## 4. The Six Dimensions You Can Change

| Dimension | What to use to change it |
|---|---|
| Landing face | `entityRules."<entity>".belowAny` (extra blocks counted as standable), `place` (ground/water/water surface/lava…) |
| Light | `light` (tier: `none`/`dark`/`bright`/`bat`/`slime`/`glow`/`bl8`), and the finer `lightMax` / `lightMin` (0–15) |
| Height | `yMin` / `yMax` (closed interval), and the count curves `groupByY` / `capByY` |
| Biome | `biomeIn` / `biomeNot` (biome tags may be used, e.g. `#minecraft:is_nether`) |
| Weather / time | `weather` (`thunder`/`rain`/`clear`), and `when:{thundering:true,raining:true}` inside an entry |
| Count | An entry's `weight` / `min` / `max`, plus `counts.groupByY` (how many at a time) and `counts.capByY` (the total cap for that category) |

Field values, what they accept, and the hard upper limits are all in [[规则字段参考]].

## 5. View / Undo / Share

```
/function doom.nats:author/show      All current overrides
/function doom.nats:author/export    Pack into one line, shareable with others
/function doom.nats:author/reset     Everything back to vanilla
```

## 6. Caveats

- Field names work on two layers: inside an entry the biome is `biome` (singular) and the group size is `min` / `max`; `biomes` / `group` / `cluster` / `ySea` are the build-time `rules/*.json` spellings, and writing them into storage **neither errors nor takes effect**.
- What cannot be done at runtime: source-level switches that decide the shape of the function body (`coins` / `cluster` / `deep` / `sky` / `ySea` and so on), adding mobs to "a biome that originally had no such category", and making an entry go through the full group-data semantics. For these, either use the build-time rule layer, or it simply cannot be done (see [[已知限制]]).
- Restricting spawning by structure cannot be done: there is no corresponding field for "spawn only inside an end city / fortress" (the author layer has no structure key, and the release has no `in_end_city` predicate either); express it with biomes instead (the 4 biomes of the end outer islands are in [[示例库]]).
- `$sel.rule` / `$sel.tall` inside an entry may not be the value you wrote: the entry path does not load the selected species' vanilla `place`/`light`/`rule`/`tall`, and carries over the leftover values from the last vanilla draw (`entityRules` can only pin `place`/`light`). After a biome change the leftovers can silently reject your mob (`reason=9`).
- Hard upper limits (exceeding them simply does not take effect): 8 entries · 8 Y segments · 8 landing-face tags · 4 biomes per list.
- Rules written into the `author` storage follow the save; swapping the pack does not lose them, but if field semantics changed you must re-check them.
- When you only want a different "feel" (cadence, caps, sea level, persistence) rather than different rules, use the config layer `doom.nats:config` + `/function doom.nats:cfg/apply`, see the repository's [docs/18-配置手册.md](https://github.com/Doom-Flare/doom.nats/blob/main/docs/18-配置手册.md).
