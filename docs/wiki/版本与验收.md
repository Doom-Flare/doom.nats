# 版本与验收
English: `docs/wiki/版本与验收.en.md`

> 口径依据（2026-10-01 实测 GitHub Releases API）：`tag=v4.25` · `name=doom.nats v4.25` · `draft=false` · `prerelease=false` · published 2026-09-29 ⇒ v4.25 是正式版；`v4.22-beta` 才是 `prerelease=true`。

当前发布 v4.32.0（正式版），支持 Minecraft 1.21.5 到 26.3，按版本区间分五份，基线包是 1.21.6（`pack_format` 80）。每次发版都过四道门，数字留档在作者本机的 `reports/`（不随本仓库分发）。

## 一、四道门是什么

| 门 | 查什么 | 命令（在作者本机跑） | 最近结果 |
|---|---|---|---|
| ① 静态 | 生成器无漂移 + lint L1–L16 + 引用闭包 | `node tools/check_static.mjs` | 0 error / 2 warning（< 2 秒，CI 已接）；闭包门另报 108 处待确认（该门恒 exit 0，见[[已知限制]]） |
| ② 加载期 | 装机 + `/reload`，只看本轮 `Failed to load function`；外加 12 版矩阵 | 内建在 `mcauto` / `regress`；矩阵 `_work/ports/_v432_matrix.mjs` | 0；矩阵 **12/12 `pass=14 fail=0`**（1.21.5 → 26.3，单版 36.6–38.7 秒） |
| ③ 真机断言 | 逐实体规则、动物、持久化、维度、多机器人、物种混合、要塞端到端 | `_work/verify_*.mjs` | `rules 16/0` · `animals 6/0` · `persist 10/0` · `dims 13/0` · `multibot 4/0` · `species_mix 9/0` · `dim_att 6/0` · `fortress_e2e 3/0`（表外 0/24 = 0.0%）· `e6_generic 7/0` |
| ④ 一键回归 | 静态 → 离线 → 真机 → 生存开关 | `node tools/regress.mjs --reuse --minutes 1 --curve 1` | 16 PASS / 0 FAIL |

> 记法：`16/0` = 16 条通过 / 0 条失败。门 ③ 的断言脚本带 RCON 端口参数，可指到隔离实例跑，不影响正式服。

## 二、容量与性能（本机实测）

| 指标 | 实测 |
|---|---|
| 稳态怪物数 | 71.7（cap 70，峰值 77），容量链真的在管 |
| mspt | 均值 5.29 / 峰值 5.70（预算 50） |
| 全清后回满 | 2 秒内 70 → 26，约 6 秒回到 70 |
| 吞吐上限来源 | 不是性能，是原版 `maxCommandChainLength`（默认 65536 ≈ 10 次尝试/tick） |
| 抬到 1,000,000 后 | batch 40 → 9.7 ms；160 → 24.1 ms；400 → 50.9 ms（超预算） |

建议：mspt 想守在 30 ms 以内，`$eff.batch` 不超过 200。自定义地图要更高密度，优先抬 `maxCommandChainLength`，别把帧预算吃光。

## 三、版本线（玩家可见）

| 版本 | 一句话 |
|---|---|
| v4.32.0 | 条目路径的四处断链：`author/entry_rule` 的 storage 路径少了空格，整行执行期抛错 ⇒ 条目的 `rule` / `tag` / `cluster` / `wide` 四组值全部沿用上一只的残值；`core/setup` 从不调用 `mob/load`，新存档里注册表是空的；`add_entry` 的第 9 条能写进去但 `entry_scan` 只枚举 8 个槽位，永不生效也不报错；`check/block` 的 tag 门不认 `place` ⇒ 蝙蝠/鹦鹉即便写 `place:"any"` 也进不了空中。另把 `place = any` 正式定义成「同时放行 tag 门与 `belowSurface` 高度门」 |
| v4.31.0 | 空中生成的两处几何漏写：距离门不分类别（`creature` 本应豁免、`water_ambient` 本应 64）、模式 0 的锚点跟着玩家高度（原版按该列 `WORLD_SURFACE`）；加上被动生物的 400 tick 门因每 20 tick 采样而永不为零。三处一起修完，玩家悬空 y=200 从 0 只变成 90 秒 5259 次生成。另修 `mode/off` 不真退场（新增 `$mode.off` 锁），并重建长期漂移的实验性变体（776 → 781 文件） |
| v4.30.1 | 26.3 那份包的 `pack.mcmeta` 改回真值（`pack_format` 94 → **121**，`min_format` `[121,0]`）；只改元数据，`data/` 一个字节没动 |
| v4.29 | 修 in-game 帮助里错误的 `weight` 示例（示例写 `40`，照它写永远不刷），`weight` 口径全仓校正（引 `c3238d8`）；产物与仓库同步到 v4.29 |
| v4.30.0 | 新增数量档位（`/function doom.nats:scale/*` 五档 + `qty` 配置项），补齐容量计数（v4.28 的 5 个文件） |
| v4.28 | 容量计数改成「每维度 1 次整图盒子 + 逐实体按类别 tag 派发」，总量 ≈ ÷7（实机 tps 13.92 → 20.0x）；修好就绪提示与 4 处 `debug/*` 宏缺参（`E911`–`E914`） |
| v4.25 | 自定义外观桥接（实验性）：真实体当内核 + 骨架当外观，位移误差 0.0000 格，容量只数内核。但源码在（`src/tools/gen_exp_aj.mjs`），没随本版成品发布：要自备非空 `rules/rigs.json`（样例 `src/rules/examples/aj/rigs.json`），带上 `DOOM_EXP=1` 重跑生成器才会产出；本仓 `src/rules/rigs.json` 就是 `{}`，成品 zip 里 `exp/aj` 条目为 0（上列数字来自非空 rigs 的实验构建） |
| v4.24 | 运行时刻作者层：改 `doom.nats:author` 即刻生效，不用重装包；非原版能力单独放进实验性变体 |
| v4.23 | 作者规则层：逐实体规则 / 条件条目 / 数量曲线（默认全部为空 = 原版行为） |
| v4.22 及更早 | 消失层最近玩家量词 bug、跨维度容量、水中溺尸、组数据层、逐实体光照等成片修复 |

同批修复的玩家可见问题：主世界四类水生生物全局容量判定恒读 0（容量门形同不存在）；实验性变体因一个孤儿文件导致整函数加载失败；`data merge` 递归把上一条 NBT 粘到下一只；1.21.5+ 装备 NBT 应为 `equipment:{}`。

完整逐版本条目与数字见仓库的 [CHANGELOG.md](https://github.com/Doom-Flare/doom.nats/blob/main/CHANGELOG.md)。

## 四、发布渠道与状态

- GitHub Releases 上 v4.32.0 是正式版（`prerelease=false` 口径）。
- 更早的 v4.22-beta 已被正式版取代，请下 v4.32.0。
- 两个变体的 zip 都在 `dist/` 下随仓库走，校验值统一在 `dist/SHA256SUMS.txt`（每次发版重算，历史产物一并留档）。
