# Versions and Acceptance

中文: `docs/wiki/版本与验收.md`

> Basis for the measure (measured against the GitHub Releases API on 2026-10-01): `tag=v4.25` · `name=doom.nats v4.25` · `draft=false` · `prerelease=false` · published 2026-09-29 ⇒ v4.25 is a stable release; `v4.22-beta` is the one with `prerelease=true`.

The current release is v4.30.0 (stable), supporting Minecraft 1.21.5 to 26.3, split into five builds by version range, with the baseline pack at 1.21.6 (`pack_format` 80). Every release passes four gates, and the numbers are kept on record in the author's local `reports/` (not distributed with this repository).

## 1. What the Four Gates Are

| Gate | What it checks | Command (run on the author's machine) | Latest result |
|---|---|---|---|
| ① Static | no generator drift + lint L1–L14 + reference closure | `node tools/check_static.mjs` | 0 error / 2 warning (< 2 seconds, already wired into CI) |
| ② Load time | install + `/reload`, looking only at this round's `Failed to load function` | built into `mcauto` / `regress` | 0 |
| ③ Real-hardware assertions | per-entity rules, animals, persistence, dimensions, multi-bot, species mixing, fortress end-to-end | `_work/verify_*.mjs` | `rules 16/0` · `animals 6/0` · `persist 10/0` · `dims 13/0` · `multibot 4/0` · `species_mix 9/0` · `dim_att 6/0` · `fortress_e2e 3/0` (off-table 0/24 = 0.0%) · `e6_generic 7/0` |
| ④ One-key regression | static → offline → real hardware → survival switch | `node tools/regress.mjs --reuse --minutes 1 --curve 1` | 16 PASS / 0 FAIL |

> Notation: `16/0` = 16 passing / 0 failing. Gate ③'s assertion scripts take an RCON port argument, so they can be pointed at an isolated instance without affecting the production server.

## 2. Caps and Performance (measured on the author's machine)

| Metric | Measured |
|---|---|
| Steady-state mob count | 71.7 (cap 70, peak 77), the cap chain really is in control |
| mspt | mean 5.29 / peak 5.70 (budget 50) |
| Refill after clearing everything | 70 → 26 within 2 seconds, back to 70 in about 6 seconds |
| Source of the throughput ceiling | not performance, but vanilla's `maxCommandChainLength` (default 65536 ≈ 10 attempts/tick) |
| After raising it to 1,000,000 | batch 40 → 9.7 ms; 160 → 24.1 ms; 400 → 50.9 ms (over budget) |

Recommendation: to keep mspt within 30 ms, keep `$eff.batch` at no more than 200. For higher density on a custom map, raise `maxCommandChainLength` first rather than eating the whole frame budget.

## 3. Version Line (player-visible)

| Version | In one sentence |
|---|---|
| v4.29 | Fixed the wrong `weight` example in the in-game help (the example wrote `40`, which never spawns if you follow it), and corrected the `weight` measure repo-wide (citing `c3238d8`); artifacts and repository synced to v4.29 |
| v4.30.0 | Added count scaling (`/function doom.nats:scale/*` five tiers + the `qty` config item), and completed the cap counting (the 5 files from v4.28) |
| v4.28 | Cap counting changed to "1 whole-map box per dimension + per-entity dispatch by category tag", total ≈ ÷7 (real-hardware tps 13.92 → 20.0x); fixed the readiness notice and 4 `debug/*` macros missing an argument (`E911`–`E914`) |
| v4.25 | Custom appearance bridge (experimental): a real entity as the core + a rig as the appearance, positional error 0.0000 blocks, and only the core counts toward the cap. But the source is there (`src/tools/gen_exp_aj.mjs`) and was not released with this version's build: you must supply your own non-empty `rules/rigs.json` (sample `src/rules/examples/aj/rigs.json`) and re-run the generator with `DOOM_EXP=1` for it to be produced; this repo's `src/rules/rigs.json` is `{}`, so the release zip contains 0 `exp/aj` entries (the numbers above come from an experimental build with non-empty rigs) |
| v4.24 | Runtime author layer: changing `doom.nats:author` takes effect immediately, no need to reinstall the pack; non-vanilla capabilities were moved separately into the experimental variant |
| v4.23 | Author rule layer: per-entity rules / conditional entries / count curves (empty by default = vanilla behavior) |
| v4.22 and earlier | A wave of fixes: the despawn layer's nearest-player quantifier bug, cross-dimension caps, drowned in water, the group data layer, per-entity light, and more |

Player-visible problems fixed in the same batch: the overworld's four water-mob global cap check always read 0 (the cap gate did not effectively exist); the experimental variant failed to load a whole function because of one orphan file; `data merge` recursively pasted the previous mob's NBT onto the next one; and for 1.21.5+ equipment NBT should be `equipment:{}`.

For the complete per-version entries and numbers see the repository's [CHANGELOG.md](https://github.com/Doom-Flare/doom.nats/blob/main/CHANGELOG.md).

## 4. Release Channels and Status

- On GitHub Releases, v4.30.0 is a stable release (`prerelease=false` by that measure).
- The earlier v4.22-beta has been superseded by the stable release; download v4.30.0.
- Both variants' zips ship with the repository under `dist/`, and the checksums are all in `dist/SHA256SUMS.txt` (recomputed on every release, listing only the two current release artifacts).

## 5. Why It Is Still Beta

Real-hardware acceptance passes, but the known deviations are documented one by one and are not all fixed yet (see [[已知限制]]).

**You can install it into a save and play, but please back up the save first.**
