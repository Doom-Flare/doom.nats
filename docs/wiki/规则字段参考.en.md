# Rule Field Reference

中文: `docs/wiki/规则字段参考.md`

What you can change falls into three big blocks: per-entity rules (how a given mob spawns), appended entries (what extra spawns under what conditions), and count curves (how many at a time / how many of this category there can be). Below they are listed in full along the six dimensions "landing face / light / height / biome / weather / count".

> **The field table is governed by this repository's `src/rules/README.md`** ([view](https://github.com/Doom-Flare/doom.nats/blob/main/src/rules/README.md)); this page is the player quick-reference edition, and where the two disagree, that one prevails.
> The way to change things is to write into the `doom.nats:author` storage (see [[快速上手-在游戏里改规则]]); it takes effect on the next tick.

## 1. Per-Entity Rules `entityRules."<entity id>"`

| Key | Values | Effect | Example |
|---|---|---|---|
| `belowAny` | block tag array | additionally counts as "somewhere you can stand" | `["#minecraft:leaves"]` ⇒ zombies can spawn on leaves (do not drop the `#` on a block tag) |
| `place` | `ground` / `any` / `water` / `water_surface` / `below_tag` / `lava` | landing type (whether ground is required, whether it must be in water) | change the glow squid to `ground` ⇒ it goes on land |
| `light` | `none` / `dark` / `bright` / `bat` / `slime` / `glow` / `bl8` | light tier | `dark` ⇒ spawns only in the dark |
| `lightMax` / `lightMin` | 0–15 | finer brightness upper/lower bounds than the tiers | `lightMax:7` ⇒ spawns only after nightfall |
| `yMin` / `yMax` | integers (closed interval) | spawns only at a certain height | `yMin:-64,yMax:0` ⇒ underground only |
| `biomeIn` / `biomeNot` | array of biome ids, or `["#tag"]` | only in / not in these biomes | `["#minecraft:is_deep_ocean"]` |
| `weather` | `thunder` / `rain` / `clear` | only in a certain weather | `thunder` ⇒ thunderstorm only |
| `persist` | `true` | as soon as it spawns, it never despawns (for "landmark mobs") | — |

> Keys that can only be changed at build time (writing them into storage will not take effect): `tag` (which tag `below_tag` uses) · `cluster` · `coins` · `sky` `deep` `river98` `d64` `noPlayer5` `ySea` `yTurtle` `lavaToAir` `noSky` `belowSurface` `notWart` `moreDrowned`.
> These are source-level / rule-level switches. For instance the glow squid's depth gate (y ≤ sea level-33) is judged by rule number, and changing `place` at runtime cannot get around it. To touch them you must change `rules/` at build time and regenerate.

## 2. Appended Entries `entries[]` (one entry = "what extra spawns under what conditions")

| Field | Description |
|---|---|
| `id` / `mob` / `category` | name / entity id / category (`monster` `creature` `ambient` `water_creature` `water_ambient` `underground_water_creature` `axolotls`) |
| `biome` | biome id or `#tag` (singular; for several biomes add several entries) |
| `weight` | hit rate ≈ `weight / 1000000` (not "proportional within the same pool"). For a clear effect fill in hundred-thousand-scale values; writing `40` equals not spawning. Defaults to `1`. When several are present at once, the total matters: **Σweight ≤ `1000000`**. See the ⚠ `weight`'s real measure section below |
| `min` / `max` | how many spawn at a time (still constrained by vanilla's "cluster cap"; most mobs ≤ 4) |
| `nbt` | custom NBT: equipment, name, attributes, potion effects, passengers… (for 1.21.5+ write equipment as `equipment:{}`) |
| `when` | `thundering` `raining` `yMin` `yMax` `lightMax` `lightMin` (multiple conditions are all ANDed) |

> Build-time entries (`rules/entries.json`) additionally have `biomes` (a multi-biome array) / `group:[min,max]` / entry-level `place`·`light`·`tag`·`cluster` overrides / `groupByY`. That is a different spelling, and writing it into storage does not take effect.

### ⚠ `weight`'s real measure (measured on real hardware in v4.28)

In one sentence: when the condition holds, the chance of being picked on each attempt ≈ `weight / 1000000`. For it to actually spawn, fill in hundred-thousand-scale values.

| The `weight` you fill in | Hit rate per attempt | Actual impression (real hardware) |
|---|---|---|
| `40` | 0.004% | equals not spawning: it takes 25,000 attempts to come around once |
| `90` | 0.009% | same as above: measured 0 in 90 seconds |
| `10000` | 1% | rare, but visible |
| `100000` | 10% | common |
| `250000` | 25% | very common |
| `500000` | 50% | on equal footing with the existing species |
| `900000` | ≈90% | almost exclusive. Measured over 180 seconds: blazes 22 → 32 (usable only as a single entry; for several see Σweight below) |

- Why it is not "competing in the same pool": the hit window `#off..#hi` is computed from a small magnitude like "vanilla weight sum + weight" (each biome/category ranging from single digits to around 600), but the `$rng` compared against it is `random value 0..999999` before the modulo. The modulo `$rng %= #wsum` happens after this comparison, so only the segment of 0..999999 whose length = `weight` can hit.
- 🔴 When several are present at once it is the total that matters: `#off` starts from the "vanilla weight sum" (about 10), and each entry eats its interval in declaration order. So **Σweight is recommended ≤ `1000000`**, otherwise the window start of the later entries exceeds `999999` and they never hit (a source-level argument; `4 × 200000` has measured corroboration).
- So the sentence in the old documentation and source comments — "competes proportionally in the same pool as the vanilla entries" — disagrees with the measurements (a known deviation. The pack's built-in fixed `$rng` probe happens to land exactly on the segment where the two measures coincide, so it cannot verify the hit rate). Just fill it in according to the table above.
- The default value is `1`; an entry without `weight` is ≈ one in a million and essentially never appears.
- When several entries' conditions hold at once, they eat the interval in declaration order: the first one eats its own segment first, and the later ones only have what is left. Once Σweight > `1000000`, the window start of the later entries exceeds `999999` and they can never hit. If you want several to have a chance, separate them by biome/condition and keep Σweight within `1000000` (for example 4 entries at `200000` each).
- Build-time entries (`rules/entries.json`) go through the same hit chain, with the same measure.

## 3. Count Curves `counts`

| Key | Effect |
|---|---|
| `groupByY."<entity>"` | `[{yMin?,yMax?,min,max}]`: how many spawn at a time, segmented by height |
| `capByY."<category>"` | `[{yMin?,yMax?,max,localMax}]`: this category's total cap / per-player cap, segmented by height |

## 4. Hard Upper Limits (exceeding them does not take effect)

8 entries · 8 Y segments · 8 landing-face tags · 4 biomes per list.

## 5. Quick Reference for the Six Dimensions

| Dimension | Which keys to use |
|---|---|
| Landing face | `belowAny` · `place` · `tag` (+ global block tags see below) |
| Light | `light` (tier) · `lightMax` / `lightMin` (fine) |
| Height | `yMin` / `yMax` · `counts.groupByY` · `counts.capByY` |
| Biome | `biomeIn` / `biomeNot` |
| Weather / time | `weather` · `when.thundering` / `when.raining` |
| Count | `weight` · `group` · `counts.*` |

## 6. Tag Interface (most used by map authors / modpack makers)

| Thing | Effect |
|---|---|
| `#doom.nats:standable` / `#doom.nats:full_collision` | "what counts as ground you can stand on" |
| `#doom.nats:spawnable_at` / `#doom.nats:narrow_partial` | "what counts as an empty spot / a narrow strip you can pass through" |
| `#doom.nats:water_fluid` | what counts as "water" (including seagrass / kelp / bubble columns) |
| The `doom.nats.persistent` entity tag | immune to this pack's cleanup and despawn layer (vanilla despawn logic still applies) |
| `PersistenceRequired:1b` | vanilla semantics: never despawns |
| Category tags such as `#doom.nats:monster` | filter / count by category, e.g. `@e[type=#doom.nats:monster]` |

## 7. Runtime Knobs (not rules, but "intensity")

Sea level, per-category caps, despawn distance, spawning cadence, batch size, spawn-point 24-block exclusion, persistence, the peaceful-difficulty switch… these go through the config layer:

```
data merge storage doom.nats:config {cap:{monster:70}, persist:0, border:{centerX:0,centerZ:0,size:0}}
function doom.nats:cfg/apply
```

For the complete key list and value ranges see the repository's [docs/18-配置手册.md](https://github.com/Doom-Flare/doom.nats/blob/main/docs/18-配置手册.md).
