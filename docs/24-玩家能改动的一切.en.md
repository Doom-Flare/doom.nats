# 24 · Everything Players Can Change (Full List)

中文: `docs/24-玩家能改动的一切.md`

> Aimed at players/modpack authors: this table lays out "what you can touch" in one pass.
> Three ground rules first: ① changing nothing = vanilla (with `rules/` empty + storage empty, behavior matches vanilla — verified automatically on every commit);
> ② what you can change is the checks and the counts, not client assets or entity AI; ③ anything marked 🧪 is a non-vanilla capability, only in the experimental variant `v4x`, and the world must enable the matching experimental gameplay.
>
> Layers: A runtime (edit in game, takes effect the next tick) · B build time (change files and regenerate, shareable) · C runtime knobs (`$cfg.*`/`$eff.*`, see `docs/18`) · D tags and switches (block/entity tags, mode commands).

---

## A. Runtime: storage `doom.nats:author` (edit in game, effective immediately)

Management commands:

```
/function doom.nats:author/show        Print all current overrides (including "experimental: on/off")
/function doom.nats:author/reset       Everything back to vanilla
/function doom.nats:author/help        Command overview
/function doom.nats:author/add_entry   Sample one entry from the mob in your hand (including NBT) 🧪
/function doom.nats:author/export      Export the current overrides as a copyable one-line command (to share with others)
/data merge storage doom.nats:exp_in {name:"blood_moon"}   Apply a preset 🧪 step 1: set the preset name (blood_moon / storm_season / deep_dark available)
/function doom.nats:exp/preset         Apply a preset 🧪 step 2: dispatch the name above (the verified entry point; a no-argument macro — doom.nats:author/preset does not exist in the build)
```

### A1 Per-entity rules `entityRules."<entity id>"`

| Key | Values | Purpose | Example |
|---|---|---|---|
| `belowAny` | array of block tags | Additionally counts as "standable" | `["#minecraft:leaves"]` ⇒ zombies can spawn on leaves (don't drop the `#` from the block tag; `minecraft:leaves` is a tag name, not a block id) |
| `place` | `ground` / `any` / `water` / `water_surface` / `below_tag` / `lava` | Placement type (does it need ground, does it need to be in water) | Change glow squid to `ground` ⇒ it comes onto land |
| `light` | `none` / `dark` / `bright` / `bat` / `slime` / `glow` / `bl8` | Light tier | `dark` spawns only in the dark |
| `lightMax` / `lightMin` | 0–15 | Finer brightness bounds than the tiers | `lightMax:7` spawns only after nightfall |
| `yMin` / `yMax` | integers (closed interval) | Spawn only at a certain height | `yMin:-64,yMax:0` ⇒ underground only |
| `biomeIn` / `biomeNot` | array of biome ids or `["#tag"]` | Only in / not in these biomes | `["#minecraft:is_deep_ocean"]` |
| `weather` | `thunder` / `rain` / `clear` | Only in a certain weather | `thunder` ⇒ thunderstorm-only |
| `persist` | `true` | Never despawns once spawned | For making a "landmark mob" |

> Keys that can only be set at build time (writing them into storage has no effect): `tag` (which block tag `below_tag` uses) · `cluster` (max per attempt) · `coins` (coin flip / moon phase) · source-level switches such as `sky` `deep` `river98` `d64` `noPlayer5` `ySea` `yTurtle` `lavaToAir` `noSky` `belowSurface` `notWart` `moreDrowned`. Change `rules/entity-rules.json` and regenerate (route B).
> Note that "rule-level" switches like `ySea` can't be removed at runtime: the glow squid's depth gate (y ≤ sea level-33) is decided by rule number in `check/entity`, and changing `place` won't get around it.

### A2 Extra entries `entries[]` (one entry = "under what conditions, spawn more of what")

| Field | Notes |
|---|---|
| `id` `mob` `category` | Name / entity / category (`monster` `creature` `ambient` `water_creature` `water_ambient` `underground_water_creature` `axolotls`) |
| `biome` | A biome id or `#tag` (singular; for several biomes add several entries. Example: "End outer islands" = `end_highlands`/`end_midlands`/`end_barrens`/`small_end_islands`, 4 entries total; the central island is another biome, `the_end`) |
| `weight` | Hit rate ≈ `weight / 1000000` (not a "proportional share of the same pool"): to take effect fill in hundred-thousand-scale numbers; a small number like `40` means it never spawns. Default `1`. When several entries coexist, look at the sum: Σweight ≤ `1000000`, otherwise later entries never hit (each entry eats its interval from `0..999999` in declaration order ⇒ e.g. 4 entries at `900000` each means only the 1st is alive; instead make it 4 entries at `200000` each). Build-time `rules/entries.json` uses the same measure. See the ⚠ "the real measure of `weight`" in [[规则字段参考]] |
| `min` / `max` | How many per spawn (group size; the upper bound is also constrained by vanilla's "cluster cap" — most mobs ≤ 4) |
| `nbt` | Custom NBT (equipment, name, attributes, potion effects, passengers… 1.21.5+ uses `equipment:{}`) |
| `when` | `thundering` `raining` `yMin` `yMax` `lightMax` `lightMin` (all ANDed) |

> Build-time entries (route B) additionally support these spellings: `biomes` (a multi-biome array) · `group:[min,max]` · entry-level `place`/`light`/`tag`/`cluster` overrides · `groupByY`. The runtime set reads `biome` / `min` / `max`; don't mix the two.

### A3 Count curves `counts`

| Key | Purpose |
|---|---|
| `groupByY."<entity>"` | `[{yMin?,yMax?,min,max}]`: how many per spawn, segmented by height |
| `capByY."<category>"` | `[{yMin?,yMax?,max,localMax}]`: this category's total capacity / per-player capacity, segmented by height |

Hard limits (exceeding them has no effect): 8 entries · 8 Y segments · 8 placement-face tags · 4 entries each in the biome lists.

### A4 What You Can't Reach (Not Possible at Runtime)

Source-level switches (`coins`/`cluster`/`deep`/`sky`/`ySea` and other fields that shape the function body), adding mobs to "a biome that originally had no such category" (requires changing world generation), and entries not going through group data (`SpawnGroupData` — for full group semantics use build time).

Two more boundaries that are easiest to trip over (verified on real hardware):

- You can't restrict spawning by structure. There is no corresponding field for "spawn only inside end cities / strongholds / temples" — the author layer has no structure key, and there is no `in_end_city` predicate in the build; the structures hardcoded at build time are only strongholds / outposts / swamp huts / ocean monuments / ancient cities / trial chambers ⇒ you can only express it with biomes (e.g. End outer islands = 4 biomes, see the table above).
- The entry path doesn't load the chosen species' vanilla `place`/`light`/`rule`/`tall`. These `$sel.*` values carry over whatever the "last vanilla draw" left behind ⇒ reading `$sel.rule` / `$sel.tall` may not give the species you expect. `entityRules` can only pin `place`/`light`; `rule`/`tall` have no corresponding fields. After switching biomes/dimensions the leftover may turn from "inert" into "veto" (`reason=9`, showing up as "mobs silently rejected"). For troubleshooting see [[FAQ]].

## B. Build Time: `doom.nats/rules/` (change files + regenerate, shareable with others)

| File | Contents | Relation to A |
|---|---|---|
| `rules/entity-rules.json` | All of A1's fields (including `coins`/`cluster`/`deep`… which runtime can't do) | A subset of A + source-level switches |
| `rules/entries.json` | All of A2's fields (entries go through full group data) | An enhanced version of A |
| `rules/counts.json` | All of A3's fields | Same as A |
| `rules/rigs.json` 🧪 | Custom appearances: `carrier` (kernel mob) / `carrier_nbt` / `rig` (skeleton summon function) / `on_spawn` / `cat` / `count_with_carrier` | Only in the experimental variant, and not shipped with the v4.25/v4.28/v4.29/v4.30.0 builds (`src/rules/rigs.json` is `{}` ⇒ the generator produces no file; you need to supply a non-empty config yourself + re-run `gen_exp_aj` with `DOOM_EXP=1`) |
| `rules/presets/*.json` 🧪 | Preset packs (one-switch worldviews) | Experimental |

Generation and installation (the commands below need a local development environment, not distributed with this repo; if you only want the datapack, just unzip the zip from `dist/`):

```bash
cd doom.nats
for g in gen_pack gen_pos gen_check gen_mobs gen_spawn gen_despawn gen_effects gen_debug gen_group gen_author; do node tools/$g.mjs; done
node tools/check_static.mjs                  # must be 0 error (default variant 0 error / 2 warning)
node tools/install.mjs --variant std          # or --experimental to install the experimental variant
```

## C. Runtime Knobs `$cfg.*` / `$eff.*` (key list and value ranges in `docs/18-配置手册.md`)

| Group | What you can tune |
|---|---|
| Capacity | Per-player caps and global capacity bases for each category (`max_monster` / `max_creature` / `max_ambient` / `max_water_*` / `max_axolotls` …) |
| Light | The tier at which monsters are "dark enough" (`light` 0–15 tiers) |
| Cadence | Spawn attempt period `period`, batch size `batch`, snapshot period (faster = denser, slower = cheaper) |
| World | Sea level, Nether/End light tiers, spawn 24-block exclusion, world border (reason=11), placement fallback and floor height |
| Gameplay | `peaceful` (peaceful difficulty), `difficulty`, `special` (special mob ratio), `persist` (persist all spawned mobs) |
| Mode | `mode/survival` (disable vanilla spawning, this pack takes over) / `mode/manual` / `mode/auto` / `mode/off` (hand it back to vanilla) |

## D. Tags and Objects (The "Interfaces" Authors/Modpacks Use Most)

| Thing | Purpose |
|---|---|
| `#doom.nats:standable` / `#doom.nats:full_collision` | "What counts as standable ground" (a global whitelist beyond `belowAny`) |
| `#doom.nats:spawnable_at` / `#doom.nats:narrow_partial` | "What counts as a free space / a narrow gap you can pass through" (AABB approximation) |
| `#doom.nats:water_fluid` | What counts as "water" (including seagrass/kelp/bubble columns) |
| `doom.nats.persistent` entity tag | Immune to this pack's clearing layer (vanilla despawn logic still applies) |
| `PersistenceRequired:1b` | Vanilla semantics: never despawn |
| Category tags such as `#doom.nats:monster` | Filter/count by category (`@e[type=#doom.nats:monster]`) |
| Structure overrides / biome lists | Go through world generation overrides (`tools/apply_worldgen.mjs`); you can delete a whole category or rewrite a biome's spawn table |

## E. Experimental-Only 🧪 (the `v4x` variant; the world must enable the matching experimental gameplay to load)

| Capability | How to write it |
|---|---|
| `near`: spawn only when certain things are nearby ("sheep appear near a wolf pack") | Add a nearby-entity condition (radius + count range) to an entry/rule |
| `on_spawn`: spawn presentation (particles/sounds/broadcasts/extra NBT) | Write `on_spawn:1b` in the entry (the hook switch), then create the function `doom.nats:exp/on_spawn/<entry id>` in the datapack (`@s` = the new entity); or configure it in a preset |
| Preset packs | `data merge storage doom.nats:exp_in {name:"blood_moon"}` → `function doom.nats:exp/preset` (the verified entry point; `author/preset` does not exist in the build) |
| Custom appearances (rig bridge) | `rules/rigs.json`: a real entity as the kernel + a skeleton as the appearance (mounted with `ride`). Source in `src/tools/gen_exp_aj.mjs`, not shipped with the v4.25/v4.28/v4.29/v4.30.0 builds: you need your own non-empty `rules/rigs.json` (sample `src/rules/examples/aj/rigs.json`) and re-run the generator with `DOOM_EXP=1`; this repo's `rules/rigs.json` is just `{}`, and the built zip has 0 `exp/aj` entries |
| `author/export` sharing | Packs the current overrides into one copyable command |

Engine gate: the experimental variant declares the required flags in `pack.mcmeta`; if the world doesn't enable them it refuses to load (not a warning). The only native flags available on 1.21.6 are `minecart_improvements` / `redstone_experiments` / `trade_rebalance`; a world that enables one also gets the corresponding vanilla change.

## F. In One Sentence

Position (placement face / block tags / Y) · state (light / weather / time / moon phase) · space (biome whitelists and blacklists; structures are only the 6 hardcoded at build time, and runtime can't express them) · counts (weight / group size / capacity by height) · appearance and presentation (NBT / spawn effects / custom skeletons 🧪).
These five groups are mutually orthogonal and can be stacked and combined. Effects like "thunderstorm in the deep ocean, hovering over the sea surface, riding a chicken, wearing a glowing helmet, two at a time" are assembled by picking one item from each column of this table.
